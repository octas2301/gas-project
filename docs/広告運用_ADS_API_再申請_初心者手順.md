# Amazon Ads API 再申請 — パソコン初心者向け手順

**最終更新**: 2026-10-15  
**目的**: 自社（日本セラー）で Ads API を使えるように、もう一度申請する  
**使うメール（推奨）**: Seller Central・広告・開発者で同じもの（例: `3358miho@gmail.com`）  
**詳細・海外要否**: [広告運用_ADS_API_日本申請と取得手順.md](広告運用_ADS_API_日本申請と取得手順.md)

> この作業は **米国法人登録は不要**です。日本のまま進めます。  
> **パートナー／代理店**ではなく、**直取引の広告主**（自分の店だけ）で申請します。

---

## 全体の流れ（地図）

| 順番 | やること | 承認が要る？ |
|------|----------|--------------|
| 0 | 準備チェック（メール・名前・Adsに入れるか） | 不要 |
| 1 | Login with Amazon（LwA）用の「セキュリティプロファイル」があるか確認。無ければ作る | 不要 |
| 2 | **APIアクセスを申請**（フォーム提出） | **審査あり（最大72時間）** |
| 3 | （通ったら）LwA に API を割り当てる | メールの案内どおり |
| 4 | （通ったら）Refresh Token を取る | 別手順。承認後に進む |

**いまやるのは 0 → 1 → 2 まで**です。3・4は「承認されました」のメールが来てから。

---

## 手順0 — 始める前（10分）

### 0-1. ブラウザの準備

1. **Chrome** か **Edge** を使う（できればいつも使うもの）  
2. 右上の人物アイコンなどで、**別のAmazonアカウントでログインしたまま**なら、いったんログアウトする  
3. メモ帳（Windowsなら「メモ帳」アプリ）を開き、あとでコピーする用に空いておく  

### 0-2. 必ず同じメールで入る

次の3つに、**同じメール**で入れるか確認する。

| # | どこ | 開き方 |
|---|------|--------|
| A | セラーセントラル | https://sellercentral.amazon.co.jp/ にログイン |
| B | 広告（Campaign Manager） | セラー中央から「広告」へ、または https://advertising.amazon.co.jp/ |
| C | 開発者サイト | https://developer.amazon.com/ にログイン |

**全部、同じメール（例: 3358miho@gmail.com）** で入れることを確認。  
違うメールなら、申請は **広告に入れる方のメール**に揃えてから進む。

### 0-3. 会社名をメモ帳に書く

申請フォームに書く名前は、**一字一句そろえる**のが大事です。

メモ帳に次を書いておく（分かる範囲でOK）:

```
ログインメール: （例）3358miho@gmail.com
ストア表示名: オンラインショップ Octas
申請に書く会社名: （Seller Centralの法人名・屋号。前回書いた文字があればそれを優先）
Ads account ID: amzn1.ads-account.…（分かるなら）
```

**前回通らなかった定型理由**は「会社名＋メールに紐づく広告アカウントが見つからない」です。  
表示名と申請名が違うときは、**前回申請に書いた会社名**か、**Seller Centralの正式な事業者名**のどちらかに揃え、あとでサポートに両方書く。

### 0-4. すでに承認済みでないか（1分）

以前どこかで通っているのに再申請していることがあります。

1. https://advertising.amazon.com/ など Advanced Tools / 開発者向けの **My Apps（マイアプリ）** が開けるなら開く  
2. 自分のアプリが **Approved / 承認済** で、広告の権限が付いているなら、**新規申請は不要**（次は割り当て・トークン）

分からなければ、そのまま手順1へ進んでよいです。

## 手順1 — LwA（Login with Amazon）の準備

Amazon Ads API は、先に「クライアントアプリ」用の **セキュリティプロファイル** が必要です。  
**すでに作ってあるなら作り直し不要**です。Client ID と Client Secret が分かればOK。

### 1-1. 開発者サイトを開く

1. ブラウザのアドレス欄に次を入力して Enter  
   `https://developer.amazon.com/`  
2. **サインイン**  
3. メール・パスワードは **手順0と同じメール**  

### 1-2. コンソールへ

1. 「**開発者コンソール**」または 「**Console**」をクリック  
2. 上のメニューから 「**Login with Amazon**」 をクリック  

### 1-3. すでにプロファイルがある場合

一覧に自分で作った名前（例: `AmazonAdsAPI_Octas`）があるか見る。

- **ある** → その行で 「**クライアントIDとクライアントシークレットを表示**」／「Show Client ID and Client Secret」  
  → メモ帳に `Client ID` と `Client Secret` を控える（他人に送らない・Gitに載せない）  
  → **手順2へ**  
- **ない** → 下の 1-4 へ  

### 1-4. ない場合だけ新規作成

1. 「**新しいセキュリティプロファイルを作成**」／「Create a New Security Profile」  
2. 入力例:

| 欄 | 書いてよい例 |
|----|----------------|
| セキュリティプロファイル名 | `AmazonAdsAPI_Octas_JP` |
| 説明 | `自社のAmazon広告レポート取得用` |
| 同意プライバシー通知のURL | 自社のプライバシーページ。無ければ `https://www.amazon.co.jp/` でも可（直取の自社利用） |

3. **保存**  
4. 「クライアントIDとクライアントシークレットを表示」→ メモ帳に控える  

> SP-API用のプロファイルがあっても、公式は **Ads用に新しいものを作る**ことを勧めています。無いならこの1つでOK。

## 手順2 — APIアクセスを申請する（いちばん大事）

### 2-1. 申請ページを開く

1. 次の日本語説明ページを開く  
   https://d3a0d0y2hgofx6.cloudfront.net/ja-jp/guides/onboarding/apply-for-access.html  
2. ページ内の **「直取引の広告主様としてAPIアクセスを申請」** のリンクをクリック  
   （「パートナー」は選ばない）  
3. ログインを求められたら、**手順0と同じメール**  

**画面右上**に表示されている名前／メールが正しいか必ず見る。  
違う人が出ていたらログアウトして、正しいメールで入り直す。

### 2-2. フォームの書き方（迷ったらこれ）

画面の英語・日本語は時期で少し違います。近い欄に次を入れる。

| 聞かれていること | 書き方 |
|------------------|--------|
| 申請者の種類 | **Direct advertiser / 直取引の広告主**（自分の店だけ） |
| 会社名・法人名 | メモ帳に書いた **申請用会社名**（一字一句同じ） |
| メール | 自動で入るならそのまま。手入力ならログインと同じ |
| 国／マーケット | **Japan / 日本** |
| 使い方・目的 | 例（英語で書く画面なら下の英文をコピー） |

目的の英文コピー用:

```text
I am a Japan Amazon seller (storefront: オンラインショップ Octas).
I will use the Amazon Ads API only for my own Sponsored Products:
download search term reports and manage my own campaigns.
I am not building a tool for other advertisers.
```

日本語だけの欄があれば:

```text
日本の自社セラーです。自社のスポンサープロダクト広告の
検索用語レポート取得と運用自動化のみに使います。他社向けツールではありません。
```

### 2-3. 契約への同意

「ライセンス契約」「データ保護」などにチェックが入る画面なら、内容をざっと見て **同意** にチェック → **審査に提出**／Submit。

### 2-4. 提出したあと

1. 提出したメール宛に **受領メール**が来る（迷惑メールも見る）  
2. 審査は **最大72時間**かかることがある  
3. `jira@amzn-clicks.atlassian.net` からサポート招待が来たら **Accept / 承諾**する  
4. 結果メール:
   - **承認** → 手順3（割り当て）へ。リンクをすぐ押さず、下の注意を読む  
   - **却下** → 理由と一緒に、Adsの「メールが見えるスクショ」と Ads account ID・申請した会社名を Jira に英文で送る  

**承認メールのリンクは、押す前に次を読む**（公式警告）:  
紐づけは **一度きりで変更できない**ことがあります。  
https://d3a0d0y2hgofx6.cloudfront.net/ja-jp/guides/onboarding/assign-api-access.html

## 手順3 — 承認されたら（いまは読だけ）

1. 承認メールの案内どおり、手順1で作った **LwAプロファイルを選んで割り当て**  
2. そのあと Refresh Token 取得（日本は極東 FE）  
   → 詳しくは [日本申請と取得手順](広告運用_ADS_API_日本申請と取得手順.md) の手順D・E  

承認前に手順3をやる必要はありません。

## よくある失敗（避ける）

| やりがち | どうする |
|----------|----------|
| 買い物用Amazonとセラー用が混ざる | 申請前にログアウトし、セラー用メールだけで入る |
| 「パートナー」で申請する | **直取引の広告主**にする |
| 会社名を感覚で書く | メモ帳の正式名をコピペする |
| Seller Centralだけ見て「アカウントある」と言う | **広告（Campaign Manager）に入れる**ことも確認 |
| Client SecretをチャットやGitに貼る | メモ帳のローカルか Script Properties のみ |
| 承認前にトークン取得まで急ぐ | 先に申請→承認メール待ち |
