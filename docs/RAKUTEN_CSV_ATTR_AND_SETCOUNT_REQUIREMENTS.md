# 楽天CSV：商品属性と「楽天セット数」（親子行）要件・判断の経緯

対象実装: `コード.js` の `generateRakutenCSV`（マルチSKU の `virtualRow`、SKU 行の属性継承、属性値クリーニング）

---

## 1. 背景（障害）

楽天 FTP のエラーログに、概ね次の趣旨が出るケースがあった。

- 「商品属性（項目）3 がありません。商品属性（値）3 を設定する場合は、必ずご指定ください。」

生成 CSV では **商品属性（項目）3 が空**、**（値）3 が `0`**、**（単位）3 が空** となっていた。

---

## 2. 原因の整理

### 2.1 親行の「楽天セット数」と `virtualRow`

マルチ SKU では、バリエーションごとに **`virtualRow = 親行のコピー + URL・商品名・画像などの上書き** で商品行を組み立てる。

**`楽天セット数` は従来この上書き対象に含まれていなかった**ため、対象子に合わせたセット数ではなく **親行のセル値**（運用上、親に `0` やプレースホルダが入っていることがある）が商品行の計算にそのまま載った。

### 2.2 SKU 行の属性継承（`parentDataValues`）

SKU 行では `attr_*` / `product_attr` 系について、商品行で確定した `parentDataValues[key]` で上書きする処理があった。

条件が **`parentDataValues[key] !== undefined` のみ**だったため、

- 商品行側の属性「値」が **数値 `0`** のときも「親から渡す値あり」とみなされ、
- マスタの **子行から読み取った正しいセット数（1, 2, 3 …）が `0` で上書き**される

という挙動になった（`0` は JavaScript では `undefined` ではない）。

### 2.3 自動クリーニング（`attr_value` と `!val`）

生成後の調整で、`attr_value` が **falsy** のときに対になる項目名・単位を空にする処理があり、**数値 `0` が falsy** であるため、

- **値は `0` のまま残り**、
- **項目名・単位だけ消える**

という不整合が楽天側の「項目なし・値あり」エラーと整合的だった。

※ 文字列 `"0"` は従来ロジックではこのクリーニングの対象外だったが、2.2 により **数値 `0` に揃う** ときに問題が顕在化しやすい。

---

## 3. 採用した仕様（実装）

1. **`virtualRow` に子行の `楽天セット数` をコピー**  
   マルチ SKU の各 `childRow` について、`virtualRow[楽天セット数列] = childRow[同列]` とし、**当該バリエーションの商品行ベース**が子のセット数と一致するようにする。

2. **SKU 行の属性継承**  
   - `INHERIT_KEYS` … 従来どおり親の `parentDataValues` を優先（在庫・配送系など）。  
   - `attr_*` / `product_attr` … **▼設定の 3 行目にマスタ列名がある場合**は、**子行のセルに値があるときは親で上書きしない**。  
     「空」の判定は **`undefined` / `null` / 空文字**のみとし、**数値 `0` は有効なので空扱いにしない**。  
   - 3 行目にマスタ列がない属性（固定値のみの項目名など）は、従来どおり親の `parentDataValues` を使う。

3. **クリーニング**  
   `attr_value` について **`!val` 一律をやめ**、**未入力は `undefined` / `null` / 空文字（trim 後）のみ**とし、**`0` は未入力とみなさない**。

---

## 4. 運用上のメモ

- 親行の `楽天セット数` を空白にする運用は **補助的には有効**だが、**本改修がないと子の値が親の空や 0 で潰れる**ため、単体では不十分だった（上記 2.2）。
- RMS 上の単位表記（例: 「個」）とマッピングの固定値（例: 「セット」）の整合は **ジャンル要件**の別論点。本改修は **FTP の「項目と値の組の不整合」** を主に防ぐ。

## 6. 今後の検討事項（メモ｜未決定）

**経緯**

- ジャンル（商品仕様マニュアル）ごとに **許される商品属性の「項目名」が異なる**。例として、当該ジャンルでは **`原産国／製造国` が定義に含まれず**、FTP 側で「ジャンルID と商品属性（項目）の組み合わせが不正」と判定されるケースが確認された。
- 一方、**原材料・保存方法**などは複数ジャンルで項目名が共通しやすく、**原産国・産地表示など名前のブレが大きい項目**だけ運用を分けたいニーズがある。
- また **自由入力行1〜5**（項目名・値のペア、文字数制約あり）はジャンル定義に含まれる場合があり、**公式スロットに無い文言を載せずに**ノート的に補足する手段になり得る。
- いましばらく **アップロードを続けてエラー傾向を見たうえで**、下記どちら（または併用・別案）に寄せるか **判断する**。現時点では **実装タスクとしない**。

### 6.1 案A：原産地（原産国系）のみ自由入力行へ寄せる

- **概要**: 属性スロットの一部（例: 属性4相当）で **`原産国／製造国` 等の固定項目名を出さない**。代わりに **自由入力行**の項目列に「原産国／製造国」など運用で決めたラベル、値列にマスタ由来の産地・国名を出力する。
- **狙い**: ジャンルごとに変わる **公式項目名への手作業合わせ**を、原産地系に限って減らす。原材料・保存方法などは従来どおり公式属性のまま試す。
- **注意**: ジャンルによっては自由入力行自体が無い／制約が厳しい。RMS／マニュアルで **当該ジャンルIDで利用可能か** を事前確認する。構造化属性より検索・絞り込み効果は弱くなり得る。
- **実装観点（検討時）**: `▼設定(マッピング)` に楽天定義CSVの **自由入力行用システムキー列**を足し、原産地系だけそちらへルーティングする。必要なら `generateRakutenCSV` で該当キーの **SKU 行継承** を属性と揃える等小調整。

### 6.2 案B：段階別アップロード（リトライ戦略）

- **概要**: 楽天の処理結果（FTP エラーログ等）を見て **段階を踏んで CSV を組み直し、再アップロード**するフロー。
- **例（検討中のイメージ）**
  1. **第1段**: 現状どおり **商品属性4以降も含む** normal-item CSV を送信。
  2. **NG かつ属性・原産系が原因と判読できる場合** → **第2段**: 原産地だけ **案Aどおり自由入力行**に差し替えた CSV を再送（属性4の公式スロットは空 or 削除）。
  3. **さらに NG** → **第3段**: **商品属性4以降を出力しない**（マッピング上の出力フラグオフや列クリア）状態で再送し、最低限の出品を優先。
- **狙い**: **一度のボタンで全自動**より、**取りこぼしを減らす**（属性ゆるめ → 出品成功の順）。
- **注意**: 再アップロードのたびに **楽天側の同一商品への反映ルール**（新規／更新／エラー時の残留）を確認する必要がある。トリガーや手動の境界、ログの見方を運用で決める。GAS 側は **モード引数**・**Script Property**・**専用メニュー**などで段階を切り替える案が考えられる。
- **実装観点（検討時）**: `generateRakutenCSV` に **属性レンジのオプション**（例: `attr_4` 以降を空にする、自由入力モード）を追加するか、**別シート・別マッピングプリセット**で同関数を呼び分けるかは、運用コストと合わせて決める。

### 6.3 決定の目安

- しばらく **継続アップロード**し、**エラー種別（ジャンルID × 項目名 × ログ文言）の分布**を見る。
- **案A 単独で十分か**、**案B の段階が実務上必要か**、または **マッピングの手戻りのみで足りるか**を整理してから実装スコープを切る。

## 7. 説明文内スペック表の列解決（2026-05-06）

**目的**: 商品登録に使う値は人間作業エリア（例: `(賞味期限(食品))`）の列に置き、`▼マスタ(...)` は下書き・参照用に留める。**曖昧検索はせず**、ヘッダー名の**完全一致**と**固定の候補順**のみ。

| 表の行 | 候補順（先に出た非空を採用） |
|--------|------------------------------|
| 名称 | `メーカー名` → `マスタシリーズ`（どちらも空なら表示用に `商品`） |
| 原材料名 | `特記すべき原材料` → `原材料(食品)` |
| 賞味期限 | `(賞味期限(食品))` → `賞味期限(食品)` |
| 保存方法 | `(保存方法(食品))` → `保存方法(食品)` |

`楽天キャッチ`・画像パス等は従来どおり `getMVal`（`▼マスタ` 優先あり）。
