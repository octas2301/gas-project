# 一括出品（D）画像ゲート要件

## 概要

一括出品（`runBatchExport` / `showBatchExportModal`）実行時、**デフォルト（Strict）**では次を満たすまで楽天 CSV 生成・Yahoo 出品に進まない。

1. **画像アップロード**（`executeRenameAndUploadFromMatrix` 相当）を実行し、R-Cabinet の **API 失敗件数（errorCount）が 0**。マトリクスシート欠如・データなし・マスタヘッダー不正のときも Strict では停止する（「画像アップロードをスキップ」で緩和）。
2. **出品 CK** 付きの全行で **楽天メイン画像1** が空でない（子 SKU 行は同一親 SKU の**親行**のメイン画像でフォールバック。`generateRakutenCSV` の前提に合わせる）。

モーダルで次を選べる。

- **画像アップロードをスキップ** … マスタにパスが既にあるとき。アップロード工程は行わないが、**Strict ではメイン画像1のゲートは継続**。
- **ベストエフォート** … 上記の欠陥があっても楽天・Yahoo を続行。内容は「一括出品ログ」に記録。

## Strict（既定・チェックオフ時）

- アップロード実行時: `errorCount > 0` で **throw**。
- `NO_MATRIX` / `NO_MASTER_SHEET` / `NO_MASTER_HEADER` / `NO_MATRIX_DATA` で **throw**（スキップオフ時）。
- メイン画像ゲート不合格で **throw**。
- **`full`**: 楽天 CSV が **throw** したら **Yahoo を実行しない**。

## ベストエフォート（明示チェック時）

- 画像・メイン画像の欠陥をログに残し **続行**。
- **`full`**: 楽天 CSV 失敗後も **Yahoo を続行**（変更前の `full` に近い挙動）。

## トリガー・通知

- `BATCH_EXPORT_SKIP_IMAGE` / `BATCH_EXPORT_BESTEFFORT` を Script Properties に保存し、トリガー実行で読み取る。
- エラー時は既存の **PENDING_ALERT・メール・トースト** の流れに乗せる。

## R-Cabinet 向け画像サイズ対策（経緯と判断）

### 経緯

- マトリクス経由の R-Cabinet 画像アップロードで、大容量画像に対し **Image size** や **Capacity** 系のエラーが発生することがあり、一括出品（D）の Strict ゲートで止まる事例があった。
- 事前にローカルで一律圧縮する運用も可能だが、作業負荷と抜けのリスクがあり、**GAS 側で可能な範囲の自動対処**を追加する方針とした。
- **追記（2026-05）**: 実運用ログで、Drive サムネ（PNG、長辺 2048 相当）が **約 2,077,520 バイト**となり、クライアント側の目安が **2×1024×1024（2,097,152）バイト以下**で「採用」されたにもかかわらず、R-Cabinet 側は **`Image size Error(Capacity)`** で拒否する事象があった。  
  **解釈**: GAS 上の **2MiB 表現**と API 実装側の **厳密なバイト上限（例: 2,000,000 に近い内部閾値）** の差、および **PNG のまま送っていてヘッダ付きや実効上限でギリギリ**になるケースが重なった可能性がある。

### 判断（実装方針）

1. **目安上限（厳しめ）**  
   - `RAKUTEN_CABINET_MAX_IMAGE_BYTES` を **1,900,000 バイト**に設定し、**API 側が 2MiB より厳しい**可能性に備えた余裕を持たせる。
2. **アップロード直前の一本化（JPEG 化＋サイズ再チェック）**  
   - `Blob#getAs(MimeType.JPEG)` により **可能な限り JPEG に変換**し、ファイル名・MIME を **`.jpg` / `image/jpeg`** に揃えてから送信する（`convertBlobToJpegForRakuten_`）。  
   - **サムネ候補の採用条件**は「生 PNG/JPEG のバイト数」ではなく **JPEG 化後のバイト数が `RAKUTEN_CABINET_MAX_IMAGE_BYTES` 以下**であることとする（`tryFetchDriveThumbnailBlobFromThumbnailLink_` / `tryFetchDriveThumbnailBlobLegacy_`）。  
   - `prepareBlobForRakutenCabinetUpload_` では、オリジナルまたはサムネで取得した Blob を **必ず JPEG 化**し、まだ上限を超える場合は **サムネ取得を追加で試行**してからサイズを再評価する。
3. **JPEG 化の注意**  
   - **透過 PNG** は JPEG 化時に背景が塗りつぶされる。線画・白抜き用途は事前に運用で確認する。  
   - `getAs` が失敗する形式がある場合はログで警告し、**元 Blob をそのまま送る**フォールバックを残す（完全停止は避ける）。
4. **API 失敗時の再試行**  
   - `callRCabinetInsertFile` が失敗し、メッセージが **サイズ・容量・Image** 系と判定される場合（`rakutenCabinetUploadShouldRetryWithShrunk_`）、**同じファイル ID でサムネ経由 Blob を再取得**して **1 回だけ再アップロード**する。サムネ経路は上記と同様 **JPEG 化済み・上限は JPEG 後バイト**で評価される。
5. **サムネ取得失敗時**  
   - オリジナルを JPEG 化して送るフォールバックを残す。サイズが目安を超えたままになる場合はログで警告する。
6. **制約**  
   - 本処理は **OAuth と Drive API（thumbnail / thumbnailLink）利用可能な実行コンテキスト**を前提とする。画質はサムネ由来・JPEG 再エンコードによりオリジナルより劣化しうるが、**出品可否・Capacity 回避**を優先したトレードオフとした。

### 本ドキュメント（画像ゲート）との関係

- Strict では引き続き **errorCount = 0** が必要。上記により失敗件数が減ることで、ゲートを満たしやすくなる。ゲート条件そのものは変更しない。

## 列番号マスタ自動更新（経緯と判断）

### 経緯

- D（一括出品）の前後で **▼商品マスタ(人間作業用) の列構成**が変わることがあり、メニュー **15-①（列番号マスタを生成）** と同じ内容を手動で回す必要があった。
- トリガー実行時は `SpreadsheetApp.getActive()` に依存しないよう、**実行に使ったスプレッドシート参照でトースト**する必要がある。

### 判断（実装方針）

1. **いつ更新するか**  
   - **一括出品トリガーが成功終了したときのみ**（`runBatchExportFromTriggerImpl` で `errMsg` が空のとき）に `regenerateColumnMasterFromWorkbook_(ssForToast)` を呼ぶ。失敗時はマスタが中途半端な可能性があるため **自動更新しない**。
2. **何を上書きするか**  
   - メニュー 15-① と同様、**▼商品マスタ 8 行目**から `generateColumnMasterFromHeaderRow` で生成し、`writeColumnMasterToSheet` 経由で **「列番号マスタ」シートの A〜C のみ**を更新する。**D 列以降**（G/H/I のモール別列リストなど）は **クリア・上書きしない**。
3. **トースト**  
   - `writeColumnMasterToSheet` は **`ss.toast`** を用いる（`getActive` 非依存）。トリガー実行でも同じブックに対して通知可能な範囲で動かす。
4. **GAS の列解決**  
   - 一覧や CSV 生成の **列インデックス解決は主にヘッダー行から動的に行っており、列番号マスタシートを必須とする処理パスは限定的**である。それでも **人間・チャット・メニューの 3 モール繋ぎ**は列番号マスタを参照するため、D 成功後に 8 行目と A〜C が揃うと追跡しやすい。
5. **列移動後の注意**  
   - マスタ列が増減・移動した場合、**1 行目の計算式**（商品名繋ぎなど）は列字母がずれる可能性がある。**必要ならメニュー「3モール商品名繋ぎ計算式作成」を再実行**する運用を前提とする（自動では書き換えない）。

### 補足（白背景列名）

- マスタ上で **`楽天白背景画像`** と **`楽天白背景画`** のどちらかがあれば、プログラム側の列解決に使う（`findMasterColumnIndexWhiteBg_`）。
