# 商品マスタ 人間の作業エリアとマスタエリア（AI作業エリア）要件定義

**更新方針**: 仕様変更・修正の都度、本要件定義を追記・修正する（都度更新）。紐付けの実装は `コード.js` の `TITLE_DROPDOWN_PAIRS` および `getTitleDropdownColPair` を参照。

▼商品マスタ(人間作業用) シートは、**人間の作業エリア**と**マスタエリア（AI作業エリア）**の2つに分けて列項目を設定する。

- **人間の作業エリア**: 人が入力・選択する列。プルダウンの**設定先**。選んだ1件の値が入る。
- **マスタエリア（⇒AI作業エリア）**: AIが調査・生成した複数案を保管する列。プルダウンの**候補元**。改行区切りで複数案を格納。

### Amazon相乗りSKU（既存カタログ相乗り専用・2026-07-30承認）

- `子SKU` は楽天／Yahoo／Amazon新規カタログの正として変更しない
- `Amazon相乗りSKU` はAmazon既存カタログ相乗りで送るsellerSku。GASがdry_run VALID/issues=0後にNF列へ書き、prodは保存値を再利用する
- 新規カタログ（B/M1）は子SKU、既存相乗り（A/M2）はAmazon相乗りSKUを使う
- 同一sellerSkuがAmazonにあれば更新、無ければ新規登録。旧JAN型子SKUと新ASIN型Amazon相乗りSKUは別sellerSku
- N列 `ASINコード` は人間が確定した相乗り先。O列 `競合店ASINコード` と競合URL／DB列はリサーチ参考値で、出品先には使わない
- 保存済み値のASINと確定ASINが不一致なら、自動上書きせず停止
- 物理列番号は固定せずヘッダ名で解決する
- 列追加前後に `[セット構成提案][列範囲チェック]` を確認し、親SKU／子SKU等がコピー範囲内であることを実機検収する

## 列追加・削除による影響（テンプレコピー範囲）

- セット構成提案（メニュー「1. セット構成を決める」）では、Q列から**「⇒AI作業エリア」列**（ヘッダー名で検索）まで、1行目・2行目の数式を親行・子行にコピーしている。「⇒AI作業エリア」列が見つからない場合はシートの最終列（numMasterCols）までをコピーする。
- 列の追加・削除をすると、**コピー範囲が列番号に依存している**ため、重要列（親SKU・子SKUなど）が範囲外になり、式が入らない・不整合が起きることがある。
- **不具合が出た場合の対処**:
  1. 列追加・削除の影響を疑う。
  2. 実行ログの `[セット構成提案][列範囲チェック]` を確認し、テンプレコピー範囲（開始列・終了列）と重要列の位置（範囲内=true/false）を見る。
  3. 「WARNING … がコピー範囲外です」と出ている列があれば、**影響範囲の列**と**広げるべきコピー範囲**（例: 終端を「⇒AI作業エリア」列まで含めているか、列の並びが正しいか）を人間が判断し、列レイアウトの見直しや列の追加・並べ替えで対応する。
- コード側で範囲を自動拡張・補正することは行わない（意図しない列までコピーするリスクのため）。ログで検知し、人間に提案する。
- **リスク**: 列追加後に気づかず運用し続けると、親SKU・子SKU等が空白のままになる、想定物流費AI試算・価格提案等で整合性が崩れる可能性がある。定期的にログの WARNING 確認を推奨する。

## 列解決の仕様（getTitleDropdownColPair・実装注意）

- **意図**: 候補元＝マスタエリア列（複数案）、設定先＝人間の作業エリア列（プルダウンを付けるセル）。両方が別列で存在するときはそのペアを使う。
- **注意**: 「設定先候補」から外すのは、**候補元として採用した列と同一列インデックスのときだけ**とする。`targetNames` の名前が `optionsNames` に含まれるからといって一律にスキップすると、CTRコピー・特徴キーワード・用途キーワード・楽天 補足KW・Yahoo! 補足KW で「設定先＝[CTR,CVRを上げるコピー]」や「設定先＝楽天 補足KW」が選ばれず、候補元と同一列にフォールバックし、リストが付かない・候補数0になる。
- **修正方針**: 設定先を選ぶループで、`optionsNamesSet[kt]` のときは「`masterColMap[kt] === optionsIdx` のときだけスキップ」するようにする。

## 「同じ結果」の定義（プルダウン挙動）

- **同じ結果**: どの親行も**プルダウンが付く**（値の貼り付けのみにならない）という**挙動**が同じであること。
- **中身**: 行（商品）ごとに候補の内容・選ばれた値は異なってよい。

## CTRコピー・おすすめ表示

- **指示**: マスタエリアの値で人間作業エリアをプルダウンにし、かつ**おすすめの値を1件表示する**。
- **候補元**: ▼マスタ(CTRコピー)（`[char_8]` 等のプレフィックス付き複数行）。
- **設定先**: [CTR,CVRを上げるコピー]。ここにプルダウン（リスト）を設定し、表示値はおすすめ1件にする。
- **syncAiDataToMaster**: AI情報取得data の行をマスタの親行に載せる処理。 **突合順**は **ASINコード → JANコード → 商品名または商品名amazon → 商品名ベース**（最後はマスタに当該列がある場合のみ）。名前系は AI情報取得data の **商品名** と同じ正規化で `aiMapByName` 照合。子SKU行はスキップ。**経緯・判断**（JAN/ASIN 空でベース名のみの行への対応・誤同期リスク）は [TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md](TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md) の「AI→マスタ同期（`syncAiDataToMaster`）の突合に「商品名ベース」を追加した件（2026-05）」参照。**CTRコピー**項目については `getCtrRecommendedFirstLine` でおすすめ1行を取得し、作業エリア列 [CTR,CVRを上げるコピー] に書き込む。**楽天キャッチ(60-80字)／Yahooキャッチ(20-30字)** も同様に、作業エリア（`楽天キャッチコピーAIから取得`／`Yahoo!キャッチコピーAIから取得`）へは `getFirstDropdownOptionLine_` で **先頭1案のみ**書き込む（改行複数案の全文転記禁止。複数案は ▼マスタ 列に残す）。プルダウンは別途「キーワードプルダウン再設定」で設定先に付ける（列解決で設定先が [CTR,CVRを上げるコピー] になる必要あり）。
- **全プルダウン列のおすすめ表示**: キーワードプルダウン再設定（`setTitleDropdownForParentRowsWithGivenRows`）では、各論理列ごとにデータ検証（プルダウン）を設定したあと、**設定先セルに候補の先頭（おすすめ1件）を setValue する**。これにより、商品名検索キーワードamazon/楽天/Yahoo!・楽天キャッチコピーAIから取得・Yahoo!キャッチコピーAIから取得・バリエーションテーマ・楽天ジャンルID・Yahooカテゴリ・Yahooブランドコード 等、すべてのプルダウン列でおすすめが選ばれた状態で表示される。

## 楽天ジャンルID・Yahooカテゴリ・Yahooブランドコードのプルダウン

## 統合メニュー（商品名案生成＋プルダウン再設定）

- **処理順**: キーワード案・商品名案を生成してマスタに書き込んだあと、**SpreadsheetApp.flush()** してから **masterValues = masterSheet.getDataRange().getValues()** で再取得し、**その最新の masterValues** でプルダウンを組み立てる。これにより特徴キーワード・用途キーワード・補足KW の候補が書き込み後に反映される。
- **ログ**: 不具合調査用に「キーワード書き込み後 masterValues 再取得 行数=N（プルダウン候補はこの最新データで組み立て）」を出力する。

## 親SKU行と子SKU行

- **プルダウンを付ける行**: レ点の付いた**親SKU行のみ**。子SKU行にはプルダウンを設定しない（仕様どおり）。子SKU行にデータが入るのは想定外。
- **Yahoo!出品の親データの参照先（2026-05）**: 同一「親SKU」で親行ブロックが複数ある（本線の下に下書き用の親行を置く等）場合、Yahoo側は **出品CKが付いた親行のうち最も下に近い行**を、キャッチ・カテゴリ・商品名系の親マージ元として使う。レ点付き親が無いときだけ、走査上「最後の親行」（レ点不問）にフォールバックする。子の出品対象は**子の出品CKのみ**（従来どおり）。詳細は `docs/TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md` §「Yahoo!出品: 親行データの選定（2026-05）」。
- **Yahoo! `path` と (Yahooカテゴリ名)（2026-05）**: `(Yahooカテゴリ名)` は **`＞` 区切りのまま**プルダウンで選べる。Yahoo マッピングの **`path` が当該列を参照している場合**、editItem 送信時のみ **半角 `:` 区切り**に正規化し、**マスタのセルは書き換えない**。詳細は同ドキュメント §「Yahoo! editItem path の正規化（2026-05）」。

## バリエーション名（16文字まで）

ECモールのバリエーション名を「空白なら使わない・値が入っていればつなぎ合わせる」ルールで組み立てる。**バリエーション名 16文字まで**は計算式で出力し、計算式はコードに含めず人間がスプレッドシート上で管理する。

### 列の役割

| 列名 | 参照・入力 | 役割 | 空白のとき |
|------|------------|------|------------|
| **A.セット商品数** | 既存列（子SKU行ごと） | セット数 | 結合時に「セット数」部分を出さない |
| **バリエーション接頭辞** | 手入力 or 将来AI | 先頭に付ける文言（例: 蒸し生姜湯） | 使わない |
| **バリエーション単位** | AI提案→人間修正（親で1つ、子行へコピー） | 単位（袋・個・食・本・瓶など） | 使わない |
| **1個当たり内容量** | AI提案 or 手入力。コードが行ごとに「セット数×1セットあたり」を計算して書き込む | 「/」の後ろに付ける内容（96包, 400g など）。**数値+単位**のシンプル形式のみ（16g×は使わない） | 「/」以降を出さない |
| **バリエーション接尾辞** | 手入力 | 末尾に付ける文言（・六漢1袋, +唐辛子1瓶 など） | 使わない |
| **バリエーション名 16文字まで** | 計算式で出力 | 上記を結合した最終表示名（最大16文字） | — |

- 楽天は「バリエーション1選択肢定義」および SKU のバリエーション値が**合計32バイトまで**の制約あり。16文字を超えないようにし、必要に応じて Shift_JIS で32バイトチェックを行う。

### 結合順（計算式のルール）

1. バリエーション接頭辞（あればそのまま）
2. A.セット商品数（あればそのまま）
3. バリエーション単位（あればそのまま）
4. 1個当たり内容量（あれば **「/」＋その値**）
5. バリエーション接尾辞（あればそのまま）
6. 結合結果を **16文字** で切り詰める。

### 内容量の形式（16g×を除く・セット数/内容量で統一）

- **1セットあたり**を「数値＋単位」のシンプル形式で扱う（例: **48包**, **100g**）。「16g×48包」のように1包あたり内容量を出さない。AIが1包あたりと1セットあたりを混同しにくくするため。
- 各行の**1個当たり内容量**には、**その行のセット数 × 1セットあたり数値 ＋ 単位** を書き込む。例: 1セットあたり48包 → 2セット行は 96包、3セット行は 144包。1セットあたり100g → 4個行は 400g、6個行は 600g。結果として 2袋/96包、4個/400g のように**セット数/内容量**がシンプルに揃う。

### AI提案（商品名案を生成＆プルダウン再設定 実行時）

- **同一JANの◎（ASIN貼り付け Keepa用）**: `AI情報取得data` の JAN と一致するブロックで、評価列が「◎」の行の商品名がある場合、**バリエーション単位**・**1セットあたり内容量**の両方をそこから優先して推論する（`inferVariationFromAsinCircleForJan_`）。**◎ が複数行**ある場合は **全行を材料に総合判断**（質量・容量を袋数より優先）。無効時は Script Property `B_STEP7_CONTENT_FROM_ASIN_CIRCLE_ENABLED=false`。旧「先頭の ◎ だけで確定」に戻す場合は `CIRCLE_COMBINED_PER_SET_CONTENT=false`（詳細は [AI_ROUTING_GEMINI_OPENAI.md](AI_ROUTING_GEMINI_OPENAI.md) §1.1）。
- **バリエーション単位**: 上記◎がなければ親行の商品名から Gemini → OpenAI → 内容量からのフォールバック。使用可能単位は 個/箱/袋/パック/本/セット/食/瓶。提案値を親行とその子SKU行すべてに書き込む。
- **1セットあたり内容量**: ◎商品名があればそれを `getContentPerItemFromProductName` でパース。なければ親行の商品名を `parseProductNameByGemini` でパースし、**数値+単位**のシンプル形式で取得（袋数があれば「48包」、重量のみなら「100g」）。コードが各行の A.セット商品数 を使って「セット数×数値＋単位」を計算し、その行の 1個当たり内容量 に書き込む（親行・子行それぞれで異なる値になり得る）。
- 列がマスタに存在しない場合はバリエーション提案はスキップする。

### キーワード案・商品名案のAI（OpenAI / Gemini）— 実装の正

- **キーワード案**・**商品名案（Amazon / 楽天 / Yahoo）**の本線は **OpenAI（ChatGPT API）** のみ。キーワード列が存在する場合のみキーワード案を生成し、その後に各モールの商品名案を生成する。
- **Gemini でモール別の商品名案を生成する処理**はコードに存在するが、**通常の Z／B メニューからは呼ばれていない**（未配線）。運用で「Gemini 主」と誤解しないこと。
- **バリエーション単位・1セットあたり内容量**の扱いは、直前の箇条書き（◎優先、Gemini→OpenAI、内容量パース）が**実装の正**。

### 11-③ と B 統合 Step7 の違い（検証・障害切り分け）

- **Z「11-③ 商品名案のみ生成」**は、レ点付き親行に対し **一括処理**（キーワード→商品名案→条件を満たせばバリエーション書込）。**商品名案（OpenAI）が取得できない**（429 等）場合でも、**マスタに商品名（商品名ベース等）があれば**、既定では **バリエーション書込まで進む**（`runProductNameProposalsForRows`）。旧挙動（OpenAI 失敗行はバリエーションもスキップ）に戻す場合は Script Property `PRODUCT_NAME_PROPOSALS_CONTINUE_VARIATION_ON_OPENAI_FAIL=false`。
- **B 統合の Step7**は **フェーズ分割・時間分割**（状態を保持して再開）。キーワードが空でも次フェーズに進む設計。**商品名が空でもバリエーション（単位・内容量）フェーズに入る**ことがある。検証時は「商品名列が埋まっているか」「ログに `[Step7][variation]` 等があるか」を併せて確認すること。
- 詳細・429 時の注意は [AI_ROUTING_GEMINI_OPENAI.md](AI_ROUTING_GEMINI_OPENAI.md) を参照。

### 計算式（1行目に書く前提・人間が管理）

**バリエーション名 16文字まで** のセルに、先頭データ行で次の式を入れ、下方向にコピーする。  
`E` は A.セット商品数 の列、`GJ`=バリエーション接頭辞、`GK`=バリエーション単位、`GL`=1個当たり内容量、`GM`=バリエーション接尾辞とする。行番号は先頭データ行に合わせて変更する。

```
=LEFT( IF(GJ8="","",TRIM(GJ8)) & IF(OR(E8="",E8=0),"",E8) & IF(GK8="","",TRIM(GK8)) & IF(GL8="","","/"&TRIM(GL8)) & IF(GM8="","",TRIM(GM8)) , 16)
```

- A.セット商品数 が別列の場合は `E8` をその列のセル参照に変更する。

### コード上の定数・関数（コード.js）

- `COL_VARIATION_UNIT` = バリエーション単位
- `COL_CONTENT_PER_ITEM` = 1個当たり内容量
- `COL_VARIATION_PREFIX` = バリエーション接頭辞
- `COL_VARIATION_SUFFIX` = バリエーション接尾辞
- `COL_VARIATION_NAME_16` = バリエーション名 16文字まで
- `getContentPerItemFromProductName(productName)` = 1セットあたりを「48包」「100g」のシンプル形式で返す（16g×は使わない）
- `inferVariationFromAsinCircleForJan_(ss, jan)` = 同一JANの◎行商品名から 1セットあたり内容量・単位を推論（Step7・商品名案のバリエーション書込と共通）
- `getPerSetContentFromAsinCircleTitles_(ss, jan)` = 上記の内容量のみ（後方互換）
- `formatContentAmountForRow(perSetContent, setCount)` = 1セットあたり文字列とセット数から、その行の表示用内容量（96包, 400g）を計算する
