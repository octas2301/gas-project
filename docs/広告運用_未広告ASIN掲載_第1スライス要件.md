# 未広告ASIN掲載 — 第1スライス要件

**最終更新**: 2026-10-17  
**ゴール**: 未広告の子ASINを、**親ASIN単位のオート＋マニュアル・キャンペーン**に載せる。広告グループは**子ごと**。既存親キャンペーンがあればそこに混ぜる。最適化レーンBは従来どおり。  
**実装状態**: §3 改訂（長名・ASIN末尾廃止／Listings→Catalogのみ／ブランド列／前回スナップショット）を `UnadvertisedAsin.js` に反映。**clasp push・実機検収は人間**。

## 0. 「かぶり」の意味（誤解の解消）

**親に紐づいている子どうしが「かぶっている」わけではない。**

| 混同しやすいもの | 実際 |
|------------------|------|
| 親ASINくくり | 同じ親の子は **1キャンペーンを共有**する。名前は親ブロックで1つ。兄弟同士で名前競争はしない |
| 旧仕様で起きていた「かぶり」 | **別の親ブロック**（または既存キャンペーン）が、短縮後に **同じキャンペーン名文字列** になると、Amazonアカウント内で名前が衝突する。機械が親ASIN末尾（例: `VGXT`）を付けて区別していた |

**実例（焼鳥丼）**

1. 相乗り側の親（別カタログ）が先に名前 `吉野家 缶飯 焼鳥丼` を使う  
2. 自社バリエの親 `B0HCXNVGXT` も商品名ベースが同じ → 短縮名が同一文字列  
3. 旧仕様が自社側に `VGXT`（親ASIN末尾）を付与  

→ **親子の紐づけミスではない。別名の親キャンペーン同士の「名前文字列」の衝突。**  
本改訂ではこの ASIN末尾識別をやめ、**長い名前で商品がすぐ分かる**ことを優先する。

## 2. 処理イメージ（確定）

```
SP-API出品一覧（出品開始日新しい順）＋親ASIN（Listings→Catalogのみ）
  × 広告中の商品CSVで 子の広告あり／なし
  × 既存キャンペーン（親単位）の有無を判定
       （判定: 広告中CSVに同じ親の子が1件でもある）
  → 一覧（親ブロック・予定名・ブランドが見える）
  → 人間がレ点（載せる子）
  → 親ごとに:
       ・既存オート／マニュアルがあれば → キャンペーンは増やさない
         ・その子用の広告グループが無ければ新規AG＋商品広告（SKU）
         ・あれば商品広告（SKU）だけ追加
       ・無ければ → 新規オート＋マニュアル（各1キャンペーン）
         ・レ点子ごとに広告グループ1・商品1ASIN
         ・マニュアル初回KW: 商品名ベースを完全一致で1語
       ・除外KW: その親の全子ASINを完全一致で、キャンペーン＋各AGの両方
  → バルクxlsx → 人が一括操作UL
```

**構造の正**

| 層 | 単位 | 意図 |
|----|------|------|
| キャンペーン | 親ASIN（オート1＋`Manual_`1） | 出品・日予算をまとめる |
| 広告グループ | **子ASINごと**（1グループ＝1商品） | 用語分析・除外・調整をバリ別にできる |
| 商品広告 | SKU | 既存混ぜは基本ここ |

一覧の末尾に見える `A0…` は **AmazonのキャンペーンID**。新規名には付けない。

### 3.1 名前（P4／P4b）— 改訂の正

**目的**: キャンペーン名を見て **どの商品かすぐ分かる**。短い字数制限より可読性を優先。

| 項目 | 正 |
|------|-----|
| オート名の種 | ①出品マスタ `商品名ベース`（あれば）②無ければ SP-API 商品名（タイトル） |
| マニュアル名 | `Manual_` ＋ オートと同じ本体 |
| 長さ | **意図的な15／20字切りは廃止**。Amazon一括の上限まで使ってよい（実装の硬上限 **128文字**＝一般的なSPキャンペーン名上限。本体はそれ未満に収める） |
| 禁止 | 親ASIN／子ASIN／キャンペーンIDの末尾を名前に付けて区別すること（旧 `VGXT` 方式） |
| 既存混ぜ | 既存キャンペーン名は維持（変えない） |
| 同一文字列が残る場合 | 備考に `名前衝突`。該当親の新規行は **既定レ点OFF**（人間が予定名を直すか対象外）。機械はASIN末尾で勝手に伸ばさない |
| 広告グループ名 | キャンペーン本体＋バリ名（分かれば）。長くてよい（硬上限128）。子ASIN末尾付与はしない。同一親内でAG名が衝突したらバリ名・缶数などタイトルから取れる差を足す。それでもダメなら備考 `AG名衝突` |

### 3.2 親ASINの正（P10）

| 順 | 手段 | 備考 |
|----|------|------|
| 1 | SP-API **Listings** の relationships（parentAsin／parentSku→親SKUのASIN） | 出品一覧取得時の relationships を使う |
| 2 | SP-API **Catalog** relationships（バッチ） | Listingsで取れない子向け |
| 3 | Catalog **単発再試行** | バッチ取りこぼし向け |
| 4 | **前回一覧**の子→親（子自身は使わない） | API空振りの保険 |
| — | 出品マスタの親SKU／子SKU | 親くくりには使わない |

失敗時のみ親＝子自身（備考 `親ASINフォールバック=子`）。

マスタ参照は **商品名ベース・バリ名・相乗りSKU補助・（任意）メーカー名フォールバック** に限定。親くくりには使わない。
