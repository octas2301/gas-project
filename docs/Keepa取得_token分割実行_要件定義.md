# Keepa取得：token 分割実行・画面非依存 要件定義

**目的**: ASIN貼り付け（Keepa用）シートでの Keepa 取得について、画面固定をやめ、token 制限に合わせた分割実行・トリガー再実行・終了予定表示を可能にする。

参照: [RESEARCH_AND_ESTIMATE.md](RESEARCH_AND_ESTIMATE.md) §8.4、[メニューとフロー_サマリー.md](メニューとフロー_サマリー.md) §9（A. ASIN貼付⇒Keepa抽出）。

---

## 1. スコープ

| 対象 | 内容 |
|------|------|
| **処理** | `runKeepaFetchAsinPasteSheetImpl`（コード.js）。メニュー「1. Keepa取得（20件）」「2. Keepa取得（50件）」「3. Keepa取得（全件）」から呼ばれる。 |
| **シート** | 「ASIN貼り付け（Keepa用）」シート。`getSheetByName(ASIN_PASTE_SHEET_NAME)` で取得する。 |

---

## 2. 画面に依存しない実行

- アクティブシートが「ASIN貼り付け（Keepa用）」でなくても、**常に `getSheetByName(ASIN_PASTE_SHEET_NAME)` でシートを取得**し、処理を続行する。
- トリガー実行時も、ユーザーが別シートを開いたままでよく、実行中に他の画面にしていてもよい。
- シートが存在しない場合は自動作成し、そのときだけシートに切り替えてメッセージを表示してよい。

---

## 3. Keepa token の前提（計算の定義）

**日次リセットの件数枠ではない。** Keepa 公式（[api-docs](https://keepa.com/api-docs/)）: プランが **毎分一定数（`refillRate`）** を生成する。未使用トークンは **60分（1時間）で失効**。貯められる量 ≒ **`refillRate` × 60**。

**正の優先順位**: ①応答の `refillRate` / `tokensConsumed` / `tokensLeft` / `refillIn` → ② Property `KEEPA_REFILL_RATE` → ③下記フォールバック。料金画面のプラン表だけで「現行」と書かない。

### 3.1 料金画面のプラン選択肢（参考・2026-08-20）

| プラン | トークン/分 | バケツ（×60分） |
|--------|-------------|-----------------|
| Starter | 20 | 約 1,200 |
| Developer | 250 | 約 15,000 |
| Business | 2,000 | 約 120,000 |
| Enterprise | 10,000 | 約 600,000 |

※ 上表は購入候補。契約後は **API 応答で確定**する。

### 3.2 本契約の実測（確定・2026-08-20）

| 項目 | 値 | 根拠 |
|------|-----|------|
| **`refillRate`** | **5 /分** | ①ログ `pr_20260820_211319`（味の素）`refillRate=5` |
| **バケツ目安** | **約 300**（5×60） | 同ログ `left=285` |
| 待ち分数 | `ceil(15/5)=3` | 同ログ `consumed=15 waitMin=3` |

プランを上げたら応答の `refillRate` を見て本表を更新する。

### 3.3 本PJの計算前提

| 項目 | 値 | 備考 |
|------|-----|------|
| **1ASIN あたり（出品）** | **2 トークン** | `stats`＋`offers=20` のフォールバック。正は `tokensConsumed`。 |
| **1ASIN あたり（①門）** | **おおよそ1トークン** | `history=0&stats=90`。正は `tokensConsumed`。 |
| 回復フォールバック | **5 トークン/分** | 実測。Property `KEEPA_REFILL_RATE` 可。**応答があれば優先**。 |
| **バケツ（貯め上限）** | **約 300**（5×60） | 日次枠ではない。 |
| **分割の基本件数** | **20 件/回** | 出品「Keepa取得（20件）」／①メーカー洗い既定。 |
| **1回チャンク上限（全件）** | **150 件** | 運用上限。 |
| **トリガー待ち分数** | **`ceil(tokensConsumed / refillRate)`**（最低1分） | 例: 消費15・5/分→3分。応答無し時のみ `件数×2÷5`（出品）。 |

※ 実測と料金画面が食い違うときは **実測（応答）を正**とする。

## 4. 機能要件

### 4.1 分割実行

- メニュー「Keepa取得（20件）」「Keepa取得（50件）」では、**1回の実行で最大 20 件／50 件**（全ブロック合計）まで API を叩く。
- 未取得の ASIN が残っている場合、**時間トリガー**で「回復時間（**`ceil(tokensConsumed/refillRate)`** 分）後に続きを実行」する。
- バケツ満タン時の目安（実測約300トークン）を超えない範囲で、**20件／50件**の分割により運用する。日次枠ではない。
- **「Keepa取得（全件）」**: 運用上は**全件を基本**とし、20件／50件は急ぎのときだけ使う。全件実行は**夜に回し、翌朝までに整っている**ことを想定する。
  - 対象が 150 件以下なら 1 回で完了する。
  - **150 件を超える場合**は、**1回あたり最大 150 件**ずつ処理し、トリガーで続きを実行する（分割＋トリガーで完了させる）。

### 4.2 トリガー再実行

- 分割で残りがあるとき、**Script Properties** に再開位置（スプレッドシート ID・ブロック・行）を保存する。
- **時間ベースのトリガー**を 1 本だけ作成し、**`ceil(tokensConsumed/refillRate)` 分後**（最低1分。応答が無いときだけ件数×2÷既定5）に「続きを実行する関数」を 1 回だけ呼ぶ。ログに consumed / refillRate / left / refillIn / afterMin を残す。
- トリガー実行時は、保存されたスプレッドシート ID で `SpreadsheetApp.openById` し、**アクティブシートに依存せず**続きから処理する。
- **トリガーによる続きの実行は、ユーザー操作なしに自動で行う。** 確認ダイアログや「実行する／しない」の選択は行わない。

### 4.3 最初の実行時の終了予定表示

- **最初の実行時のみ**（メニューから「Keepa取得（20件）」または「Keepa取得（50件）」を実行したとき）、条件を満たす場合に**終了予定**をユーザーに伝える。トリガー実行時は表示しない。
- **「対象が limit を超える場合」**: シート上の**対象 ASIN 数（asinCount）**が、メニューで指定した **limit（20 または 50）より大きい場合**。
  - 「20件」のとき: asinCount ≥ **21** のとき表示。
  - 「50件」のとき: asinCount ≥ **51** のとき表示。
  - 「全件」のとき: limit=0 のため表示しない。
- 表示内容の例: 「全件取得の終了予定: 約 XX 分後」（XX = **対象件数×2÷refillRate の切り上げ**。フォールバック refillRate=**5**）。
- 表示後は**実行の可否をユーザーに聞かず**、そのまま処理を開始する。
- **ログ（原因調査用）**: 終了予定判定（fromTrigger, limit, asinCount）に加え、**tokensConsumed / refillRate / tokensLeft / refillIn / waitMin** を毎回 `Logger.log` で出力する。

### 4.4 状態の保持（Script Property）

| キー | 内容 |
|------|------|
| `KEEPA_FETCH_STATE` | 分割続行用。JSON で `{ spreadsheetId, limit, nextBlockIndex, nextRowIndexInBlock }` を保存。続きが無ければ削除する。 |

- トリガーは「Keepa 取得続行用」のハンドラ名（例: `runKeepaFetchFromTrigger`）にし、本処理のみがそのトリガーを削除・作成する。

## 6. 非機能・制約

- 既存の「20件／50件／全件」メニューは維持する。
- **全件**: 運用は全件を基本とし、夜実行で翌朝までに全件処理が完了していることを想定する。150 件を超える場合は分割＋トリガーで完了させる。
- トリガーは「1 回だけ実行」の時間トリガーとし、実行後に削除する。複数本が残らないようにする。
- エラー時はトリガーを作成せず、状態は残してもよい（ユーザーが再度メニューで実行すれば上書きされる想定）。
- **計算の定義**: 終了予定・トリガー間隔は「**応答の tokensConsumed / refillRate**」が正。フォールバックは「**1 ASIN = 2 トークン**」「**回復 5/分（実測）**」。例: 消費15・5/分→3分後。分割の基本は **20件/回**。1回チャンク上限は運用上150件。
