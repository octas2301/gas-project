# Keepa取得：token 分割実行・画面非依存 要件定義

**目的**: ASIN貼り付け（Keepa用）シートでの Keepa 取得について、画面固定をやめ、token 制限に合わせた分割実行・トリガー再実行・終了予定表示を可能にする。

参照: [RESEARCH_AND_ESTIMATE.md](RESEARCH_AND_ESTIMATE.md) §8.4、[メニューとフロー_サマリー.md](メニューとフロー_サマリー.md) §9（A. ASIN貼付⇒Keepa抽出）。

---

## 1. スコープ

| 対象 | 内容 |
|------|------|
| **処理** | `runKeepaFetchAsinPasteSheetImpl`（コード.js）。メニュー「1. Keepa取得（20件）」「2. Keepa取得（50件）」「3. Keepa取得（全件）」から呼ばれる。 |
| **シート** | 「ASIN貼り付け（Keepa用）」シート。`getSheetByName(ASIN_PASTE_SHEET_NAME)` で取得する。 |

---

## 2. 画面に依存しない実行

- アクティブシートが「ASIN貼り付け（Keepa用）」でなくても、**常に `getSheetByName(ASIN_PASTE_SHEET_NAME)` でシートを取得**し、処理を続行する。
- トリガー実行時も、ユーザーが別シートを開いたままでよく、実行中に他の画面にしていてもよい。
- シートが存在しない場合は自動作成し、そのときだけシートに切り替えてメッセージを表示してよい。

---

## 3. Keepa token の前提（計算の定義）

| 項目 | 値 | 備考 |
|------|-----|------|
| **1ASIN あたり** | **2 トークン** | 計算・終了予定・トリガー間隔の前提。 |
| 回復 | 5 トークン/分 | Keepa Pro では画面に「1分あたり5トークン」と表示される。 |
| **上限** | **300 トークンで固定** | **どれだけ待っても 300 を超えて回復しない。** 1回の実行で使えるトークンも最大 300 まで。 |
| **1回で処理できる最大 ASIN 数** | **150 件** | 300 ÷ 2 = 150。それ以上は分割が必要。 |
| 回復に必要な時間 | N 件処理後 → 約 **2N/5** 分（切り上げ） | 1ASIN=2トークンのため。例: 20件→約8分、50件→約20分、150件→約60分。 |

※ 実運用で実績が異なる場合は、本ドキュメントおよび RESEARCH_AND_ESTIMATE.md §8.4 を更新すること。

---

## 4. 機能要件

### 4.1 分割実行

- メニュー「Keepa取得（20件）」「Keepa取得（50件）」では、**1回の実行で最大 20 件／50 件**（全ブロック合計）まで API を叩く。
- 未取得の ASIN が残っている場合、**時間トリガー**で「回復時間（2×処理件数÷5 分の目安）後に続きを実行」する。
- トークン上限 300（＝150件相当）を超えない範囲で、20件／50件の分割により運用する。
- **「Keepa取得（全件）」**: 運用上は**全件を基本**とし、20件／50件は急ぎのときだけ使う。全件実行は**夜に回し、翌朝までに整っている**ことを想定する。
  - 対象が 150 件以下なら 1 回で完了する。
  - **150 件を超える場合**は、**1回あたり最大 150 件**ずつ処理し、トリガーで続きを実行する（分割＋トリガーで完了させる）。

### 4.2 トリガー再実行

- 分割で残りがあるとき、**Script Properties** に再開位置（スプレッドシート ID・ブロック・行）を保存する。
- **時間ベースのトリガー**を 1 本だけ作成し、**回復に必要な分数後**（1ASIN=2トークンなら 処理件数×2÷5 分の切り上げ）に「続きを実行する関数」を 1 回だけ呼ぶ。
- トリガー実行時は、保存されたスプレッドシート ID で `SpreadsheetApp.openById` し、**アクティブシートに依存せず**続きから処理する。
- **トリガーによる続きの実行は、ユーザー操作なしに自動で行う。** 確認ダイアログや「実行する／しない」の選択は行わない。

### 4.3 最初の実行時の終了予定表示

- **最初の実行時のみ**（メニューから「Keepa取得（20件）」または「Keepa取得（50件）」を実行したとき）、条件を満たす場合に**終了予定**をユーザーに伝える。トリガー実行時は表示しない。
- **「対象が limit を超える場合」**: シート上の**対象 ASIN 数（asinCount）**が、メニューで指定した **limit（20 または 50）より大きい場合**。
  - 「20件」のとき: asinCount ≥ **21** のとき表示。
  - 「50件」のとき: asinCount ≥ **51** のとき表示。
  - 「全件」のとき: limit=0 のため表示しない。
- 表示内容の例: 「全件取得の終了予定: 約 XX 分後」（XX = **対象件数×2÷5 の切り上げ**。1ASIN=2トークン・回復5/分前提）。
- 表示後は**実行の可否をユーザーに聞かず**、そのまま処理を開始する。
- **ログ（原因調査用）**: 終了予定を表示するかどうかの判定に使った値（fromTrigger, limit, asinCount、表示するかどうか、表示した場合はメッセージまたは分数）を毎回 `Logger.log` で出力する。

### 4.4 状態の保持（Script Property）

| キー | 内容 |
|------|------|
| `KEEPA_FETCH_STATE` | 分割続行用。JSON で `{ spreadsheetId, limit, nextBlockIndex, nextRowIndexInBlock }` を保存。続きが無ければ削除する。 |

- トリガーは「Keepa 取得続行用」のハンドラ名（例: `runKeepaFetchFromTrigger`）にし、本処理のみがそのトリガーを削除・作成する。

## 6. 非機能・制約

- 既存の「20件／50件／全件」メニューは維持する。
- **全件**: 運用は全件を基本とし、夜実行で翌朝までに全件処理が完了していることを想定する。150 件を超える場合は分割＋トリガーで完了させる。
- トリガーは「1 回だけ実行」の時間トリガーとし、実行後に削除する。複数本が残らないようにする。
- エラー時はトリガーを作成せず、状態は残してもよい（ユーザーが再度メニューで実行すれば上書きされる想定）。
- **計算の定義**: 終了予定の分数・トリガー間隔は「**1 ASIN = 2 トークン**」「**回復 5/分**」「**上限 300 トークンで固定**」を前提に算出する。例: 20件処理→約8分後、50件処理→約20分後。1回で処理できる最大は 150 件（300÷2）。
