# 価格・送料・再③ 要件定義 v1（実装 2026-03）

## 1. 目的

- **税込販売価格**と**送料**の決定順序を、**ドラフト → 送料試算 → 単調補正 → 再③**で揃える。
- **寸法ベースの送料下限ランクは使わない**（既定）。主軸は**価格帯からの推定**と**自己配送マスタ**。
- **ログ**で挙動を追跡可能にし、**Script Properties** で旧挙動へ切り戻し可能にする。

## 2. 処理順（メニュー名に依存しない）

1. **初回価格ドラフト**（CPO 等）：競合 min/max 行は競合−1、他は生成可、利益ガード、単調補正。
2. **送料決定（②.5／現行3.1）**：寸法あり時は **サイズ昇順 first-fit**（箱代最安ではない）。送料＝自己発送表、箱代＝資材D。合計は利益警告のみ。寸法あり不適合・**寸法なし**は空欄（ネコポス埋め禁止）。表に無い／非標準号数（例: 170）のサイズ名は書かない。
3. **単調補正**（価格）：送料確定後、ルールで単価・総額整合。
4. **再③**：同一 JAN 塊で調整（`runRound3PriceAdjustAllMalls_`）。  
   - **競合あり**：従来どおり「最小競合セットより下流」かつ利益 200 円未満を、競合 110% キャップ付きで引き上げ、続けて単価・総額の単調補正。  
   - **全面競合なし**（当該モールの競合列が1件も正の数でない）：利益 **200 円未満**の子行を `round3MinPriceForProfit_(200)` まで引き上げ。**単調補正は行わない**（送料前提の異常で単価逆転が残る場合は許容し、送料を人手確認する想定）。
5. **モール横断**：Amazon → 楽天 → Yahoo の順で再③が走る（同一関数内）。

**②.5 想定物流費AI試算**（`runEstimateLogisticsCost`）：サイズ・梱包箱指定は従来どおり算出値を書き込む。**梱包箱コスト**・**確定送料**は、マスタ **2行目（子SKUテンプレ）** のセルが数式のときは **その数式を対象行へ `PASTE_FORMULA` でコピー**（抜けセット数行と同様、行番号は相対参照で追随）。2行目が数式でないときのみ、従来どおり算出した数値を `setValue` する。

**B-② 単独実行時**（後から実行）：**送料フェーズは走らせず**、マスタの送料を読み、**再③＋（必要なら）楽天Yahoo CPO＋Amazon CPO round2** を実行。

## 3. ログ

- **Logger**：`[pricingV1]` `[logistics]` `[round3]` プレフィックスで出力。
- **任意**：スプレッドシートに **`価格送料ロジックログ`** シートを手動作成し、1行目にヘッダ  
  `日時,タグ,メッセージ,JSON`  
  を置くと、処理が **追記**する（シートが無い場合は Logger のみ）。

## 4. Script Properties（ロールバック／切替）

| キー | 既定 | 意味 |
|------|------|------|
| `PRICING_ROUND3_ENABLED` | （未設定＝true） | `false` で再③をスキップ（B統合・B-②内）。 |
| `B_LOGISTICS_USE_PHYS_RANK` | `false` | `true` で寸法（AI梱包）による `physMinRank` を復活。 |
| `B_LOGISTICS_USE_AI_PACK_DIMS` | `true` | AI 梱包寸法の読み取り（物理ランクと独立。ランク無効時はログ用のみ）。 |
| `B_LOGISTICS_NEKOPOS_ONLY_MIN_UNPROFIT_SET` | （**廃止・未参照**） | 旧: 利益確保不可時に最小セットのみネコポス強制。**2026-08-13 以降コードは読まない**（サイズ選定のみ）。Property を残しても効果なし。 |
| `B_LOGISTICS_USE_3D_FIT` | （未設定＝true） | `false` で3D内寸フィットをオフ（従来の価格帯候補選定に戻す）。 |
| `B_FBA_P1A_DIAG_ENABLED` | （未設定＝true） | `false` で Z 15-⑰ FBAティア診断P1a をオフ。マスタサイズ列は常に書かない。 |
| `B_LOGISTICS_PICK_CLOSEST_DIFF` | `true` | 送料候補が複数のときの差分最小選択（スコア併用時は補助）。 |
| `B_LOGISTICS_SCORE_TIE_BREAK` | `true` | `false` でスコアではなく従来の closest-diff のみ。 |

**Git**：大きな不具合時は **main の直前コミット**へ `git revert` する運用を推奨。

## 5. 再③の分岐（実装）

| 条件 | 挙動 |
|------|------|
| 当該モールで競合が1件以上ある | `minCompSet` より下流の利益不足・`onlyCompBad` スキップ等は従来どおり（`runRound3PriceAdjustForJanMall_`）。 |
| 当該モールで競合が0件 | `runRound3PriceAdjustNoCompAll_`：200 円未満のみ売値を引き上げ、**mono_unit / mono_total は実行しない**。 |

## 6. 競合列（再③）

- Amazon：`競合価格amazon`
- 楽天：`競合価格楽天`
- Yahoo：`競合価格Yahoo!`

## 7. B 統合ステップ（コード）

`B_INTEGRATED_STEP_FUNCTIONS` の順序は **1 → 2 → 3（Amazon CPO V2）→ 3.1（想定物流費）→ 3.2（楽天Yahoo! CPO V2）→ 4（再③・全モール）→ 5 → 6 → 6.5（N列ASIN自動）→ 7 → 7.6（メニュー8・Yahoo売れ筋のみ）**。  
**3.2 を 4 より前**にし、楽天・Yahoo の CPO V2 価格を書いたうえで **再③** が Amazon・楽天・Yahoo をまとめて調整する。  
旧 **3b Amazon(2回目)** は **4 再③** に置換（Gemini 第2ラウンドは既定で含めない）。

**移行注意**：デプロイ前に **B.統合を途中まで実行して保存**している場合、`B_INTEGRATED_RUN_STATE` の `nextStepIndex` は **旧配列前提**のため、**続きから再開せず最初から**実行すること（または Script Properties で `B_INTEGRATED_RUN_STATE` を削除してから再実行）。

## 8. B-②（後から単独実行）

`menuRunPriceProposalOnly`：**楽天Yahoo CPO V2 → Amazon CPO（②.5後・V2）→ 再③** の順。送料フェーズは含めない（マスタの送料をそのまま利用）。
