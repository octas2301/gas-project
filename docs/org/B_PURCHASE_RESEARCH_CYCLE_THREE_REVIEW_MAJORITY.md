## 3. 採用（2/3以上）→ CYCLE 反映

1. **セラーヒットは再計算** … A-light 完了時の +1 加算を廃止。`セラー` 全行の `抽出メーカー` から sellerId 単位で一意集計。初回バックフィル必須。再巡回で水増ししない。
2. **C0（§5.4）を自動サイクルのゲート** … 未実装中は **手動追加のみ**。状態機械のレーン0は **C0 実装後に限る**。
3. **親正本同期** … ⑧週次「運用待ち廃止」を FLOW §5.1・§3、NOW、V1、TASK_STRUCTURE と同時改訂（CYCLE 単独宣言禁止）。
4. **A-light の A 契約変更を明示** … 門・①候補・店ASIN倉庫は A-light では行わない。D/①候補の材料は **レーン2（メーカー洗い完走）** のみ。
5. **Keepaフルからセラー貯めない** … 「全表走査しない。門通過 ASIN の BB 列 JOIN に限定」と定義し直す（NOW 維持）。
6. **自動選定の優先を一本化** … **≤500（または未列挙で見積≤500）をヒット数より先**。同ティア内でセラーヒット降順。食品0%店由来のみのメーカーは除外（FLOW ⑧思想）。
7. **A-light Keepa 方針** … `/product` は **メーカー名抽出のみ・Keepaフルへ upsert しない**（トークン消費のみ。倉庫はレーン2）。429/25分は FULL と同形の温和停止＋続き。
8. **A-light トークン予算** … 既定 **店3×product cap20**（Property）。10×30 は採用しない。1実行上限を要件化。
9. **実態初期値** … サマリ insert 時は **既存シード**（`prSeedMakerJitta_`）。要確認は **洗い対象外**（人が確定するまで）。要確認件数上限は運用メモ（1バッチ後に上位ヒットのみ `実態ck`）。
10. **完走連鎖** … D1/D2 **失敗時は次メーカーを arm しない**。完走連鎖の再 arm は **既存 P3 洗いトリガー＋別承認**。§7.1 の「トリガー予約」は **メニュー手動** と読む（§8 と統一）。
11. **レーン0 SP-API** … 1回上限・429 カーソル・再開位置は C0 実装承認で定義（NOW の cap100 未達を前提）。
12. **競合DB列** … `セラーヒット` 追加は COMPETITOR_FIELDS CSV＋改修履歴（規則7）。実装前必須。
13. **total>1000 hold** … page0 の cap 分だけ **メーカー名抽出は続行**（店は hold だが発見源から消さない）。
