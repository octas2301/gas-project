## 2. 最終形（組み立て）

最終形の**最初のキーはセラーID**。メーカー名洗いはその下流。  
**実装順は逆にしないことだけが目的ではない。** 検収は §1.1 の本線を先に通す。メーカー洗いは「入れたメーカー名」で単体完走できる（JAN・セラー台帳は不要）。

```text
① セラーをリスト化
② sellerId で、ターゲットカテゴリを扱っているセラーをピックアップ
③ リスト化したセラーを定期巡回してリサーチ
④ セラーごとに取扱商品を抽出
⑤ カテゴリーごとに分類
⑥ いまは食品に絞って商品抽出
⑦ メーカー名と商品名を一覧化
⑧ 週1回サマリーし、リサーチするメーカー名を特定
        ↓
入力: メーカー名
  [発見] SP-API Catalog キーワード
         → タイトルにメーカー名を含む（正）
         → 巨大メーカーはキーワードにカテゴリ／アイテムを足してよい（例: 五木食品　麺）
         → ASIN 一意（1行1ASIN。束ねない）
  [属性] Keepa product API（domain=5）→ **競合DB Keepaフルが正**（90日。出品・貼付が再利用）
  [門]   プロファイル表の閾値
  [作業] 調査複製 ①候補（Keepaフルから転記。仕入検討品番リスト相当）
```

**発見は SP-API。** Keepa API は属性。運用して発見精度に問題があれば Keepa 発見も検討（メモのみ。第1版では切替しない）。

**brandNames だけは正にしない。** セット店が落ちる（石原実測）。

JAN が要るのは **この見積書ルート**（書類に JAN が載っているとき、Keepa でピンポイント特定する）。メーカー洗いの必須入力ではない。
