# 共通スプシ参照 — 要件

**文書種別**: requirements  
**対象**: gas-project の全エージェント（リサーチ・出品・広告を含む）  
**状態**: 確定（2026-08-19）  
**最終更新**: 2026-08-25  
**ルール**: `.cursor/rules/common-ss-view.mdc`

---

## 0. 目的

人間が実行結果の確認や合否を求めたとき、エージェントは次を守る。

1. **スプシ本体とログの両方**を見る（ログだけ／コードだけで済ませない）。
2. 見る範囲は **その指示に関係するファイルとタブだけ**（トークン浪費を防ぐ）。
3. 回答の **先頭** に、実際に見たファイル・タブ・ログを書く。

---

## 1. 確定事項

| 項目 | 内容 |
|------|------|
| スプシID | 全プロジェクト共通で **固定**。プロジェクトごとに差し替えない |
| キー名 | ファイル名からの省略名（長さの目安: `自動リサーチ260814_アマゾン調査`） |
| メニューのクリック先 | 基本は常に `自動リサーチ260814_アマゾン調査`（`1tf7…`） |
| 普段 | メニュー単位の最小ファイルセット ＋ 指示に関係するタブだけ |
| 全タブ | 人間が「全部見て」「トラブル」と明示したときだけ。対象は最小セットのファイル |
| 新規の共通スプシ | 共通表に追記して固定。プロジェクト別IDは作らない |
| 見るタブの追加 | 「このシートも見て」と言われたら、Agent モードで本要件の表を書き換える |

---

## 2. このルールを起動する指示

完全一致は不要。次の **2つを満たせば起動**する。

1. 実データを見てほしい（ログ、スプシ、実行結果、書き込みの有無）。
2. 判定または報告してほしい（合否、原因、空振り、混入、書込有無）。

### 起動する例

- ファイルとログを見て合否判定して
- ログとファイルで確認して
- ①ログを見て合否して
- スプシを見て原因を調べて
- 実行結果を見て合格か判定して
- さっきの実行、通った？落ちた？
- サトウ食品をテストした。ログ見て判定して
- clasp 後の結果を確認して
- 書き込まれているか、空振りか見て
- オキハムのヒットが少ない。ログとファイルで確認して

### 起動しない例

- この関数は何をしている？
- 要件をまとめて
- 次に何を実装する？

迷ったら起動する。見なかったタブは書かない。

## 4. メニュー単位の最小ファイルセット

クリックしたメニューで、見る **ファイル** が決まる。

| メニュー | 見るファイル |
|----------|--------------|
| `仕入れ検討①`（レ点メーカー、店調査、D1 など） | `自動リサーチ260814_アマゾン調査` ＋ `統合情報DB260815_競合（amz/楽/Yah）` |
| 出品（`AI出品ツール` / `Yahoo!出品` など） | `自動出品260221_セラセン出力`。競合価格・Keepa が関係するときだけ `統合情報DB260815_競合（amz/楽/Yah）` を足す |
| 広告・タイムセール | `広告自動化_タイムセール（amz/楽/Yah）` のみ |
| `見積・発注`（見積依頼・回答・仕入判断・発注書） | `見積発注_三協乾物` のみ。①の洗い／D1 とは別メニュー（常時セットにしない） |

未定義メニューは、関係しそうなファイルを **最大2本**。迷ったら人間に確認する。  
出品とリサーチは競合DBと連携する。広告は原則この1本だけ。見積・発注は問屋ブック専用。

## 5. タブの絞り込み（普段）

最小ファイルセットの **全タブは読まない**。指示の中身から関係タブだけ取る。

| 指示の例 | 見るタブ（目安） |
|----------|------------------|
| 合否／ログ確認／失敗原因 | `①ログ`。必要なら `①候補`、`仕入検討品番リスト`。当たり直し委譲は競合の `メーカーサマリ`／`セラー`／`実態AIログ` |
| メーカー洗い・レ点 | 上記 ＋ `メーカーサマリ` |
| Keepa が空／未取得 | 上記 ＋ `Keepaフル` |
| 出品の失敗 | 出品スプシのログ相当タブ ＋ 対象マスタ行付近だけ |
| 広告・タイムセール | 広告スプシの当該設定タブとログ相当だけ |
| 見積／未回答／貼付 | `お見積もり依頼リスト`、`見積もり（未回答リスト）`、`貼付sheet`、`PV`（intent `estimate`） |
| 発注／発注書 | `お見積もり依頼リスト`、`PV`。日付タブ `発注書YYMMDD` は `--sheet` で指定（固定登録しない） |
| 見積の利益・送料 | 上記 ＋ `検討`、`送料`（intent `estimate_profit`） |

行も絞る。

- `①ログ`: 今回の実行（`pr_…`）の行。無ければ直近の該当メニュー行
- 結果シート: 先頭の新規行、または指示されたメーカー／商品の行
- チャットには全文を貼らない。判定に必要な行だけ返す

---

## 6. 全タブ参照（例外）

次のときだけ、最小セットのファイルについて全タブを読んでよい。

- 「全部見て」「トラブル時の全タブ」と明示された
- 「このシートも追加して」と指名された（以後は §5 の表に恒久追加）

複数ファイルの全タブを常時読むのは禁止。

---

## 7. 回答の先頭（必須）

§2 で起動した回答は、**必ずこのブロックから始める**。見ていないものは書かない。

```
見た場所:
- ファイル: （省略名）／タブ: （タブ名）
- ファイル: （省略名）／タブ: （タブ名）
- ログ: （①ログ の pr_… と、その行の内容。例: ck_maker Catalog→門 / D1）
```

見られなかった場合は、同じブロックに「見られなかった／理由」を書く。  
その直後に、合否や依頼への答えを書く。

---

## 8. 問題が出る場合

| 状況 | 扱い |
|------|------|
| 表示名が変わった | 省略名と ID は維持。表示名だけ更新 |
| プロジェクト別に別IDが必要になった | 共通表は残し、例外の上書きは後から足す（今は作らない） |
| 全タブ常時読み | 禁止。時間・回数制限・トークンが増える |
| クリック中のタブの特定 | GAS は開いているファイルを知る。エージェントは共通表の ID で読む。実行の特定は `①ログ` の `pr_…` |

## 9. ローカル配置

実データの取得は Google の画面を開かず、次のフォルダで行う。認証は既存の `tools/c1_hpc_packaged/secrets/` を使う。

| パス | 役割 |
|------|------|
| `tools/common_ss_view/registry.json` | 省略名・ID・メニュー最小セット・intent→タブ。**ここが手元の正** |
| `tools/common_ss_view/dump.py` | 関係タブだけ `out/` に出す |
| `tools/common_ss_view/out/` | 取得結果（git 対象外）。先に `seen.txt` を読む |
| `tools/c1_hpc_packaged/secrets/` | token（既存。ここには ID を増やさない） |

エージェント手順:

```powershell
python tools/common_ss_view/dump.py dump --menu 仕入れ検討① --intent judge
python tools/common_ss_view/dump.py dump --menu 仕入れ検討① --intent maker --maker サトウ食品 --run-id pr_20260819_222814
python tools/common_ss_view/dump.py dump --menu 出品 --intent listing_fail --with-competitor
python tools/common_ss_view/dump.py dump --menu 広告・タイムセール --intent ads
python tools/common_ss_view/dump.py dump --menu 見積・発注 --intent estimate
python tools/common_ss_view/dump.py dump --menu 見積・発注 --intent order --sheet 発注書260807
python tools/common_ss_view/dump.py dump --menu 仕入れ検討① --all-tabs
python tools/common_ss_view/dump.py add-sheet --file 統合情報DB260815_競合（amz/楽/Yah） --sheet メーカーサマリ --intent maker
```

`out/` の TSV だけを読む。全文をチャットに貼らない。タブを恒久追加したら `registry.json` と本ファイル §5 を同じ内容にする。
