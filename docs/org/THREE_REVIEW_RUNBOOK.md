# 3者独立レビュー運用（RUNBOOK）

**文書種別**: 情シス／戦略企画の手順正  
**最終更新**: 2026-10-09  
**適用**: 組織憲章・承認マトリクス・重要要件・要件の作り方・運用手順・コード差分の「3者検証＋多数決」  
**親文書**: [AI_ORG_CHARTER.md](AI_ORG_CHARTER.md) §9 ・ [PHASE0_THREE_REVIEW_MAJORITY.md](PHASE0_THREE_REVIEW_MAJORITY.md)

## 1. 基本方針（骨格固定＋案件差込）

| やること | やらないこと |
|----------|--------------|
| **親 Agent 1本**（**手元のチャット**）が子を最大3本・**別系統の最高峰モデル**で**並列**起動 | 人間が New Agent×3 を開き、起動文を手コピペ |
| 子同士は**互いの結果を見ない**（独立） | 1本に「3役を演技」させる正式判定（簡易再レビューのみ可） |
| 親が回収し **2/3採用・1票は未決** の多数決案を出す | 子に正本を勝手に書き換えさせる（書き込みは社長承認後） |
| **固定骨格＋案件差込**。型を選ぶ | チャットごとにプロンプトをゼロから再発明する |
| 起動後、親が**差込要約で一度止める**（正式レビューにつき1回） | 差込未確認のまま子を起動する |
| 親は**いつも手元**。使える**最高峰モデル**を使う | 親を Cloud Agent（雲の別部屋）に置く（実データが見えず判定を誤るため使わない） |

人間の起動は短い指示だけでよい（例: 「Phase0の3者レビューを実行」「型は運用手順で、この作り方を3者レビュー」）。  
親は **本ファイルを読んで** 骨格に差込を載せ、§2 の一度止めのあと子を起動する。

## 1.1 固定骨格と案件差込

**固定骨格（変えない）**

- 役割・独立・コード／新ファイルを書かない・他レビューアを見ない  
- 採点5観点: 実現性／要件漏れ／矛盾／聖域／逃げ漏れ  
- 出力形式（§3）・多数決の型（§4）  
- 必読の共通: 憲章・承認マトリクス・`AGENTS.md` §2（聖域）・§5・§8・`CURRENT_PHASE.md`  
- 子に**例文**（キャッチ・セールストーク等）を書かせない。作り方・運用・差分の可否だけ見る  

**案件差込（そのレビューだけ差し替える）** — 要約は**最大10行**

1. 型（主型。必要なら副型）  
2. 対象ファイル／対象の一文  
3. 壊さない約束（案件の追加分だけ。聖域本体は固定骨格）  
4. 未決の問い（あれば）  
5. 検証サンプルの位置（既存ファイルの場所だけ。子は新しく作らない）  
6. 再レビューなら: 前回の**採用項目**と、未決への**人間の答え**だけ（子の個別結果は入れない）  

差込承認後は、同一内容を全子へ渡す。途中で差込を変えたら、全子を同条件で起動し直す。

---

## 1.2 型（4つ＋副型）

起動時に型を言うか、親が選んで差込の1行目に示す。

| 型 | 使うとき | 5観点で特に見る |
|----|----------|-----------------|
| (1) 憲章・承認 | 憲章・承認マトリクス・組織の決め | 矛盾・聖域・逃げ漏れ |
| (2) 要件の作り方 | 要件・コピー／提案の作り方（文案そのものは対象外） | 要件漏れ・材料限定・人手型禁止 |
| (3) 運用手順 | メニュー・再開・人手クリック・手順書 | 実現性・逃げ漏れ・同じメニューの反復 |
| (4) コード差分 | 実装差分の静的レビュー | 聖域・EC重要変更。**実機合格の代わりにしない** |

**複合**: 主型1つ＋副型。差込の先頭で示す。  
**副型「EC注意」**: 価格・在庫・SKU・外部EC API書き込み・一括更新を含むとき必須。型は増やさない。

## 1.3 人間との流れ

1. 短い起動（人間 → 親）  
2. 親が差込要約（最大10行）を出し、**一度止める**  
3. 人間が承認、または1行の修正指示（**沈黙は肯定にしない**）  
4. 子3本を別系統の最高峰で並列起動  
5. 親が §4 多数決案（採用／未決／質問）。各質問に推奨／理由／根拠  
6. 人間が未決だけ答える（沈黙は肯定にしない）  
7. 親が閉じる。docs 書き込み・コード改修は明示承認後  

割れが無く質問も無いときだけ、レビュー提示だけで閉じてよい。

---

## 1.4 モデル・欠け・差し替え

- **親**: 手元のチャット。その時点で使える最高峰モデル。  
- **子**: 系統ごと（例: Claude系／GPT系／Gemini系）に、使える最高峰を1本ずつ。  
- 3系統揃わないときはメモに「独立性の弱さ」と書く。  
- **子が2本しか返らない**: 正式判定にしない。保留して1本を起動し直す。急ぐときだけ社長の明示承認で2本判定し、メモに「2本」と書く。  
- **予定モデルが使えず差し替え**: 別系統が3本なら正式と認める。差し替えたこと、親と子が同じモデルになったことはメモに必ず書く。  
- 多数決メモに、親と子のモデル名を残す。

## 2. 親がやること（チェックリスト）

1. 型を決める（主型・必要なら副型）。対象 docs／範囲を特定する。  
2. **差込要約（最大10行）を出し、一度止める。** 人間の承認または修正を待つ（沈黙は承認にしない）。  
3. Task／サブエージェント等で **最大3本・別系統の最高峰**を並列起動し、§3 の骨格＋承認済み差込を渡す。  
4. 子の完了を待ち、§4 形式の多数決メモ案を書く。  
5. **docs への書き込み・commit** は社長承認後のみ。書き込み前にファイル一覧・概要・リスクを示して承認を取る。  
6. モデルが3系統揃わない／差し替えた／2本になった場合は、§1.4 どおりメモに注記する。

## 3. 子エージェント用プロンプト（正・コピー元）

親は各子に次を渡す。`Reviewer-N` とモデル名だけ差し替え、続けて**承認済みの案件差込**を付ける。  
例文を書かせる指示は付けない。

```text
【役割】
あなたは独立レビューア（Reviewer-N / 使用モデル名を自己申告）です。
新規構想の勝手な拡大は禁止。既存ドキュメントの検証のみ。
コード・新ファイルは作らない。他レビューアの結果は参照しない。
例文（キャッチ・セールストーク等）は書かない。結論に使わない。

【必読（この順）】
1. docs/org/AI_ORG_CHARTER.md
2. docs/org/AI_APPROVAL_MATRIX.md
3. AGENTS.md の §2（聖域）・§5（レビュー観点）・§8（Cloud注意）
4. docs/CURRENT_PHASE.md（スコープ確認）
5. docs/org/THREE_REVIEW_RUNBOOK.md（本手順。型・差込の約束）
（以下に親が付ける案件差込に従う）

【採点（各1–5＋根拠を2行以内）】
1. 実現性
2. 要件漏れ
3. 矛盾
4. 聖域
5. 逃げ漏れ（要実機・未決の明示不足）

【出力形式（厳守）】
## レビューアID
Reviewer-N（モデル名）

## 総評
（3行以内）

## スコア表
| 観点 | 点 | 根拠 |

## 必須修正（採用推奨）
- …

## 任意改善
- …

## 未決として残すべき事項
- …

## 結論
YES / NO / 条件付き（条件を1～3個）
```

観点の詳細は憲章 §9、§1.2 の型ごとの着眼点、および案件差込に従う。

## 4. 親の多数決出力（正）

```text
## 多数決メモ案
### レビューア一覧（モデル・結論）
親のモデル名も1行で書く。差し替え・2本・独立性の弱さがあればここに書く。
### スコア表（3者）
### 採用（2/3以上）
### 未決（1票または割れ）
### 社長に確認したい質問（3つ以上でもよい）
各質問に **推奨／理由／根拠** を付ける。高校生でも分かる言葉にする。
### 総合: YES / NO / 条件付き
```

採用したものだけ正本差分案を示し、**承認前にファイルを書かない**（または書き込み前に明示承認を取る）。

---

## 5. 人間の最短起動文（任意・記憶用）

コピペ不要が理想。どうしても貼る場合:

```text
docs/org/THREE_REVIEW_RUNBOOK.md に従い、3者独立レビューを実行。
型を決め、差込要約で一度止めてから、親が子を最大3本・別系統の最高峰で並列起動する。
完了後に多数決案のみ提示。docs書き込みとコード改修は承認後／禁止に従う。
```

---

## 6. 簡易モード（例外）

時間がない・軽微な文言修正のみのとき、親1本に「Reviewer-1/2/3を**順に**書き、途中で自己参照して結論を変えない」を許可する。  
正式な Phase 完了判定には使わない。メモに `mode: pseudo-triple` と記す。
