## 1. 共通レイヤ（一片も盛りも同じ）

一片見本・MAIN盛り・SUB盛りで**共通**するもの:

| # | 共通ロジック | 内容 |
|---|---|---|
| C1 | NG一文 | 今回の不合格を1つに切る |
| C2 | 危険文オフ | そのNGを増やす指示を落とす |
| C3 | スロット分離 | 面／形／盛り／袋の役割を混ぜない |
| C4 | 属性クロップ | 見たい属性だけを切り出して参照（縁ノイズ等は切る） |
| C5 | 属性別合否 | 色OKでも縁NGなら縁は不合格のまま |
| C6 | レシピ固定 | 合格条件を最初から使う（手探り連打しない） |
| C7 | 品質段 | 判定できる最安の quality で見る（§3） |
| C8 | 効き確認ループ | 禁止・危険文オフ・打ち消しを **low 生成で絵に効いたか** 見てから先へ進む（§3.1）。必須 |

**共通しないもの（呼び出し側）**

| | 一片見本 | 盛り（MAIN/SUB） |
|---|---|---|
| 画面 | 白〜単一片 | 小皿・場面・キャッチ等 |
| 添付 | SURFACE／SHAPE中心 | ＋一片セット＋IDENTITY＋袋 |
| 出口 | piece_set | MAIN画／SUB画 |

→ 実装は **共通レイヤ1本** ＋ **caller = piece | plating(main\|sub)**。

## 2. 盛り（MAINもSUBも）— T4/T8核

MAIN・SUBの**盛りを作るとき**は同じ核を使う（SUB専用にしない）。

1. SURFACEにディテール用クロップ（**この商品で見たい属性**。判定に不要な縁ノイズ等は切る）  
2. **この回のNGを増やす**危険文をオフ（一件の禁止リストを共通核に焼かない）  
3. SHAPEを「面の正」「色の正」にしない。形スロットが不要なら付けない  
4. 一片セットはロック同送（ゲートで一片なしなら空）  
5. 短い固定文の**型**: 必須属性を面に残す／参照役割を混ぜない／作った感じの規則パターンで属性を代用しない  
6. 合否は§3の品質段に従う  

**個別適用（中身は商品ごと）**: 必須属性・NG・クロップ対象は種・面から決める。  
他商品の禁止文・必須文を共通表や共通核にコピーしない。

## 3. quality 役割（できる限り low）

前提: low/medium/high は指示の賢さではなく、**合否に必要な見え方が残るか**。  
画像モデルは本線 **`gpt-image-2`**（変えるのは quality）。

**原則**: 判定はできる限り **low**。  
low では合否がぶれ、やり直しが増えるときだけ **medium**。  
**high は既定オフ**（合否ラインに使わない）。

| 合否の見方（型・商品非依存） | 判定 quality | 理由 |
|---|---|---|
| 構造の大失敗（別物・構図崩壊・必須属性ゼロ・参照スロット取り違え） | **low** | 大づかみで足りる |
| 危険文オフの効果（落とした指示がまた絵に出ているか） | **low** | 同上 |
| 人工的な規則くり返し（作った縁・作った面）※1 | **low** 優先 | 大失敗は low で見える。迷うときだけ medium |
| 必須属性のうち、**細い表面テクスチャ**の有無 | **medium** | low だと潰れて誤判定しやすい |
| 必須属性のうち、**細い色の帯・淡淡の差** | **medium** | 同上 |
| 形・厚みの**大差**（平たい／曲がりの大づかみ） | **low** | low で足りる |
| 形・厚みの**微差** | **medium** | 微妙なときだけ上げる |
| 採用合否（最終1枚） | 上表の必要段 ※2 | 商品カテゴリで quality を固定しない |
| 納品の一段きれい | high 任意・既定オフ | 合否に使わない |

※1 **その商品の正が規則縁・規則面なら、この行は個別適用で外す**（他商品のNGをここに焼かない）。  
※2 最終でも「細い必須属性」が論点でなければ **low**。論点なら **medium**。

**運用**

1. **先に C8（§3.1）** … low で効きを確認する（ここを飛ばさない）  
2. 効きPASS後、構造の大失敗が残っていれば low で切る  
3. 「細い必須属性」が論点のときだけ medium で合否  
4. 合格レシピを固定し、以降は同じ段で出す（探索に high を使わない）  
5. `recommend_quality` に商品固有語を焼かない

## 3.1 効き確認ループ（C8・必須）

**実証**: 禁止事項・危険文オフを文章に書くだけでは良くならない。  
**low で一度（必要なら数回）生成し、絵に効いたかを見ないと**、良いものにならない。

### 型（商品非依存）— **1枚直列（3枚同時禁止）**

```
1枚だけ生成(low)
  → Visionでその1枚を合否
  → FAIL: 不合格理由一文 ＋ 合格として残す見えの言語化 を積む
         → 禁止／打ち消しを更新して また1枚だけ再生成
  → PASS: 効きPASS。レシピ固定
  → 同じ段の「次の向き」へ進むのは この1枚がPASSしてから
```

**外側フロー（一片→深堀）の正**

| 段 | 添付 | 合否後 |
|---|---|---|
| ② 一片見本 | 種のみ | PASS → ③は任意／省略可。**FAIL → ③へ進む**（止めない） |
| ③ 深堀補完 | 種＋深堀（面） | ②で足りない見えを面で補う。ここも **1枚→合否→修正** |

つまり: **一片だけで合格しないなら、深堀画像を渡して深堀で補完する**。②FAILでフロー停止は誤り。

**禁止**: 向き違いを最初から3枚並行で回すこと（コスト増・不合格理由がぶれ対策不能）。

| 段 | 内容 | quality |
|---|---|---|
| E0 | 今回の絵・種から NG を1つに切る（他商品の禁止リストをコピーしない） | — |
| E1 | そのNG用に危険文オフ＋必要なら短い打ち消し（個別適用） | — |
| E2 | 生成 | **low** |
| E3 | **できた画像を見て**合否（Vision）。NG残存？構造大失敗？数値ヒューリスティックだけの合否は不可 | **low** 生成画を見る |
| E4a | FAIL → C1/C2更新して E2 へ（修正ループ・上限内） | **low** |
| E4b | PASS → **効きPASS**。レシピに残す（C6） | — |
| E5 | 効きPASS後: 細い必須属性が論点なら medium、否则 low のまま本線へ | §3 |

### ルール

1. **効き未PASSのまま medium／④本番／採用に進むな**  
2. **合否の正は生成画像の目視（Vision）**。blob／peak 等は空ファイル検知などの補助のみ  
3. FAIL時の言語化は弱 ban 禁止。必須: **具体差（diff）**／**残す文（keep）**／**次の具体直し（nextFix）**。クラス定型だけ回さない  
4. 種が盛りでも、正は **§3.3 の `judgeSeed`（1単位）** の材質系統。盛りレイアウトコピーは求めない  
5. 効きPASSした組み合わせだけレシピ化（C6）  
6. 上限: 既定 **maxAttempts=10**／スロット（`B5_EFFECT_VERIFY_MAX`）  
7. 記録必須: `diffOneLine` / `keepOneLine` / `nextFix` / `ngOneLine` / `attempt` / 画像パス／**`judgeSeed`**  
8. PASSゼロ時の次種選びは **§3.2 敢えて順位**（上表）。人が型を発明しない  

### 失敗クラス（型・中身は個別）

合否メッセージの置き場。商品名を書かない。

| クラス | 例（中身は商品の観察で差し替え） |
|---|---|
| `multi_unit` | 1単位のはずが山・ばら・複数 |
| `wrong_subject` | 別物 |
| `attr_zero` | 必須属性がゼロ（low で分かる欠落） |
| `slot_mix` | 参照役割の取り違え |
| `danger_residual` | 落とした危険がまた絵に出た |
| `artifact_fake` | 作った感じの規則くり返し（※その商品の正が規則なら使わない） |

## 3.2 敢えて順位（PASSがゼロのとき）

合否（PASS/FAIL）とは別。**合格ゼロの候補群から、次に進む種を機械が選ぶ**ための順位。

### いつ使うか

- C8／外側フローで **PASSが1枚もない**ときだけ  
- PASSがあるなら順位は使わない（PASSを採用）

### 何をもって並べるか（優先順・商品非依存）

| 優先 | 見るもの | 上位 | 下位 |
|---|---|---|---|
| 1 | 単位数 | **ちょうど1単位** | 山・ばら・複数・盛りレイアウト |
| 2 | 材質系統 | **判定種（§3.3）と同じ系統** | 別物・別素材 |
| 3 | 必須属性 | 判定種で求めた縁・面などの属性が残る | 属性ゼロ・つるつる無地の代用 |
| 4 | 画面役割 | 白〜単色背景の一片見本向き | 皿・手・場面ごちゃ混ぜ |
| 5 | 同点 | 判定種の外形の大づかみに近い | 遠い |

- score は **10=最良 … 1=最悪**。理由は一文（商品固有の飾り語を共通プロンプトに焼かない）  
- 記録: `judgeSeed` パス／候補 id／score／why／ラン名  
- 上位1を次の種にして **もう一度②→③**してよい（敢えて1位≠PASSのまま本番へ載せない）

### 禁止

- PASSがあるのに敢えて順位で差し替えること  
- 人が「この型で並べて」と順位基準を発明すること（上表が正）  
- 複数片の盛り種を切らずに順位付けすること（§3.3）

## 3.3 判定単位の固定（複数片が写った種）

**問題**: 種に複数の一片が写っていると、「どれと比べるか」で合否がぶれる。

**正（機械が候補 → 人間が1つ選ぶ＝検収）**

1. 合否・敢えて順位の**前**に、種から **判定単位の候補**を機械が切る（複数クロップ）  
2. **レビュー画面**で候補を並べ、人間が **ラジオボタン（ちょうど1つ）** で選ぶ → これを `judgeSeed` と呼ぶ  
3. 以降の Vision 合否・順位・再生成の「種」参照は **必ず `judgeSeed` のみ**（盛り全体を種にしない）  
4. `judgeSeed` のパスと、落選候補一覧を report に残す  

**役割分担**

| 誰 | やること | やらないこと |
|---|---|---|
| 機械 | 種を見て候補クロップを出す・画面に並べる | 人間に框を手描きさせない／文案を書かせない |
| 人間 | ラジオで **1つだけ**選ぶ（検収） | 型名・順位基準・新しい切り方の発明 |

**候補の出し方（型）**

| 種の見え | やること |
|---|---|
| すでに1単位だけ | 候補1枚＝全体。ラジオ確認だけ（スキップ可にするなら明示フラグ） |
| 複数単位が写っている | 単位ごとにクロップして候補化（重なり少・縁が見えるものを優先して列挙） |
| 候補が足りない／多すぎ | 上限を置く（目安 3〜8）。人が手で追加クロップしない |

**UI（必須）**

- 元の種（全体）＋候補サムネを同じページに出す  
- 選択は **ラジオ（単一）**。レ点（複数可）にしない（判定種は常に1つ）  
- 「この候補で進む」で `judgeSeed` を保存し、②合否へ進む  
- 画像はクリック拡大できること  

**禁止**

- 複数片のまま「どれでも近い方でPASS」とすること  
- 候補を出さず人間に自由クロップ・手描き框だけさせること（本線外）  
- 人間に型名・文案を書かせて判定単位を決めること  
- ラジオ未選択のまま合否・敢えて順位へ進むこと（1単位種の自動確定を除く）

## 4. 一片見本（同じ共通レイヤ）

C1〜C7に加え:

- 盛り工程を混ぜない。**画面は1片だけ**（山・ばら撒き・複数片を一片見本にしない）  
- 種が盛り写真なら **§3.3 で `judgeSeed` を切ってから** 添付・合否する（複数片種のまま任せない）  
- 合格したら piece_set へ。言語化の危険文も再掃除（**他商品の禁止文を足さない**）  
- MAIN/SUB盛りは§2へ渡す

## 6. 実装境界

- 共通核の同送・危険文掃除・面クロップ優先は配線済（既定ON）。  
- 一片生成（`b5_piece_set_from_truth`）もコアON時は SURFACE＋核を同送（種だけ同送は廃止）。  
- 面クロップ種は解決済み SURFACE（close 優先）。スマホマクロ／Webカメラ手撮りは同送しない。  
- 試験産物（`reinhard` 等の色転送・実験スタンプ）は SURFACE に渡さない。  
- 盛りで SURFACE＋一片があるとき SHAPE ドナーは付けない（S1・一片本体なしのときは SHAPE 残す）。  
- 品質段: `recommend_quality` は§3どおり。商品固有キーワードでは上げない。  
- **C8**: `run_effect_verify_loop`（`b5_generic_plating.py`）。1枚直列の効き確認。外側フローは②FAILでも③深堀補完へ進む。  
- **§3.2／§3.3**: `judge_seed_pick.py` / `judge_seed_pick_launch.py` で候補クロップ＋ラジオ選択。外側フローは合否前に `resolve_judge_seed` を挟む。敢えて順位の本線配線は未完。  
  - 起動例: `python judge_seed_pick_launch.py --seed （種）.jpg --fresh-port`  
  - 単一候補スキップ: `--auto-if-single` または `B5_JUDGE_SEED_SKIP_IF_SINGLE=1`
- プロファイル `food_flake` は**個別適用の一例**。ゼロベースは `B5_PLATING_PROFILE=generic`。  
- high は既定オフのまま。
