## 1. Amazon（要約）

- 素材は**透過化してから**利用 → 出力は純白背景  
- 見本の配置・重なりを転写（Gemini推奨）  
- **縦横比厳禁**: ストレッチ／縦横の比率変更は禁止（等倍スケール＋平行移動＋弱い影のみ）  
- **デザイン捏造禁止**: ラベル・蓋印字は提供画像（01ヒーロー／単体）または事実参照のみ。AIによる文字創作・描き直し禁止  
- **ヒーロー／単体タグ**: `01…` でファイル名に `ヒーロー` / `単体` があれば使い分け。無い場合は従来どおり1枚  
- **N≤4 大きさ判定**: 本体外接の**縦×横**（上部≈18%除外でスプーン除外）を同一ターゲット枠へ contain。画像全体幅揃えは使わない  
- **N≤4**: 奥行き縮小禁止。重なりは N≥5 より強めてよい  
- **処理済み移動**: 同名があれば `名前_2` / `_3`…（だめなら日時）でリネーム保存。上書きしない  

- **個数完全一致**: 販売セット数＝数えられる個体数。裏積み暗示は禁止  
- **規則性**: 縦列・横列は整列。不規則なにじり禁止  
- **動き＋画面埋め**: 縦長は斜め、低背缶は扇状・弧など（SEOサムネ）。アスペクトは維持  
- **素材**: Amazon貼付は **単体のみ**。本線は**透過PNG**（アルファ付き）。JPGは自動白抜きフォールバック  
- **実行時**: `[透過チェック] … 透過あり／無し` を標準出力・ログに表示（`inspect_alpha`）  
- **Octas**: 商品不透明ピクセル×**0.075**（標準0.05の1.5倍・N共通ロック）。hero右下キス（重なり≈10%）。傾き|θ|=**8°固定**（上部を右へ）。**N≥5**は unit 列を隠さないよう **左へスライド**（必要なら面積比フォールバック）
- **直立四隅注釈**: 素材(unit)単位で **代表1枚**のみ `_meta/upright_quad__{unitStem}.jpg`（セット数ごとには出さない）





- **事実参照**: マスタ競合／参考画像を `IMAGE_FACT` として渡し、蓋・プルタブ等の物理ディテール幻覚を抑制（デザインコピー禁止）  
- **Pillow貼付PoC**: `amazon_paste.py` / `amazon_paste_poc.py`（等倍貼付・描き直しなし）。AI経路と併用検証中  
- **縁際配置（V0・unit-only）**: **N=1 中央最大化**（heroのみ）。N=2〜5仮合格。**N=3/4 もヒーローは左下・レイヤー最前面**（unitの上）。N≥5は unit右先決（幅下限20%）。列分割: **<10→1列 / 10–19→÷2で2列 / ≥20→10+10固定＋端数は3列目以降（各列最大10）** →左余白でhero最大。  

- **縦長パターン（portrait）**: キャンバスは**正方形のまま**。素材は **`01.amazon白抜きベース` 透過PNG**。影はアルファ輪郭のみ。実装=`portrait_layout.py`／`--aspect portrait`。N≤4=扇／の字、**N≥5=hero左＋右傾け積み**。詳細は下節 **§1.1**。  

- **横長パターン（landscape）**: キャンバスは**正方形のまま**。セット組みは見本ベース（**N=1〜≥5 合格固定**）。実装=`landscape_layout.py`／`--aspect landscape`／Cメニュー③。見本=`03.amazon見本/横長画像見本`（154=N2／155=N3／156=N4／157=N5／158=N10）。詳細は **§1.2**。

- **チューニング中（draft）**: `layout_rules.json` → `amazon.tuningDraft`。占有率 inkFillMin（N=1: 0.30／N=2–3: 0.48）継続。重なり上限数値・motion/static は次段  
- 詳細は `layout_rules.json` の `amazon` 節

```text
N=3/4 概念（手前→奥）— 階段は横にも進む:
  [hero] ──→ [u1] ──→ [final]
   左+下枠   右上へ段差    上+右枠
```

#### 1.2.2 セット組み — N≥5（**合格**・見本157/158拡張）

縦長の「hero左＋右傾け積み」は**使わない**。**上hero＋下unitグリッド**。

| 項目 | ルール |
|------|--------|
| 構造 | **上: hero 1個** ＋ **下: 残り `rem=N−1` をグリッド** |
| hero大きさ（案A・採用テスト） | **左辺＝枠左／上辺＝枠上**。**右辺は枠右に接しない**（右に Octas 帯 ≈140px）。高さは縦横比ロック |
| 傾き | **すべて 0°** |
| 重なり | グリッド内は**なし**（均一 `GAP`） |
| 列数 `cols` | `rem` に対し √付近・ほぼ正方形（同点なら多列） |
| 行の並べ方 | 満列は下段へ。**余りは hero直下の上1行** |
| **半端行（重要）** | 上1行が `cols` 未満のとき、商品同士は**通常GAPで重ねない**。行全体を**中央寄せ**し、**左右の余白を広げる** |
| 満列 | hero下で水平中央 |
| Octas | hero右下キス（縦長同型）。**下枠ピンはしない**（heroが上にあるため）。unit非被覆で左スライド可 |

**Octas × hero右辺接触 — 検討案**

| 案 | 内容 | 評価 |
|----|------|------|
| **A（推奨・テスト採用）** | hero の**右辺＝枠右を廃止**。左+上のみ。右にシール帯を残し、Octas は hero 右下キス | 縦長同型のキスを維持できる。heroがやや小さくなる |
| B | hero 三辺接触維持。Octas を hero 下辺の**内側寄り**（右端から離す） | 右辺接触は守れるが、シール位置が縦長本線とずれる |
| C | hero 三辺接触維持。Octas をキャンバス右下／グリッド脇 | 見本外の新ルール。商品との関係が弱い |

  [ u3  u4  u5 ]   ← 満列3
