## 2. 流れとゴール

```text
本線
  A 店起点①–⑧
      → 洗うメーカーを決める
      → その店の取扱（query で取れた分）を C へ
  B メーカー洗い
      → C 倉庫（Keepa）
  D 品番リストへ転記 → 機械で絞る
  E 見積もり提案書を人にメール → 見積可のメーカーだけ
  F 見積作成（メーカーまとめ）→ 依頼メール → 送信
  G 返信確認 → 見積回答取得
  H 原価を表へ → 利益計算
  I 仕入れ提案書を人にメール → 承認品番だけ
  J 発注書 → 発注メール → 送信

分岐 A′（メーカー問屋からの仕入提案、仕入れ選定）
  書類で品を特定 → 検討する品を選ぶ
      ├ C に既にある → 同じ門
      └ 無い → 商品名／JAN → SP-API → Keepa → C → 同じ門
  D リストへ載せる
  単価あり → E・F・G を飛ばして H
  単価なし → 本線 E から
  その後 I → J
```

| 記号 | ゴール（できたと言える状態） |
|------|------------------------------|
| **A** | 店から「洗うメーカー」まで辿れる。取扱の取得結果が倉庫に残る（全SKUではない） |
| **B** | 指定メーカーの品が、門の結果付きで候補になる |
| **C** | 同じ Keepa／取扱を、洗い・品番リスト・出品が90日内使い回せる |
| **D** | 倉庫からリストへ載る。機械が候補を絞る。既存の式は流用し、必要な範囲で最適化する |
| **E** | 見積もり提案書が人に届き、見積可のメーカーだけ F に進む |
| **F** | 可とされたメーカー単位で依頼が作られ、相手に届く（人送信可） |
| **G** | どのメーカーのどの品がいくらか、機械が拾える |
| **H** | 表に原価が入り、利益が見える |
| **I** | 仕入れ提案書が人に届き、表に承認が残り、承認品番だけ J に進む |
| **J** | 承認分の発注が相手に届く（人送信可） |
| **A′** | 提案品が同じ門・同じリストに乗る。倉庫に無ければ SP-API→Keepa。単価ありなら H へ |

## 5. 受け渡し契約（2026-08-16 ロック）

各フローは **入力 → 機械 → 人（任意）→ 出力**。列字母は実装時。

| フロー | 入力 | 機械 | 人 | 次へ渡すもの |
|--------|------|------|----|----------------|
| **A** | sellerId／店の候補 | `/query` page0 で total。≤1000 は続行可。食品比で優先 | total>1000 のときメール判断。⑧は当面人 | メーカー名。query で取れた ASIN（保留店は除く） |
| **B** | メーカー名 | Catalog タイトル含有 → Keepa → 門 | 第2語はマスタにあれば機械 | 門付き ASIN → C と ①候補 |
| **C** | Keepa／query 結果 | 90日保管。csv[]・offers 本線なし | なし | フル行を D・出品が読む |
| **D** | C と ①候補の門 | リストへ JOIN。見積候補／見送りフラグ | 式の最終確認は後で可 | **見積候補**行 → E（A′ 単価ありなら H） |
| **E** | D の見積候補（メーカー束） | 見積もり提案書を人へメール | **見積可／不可**（表に残す） | 可のメーカー → F |
| **F** | 可メーカー＋品 | 依頼文（メーカー1通） | 送信（人でも可） | 送信済み印 |
| **G** | 返信メール | 単価・MOQ 等 | 取れない行の手直し | 見積単価 → H |
| **H** | 見積単価または A′ の提案単価 | 表へ原価、利益式 | 見るだけ | 利益付き行 → I |
| **I** | H の行 | 仕入れ提案書を人へメール | **仕入可／不可** | 承認品番 → J |
| **J** | 承認品番 | 発注書・メール | 送信（人でも可） | 発注済み |
| **A′** | 問屋提案書類 | 品特定。無ければ SP-API→Keepa→門 | **どの品を検討するか** | 単価あり→ D→H。なし→ D→E |

進め方: 契約は一連。厚い実装要件は A（巨大店）と D（フラグ）。E は承認の形だけ先にロック。F 以降のひな形・OCR は後。

### 5.1 A（巨大店・query）

| 項目 | 正 |
|------|-----|
| 取扱 | Keepa `GET /query`。まず page0 で **total** |
| total ≤ 1000 | 機械が続行してよい。全 ASIN をすぐ product／Keepa しない |
| **total > 1000** | query を続けない。**人にメール**して判断を待つ（する／しない／page0 のみ 等）。当該店は保留。自動除外の固定閾値 500 は使わない |
| メール | sellerId、店名（取れれば）、total、食品 root 比（分かれば）、推奨 |
| 倉庫 | query の ASIN は台帳側。Keepaフルへは門に使う分 |
| 食品 | 食品を扱う店を優先。食品 0% は洗うメーカーの本線にしない |
| ⑧ | 第1版は人または固定。週次トリガーは後 |
| 聖域 | storefront 全 ASIN ダンプ禁止。`offers[]` 本線なし |

検収の目安: モリタ total=30 → 続行。AN1 total≈97843 → メールして停止。

### 5.2 D（転記＋機械絞込）

| 項目 | 正 |
|------|-----|
| 門（価格・順位・冷凍生等） | **①候補**。プロファイル表 |
| 品番リスト | Keepaフル JOIN。**行は消さない** |
| 機械絞込 | **見積候補／見送り**フラグ（名称は実装時）。見送り理由を残す |
| 見送りの中身 | 門落ち・巨大店保留・メーカー未洗い・人の見積不可などの **状態の転写**。粗利では見送りにしない |
| 式 | 利益式などは **上書きしない**。最適化は別承認 |
| 原本 | 調査原本は触らない |
| E へ | 見積候補だけをメーカー単位に束ねる |

### 5.3 E（承認の形だけ。実装は後）

| 項目 | 正 |
|------|-----|
| 表 | メーカー（または行）に **見積可／不可** |
| メール | 見積もり提案書を人へ。メーカー束・通過件数・リストへのリンク（詳細は実装時） |
| 問屋への依頼送信 | F（未）。聖域の自動送信に触れない |
| 不可 | F に進まない |

### 5.4 倉庫 Keepa からセラー台帳へ（仕様ロック・実装は別承認）

**きっかけ**: 食べるおだし B09LD4YFF5 は倉庫にあっても BuyBox 空・出品一覧なし。店起点の補充ができなかった。

| 項目 | 正 |
|------|-----|
| 書く先 | 競合DB **セラー** だけ。**仕入検討品番リストには書かない**。①候補の sellerId は任意（店巡回用。リストではない） |
| 本線の Keepa | いまどおり `history=0&stats=90`。**offers を本線に載せない**（全品の出品一覧一括は禁止） |
| 取れるとき | 応答の `buyBoxSellerId` → Keepaフル「BuyBoxセラー」。空なら店は足さない（今回と同じ） |
| **書くタイミング（採用）** | **Keepaフルへ追記した直後。** そのバッチで BuyBox が新たに出た sellerId だけ、台帳に無ければ1行足す（店名は後で storefront=0）。品番リスト JOIN（D）では足さない |
| 書かないタイミング | 品番リスト、モールヒット、出品マスタ、query の全ASIN展開時 |
| 出品一覧が要るとき | 人が1 ASIN を指定したときだけ、後続で `offers`（token増）。本線のメーカー洗いには付けない |
| 次の店 | 台帳の未巡回行。total>1000 は洗わない |

実装は別承認。今は仕様のみ。
