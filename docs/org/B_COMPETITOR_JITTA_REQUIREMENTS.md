## P2 — Catalog増員並走（改訂・2026-10-31 要件ロック／P2-1・P2-2コード済）

### 0. なぜ旧案を捨てたか

旧案（仮想 role_split 厳格）: **C≥31 なら Catalog は競合、①は沈黙**。  
いまの実測では C がゲートを大きく超え、競合に Catalog 実装が無い。①を黙らせると **誰も列挙しない詰み**（仮想S5）。  
その後の①改善（案A／案E／N3／案P1落ちあと拾い）で Catalog・空振り山は①本線で回せるようになった。よって P2 は **交代ではなく増員**とする。

仮想合否: `tools/common_ss_view/_tmp_virtual_p2_revised.py` → **PASS_PROPOSE**。

### 1. 記号

| 記号 | 定義 |
|------|------|
| **U** | §P1どおり（実態未調査ユニーク） |
| **C** | Catalog待ち。製造メーカー／入口ブランドかつ規模帯が空（見積未了を含む運用定義。実装時に①の既存「Catalog待ち」判定と揃える） |

### 2. 確定ルール（本スライス）

| 項目 | 正 |
|------|-----|
| Keepa洗い | **常に①**。競合はやらない |
| ① Catalog | **Cの多寡で沈黙しない**。競合未実装でも①が続ける |
| 競合 Catalog | **実装後に増員並走**。足せるときだけ。Cゲートで①を止めない |
| 同一メーカー | Catalogは **親ロック1本**（同一親の同時禁止。別親は並走可。① N3と同思想） |
| 競合が落ちたとき | ①は継続。競合は落ちあと拾い（予約／心拍相当）で再開。人手の同メニュー連打は完成形にしない |
| Uブースト | §P1のまま独立 |
| 空振り復帰 | ①の案E（`enum_reset_pending`）を正。競合側に別の人手型を増やさない |

### 3. 禁止（本スライス）

- **C≥31 を理由に①のCatalogを止める**（旧係交代）
- 競合Catalogが合否PASSする前に①沈黙ゲートを入れること
- Keepa／自動レ点／C0／A-light を競合へ移すこと
- 人手で型・文案を増やすこと／同じメニューを件数分割で何度も押させること
