## 0. この文書の目的

- 「製造メーカー」「入口ブランド」などを **専門用語なし** で説明する。
- **巨大かどうか** では分けない（サントリー規模でも「製造メーカー」になりうる）。
- **AI／Web検索** で機械判定するときの **判断基準・参照URLの残し方** を決める。
- コード内の小さなシード（Generic 等）だけ残し、**大手名簿は持たない**。

| 置き場 | 役割 | 人が触る？ |
|--------|------|------------|

### 1.1 メーカーマスタ（調査キャッシュ）に足す列

第2クエリ語と並列。`採取元` は `official` → `gemini` → `openai` → `人手`（V1 §8 と同型）。

| 列 | 意味 |
|----|------|
| メーカー | キー（既存） |
| 第2クエリ語 | 洗い分割用（既存） |
| **実態候補** | AI／公式の結論（確定前） |
| **実態信頼度** | `high` / `medium` / `low` |
| **実態採取元** | `official` / `gemini` / `openai` / `人手` |
| **実態根拠URL** | 人が開く根拠（会社概要・IR 等。複数は `\|`） |
| **実態取得日時** | 日本時間（`+09:00`。旧UTC混在可） |
| **実態再採取しない** | TRUE なら再調査しない |
| **業種** | 一般的な業種分類（東証・日経業種、会社HPの事業内容ベース）。取れないときは §4.3.1 |
| **Amazonルートカテゴリ** | セラー台帳と同じ **ルート列名**（`食品・飲料・お酒`・`ドラッグストア`・`家電&カメラ` 等）。複数は `\|` 区切り |
| **AmazonBrowse棚** | ルート内の **Browse 棚名**（例: `調味料`・`お茶漬け・ふりかけ`）。複数は `\|` 区切り |
| **入口語候補** | 入口ブランド型のとき Catalog に使う語（例: `AGF`） |
| **判定メモ** | AI 一行理由 |
| 採取元・公式URL・取得日時・再採取しない・メモ | 第2語用（既存） |

### 1.2 メーカーサマリ（ミラー列）

人が一覧で判断しやすいよう、マスタの要約を **末尾にコピー**（JOIN キー＝メーカー名）。

**法人格ゆれ（Phase A）**: 表示名は行ごとに残すが、突合キーは `株式会社`／`(株)` 等を除いた値（`normalize_maker_key`）。同一キーの別名行には実態・ミラーをまとめて書く。行の物理削除はしない。

| ミラー列 | 元 |
|----------|-----|
| 実態採取元 | マスタ.実態採取元 |
| 実態信頼度 | マスタ.実態信頼度 |
| 実態根拠URL | マスタ.実態根拠URL |
| 業種 | マスタ.業種 |
| Amazonルートカテゴリ | マスタ.Amazonルートカテゴリ |
| AmazonBrowse棚 | マスタ.AmazonBrowse棚 |

**確定ルール**: サマリ.`実態信頼度=high` が付いた行のみ AI 確定済み（シードの実態だけではスキップしない）。high なら候補→サマリ.実態へ自動反映。`medium` 以下は **要確認のまま**＋ミラーだけ埋める。

### 1.1 メーカーマスタ B–F 列（第2語キャッシュ）

| 列 | 名前 | 用途 |
|----|------|------|
| B | 第2クエリ語 | 洗い完走で Catalog >500 のとき分割Bの語（`\|` 区切り）。**削除しない** |
| C | 採取元 | 第2語の取得元（official / gemini 等） |
| D | 公式URL | 根拠URL |
| E | 取得日時 | 第2語採取日時 |
| F | 再採取しない | TRUE なら第2語を再取得しない |

G–Q 列は実態AIキャッシュ（`実態候補`〜`判定メモ`）。旧データクリアはメニュー「マスタ旧データクリア（再調査4社）」→ 実態AI。

## 2. 四つの仕分け（平易な説明）

Amazon で仕入れ候補を洗う前に、「この名前の相手とどう付き合うか」を四つに分ける。

| 仕分け（実態） | ひとことで | 洗い（商品探し） | 例 |
|----------------|------------|------------------|-----|
| **製造メーカー** | 食品を **自分で作って** 卸に載りうる会社 | **する**。Amazon 検索は **会社名そのまま** | 尾西食品、森永製菓、アサヒ飲料、**永谷園** |
| **入口ブランド** | 会社はあるが、棚では **別の名前** で売られている | **する**。検索は **棚の名前（入口語）** | 味の素（棚では AGF・ほんだし等） |
| **非仕入先** | うちの仕入れ対象ではない | **しない** | Generic、コストコ（小売）、扶桑社（出版） |
| **要確認** | AI調査後、卸可否が **人の判断待ち** | **しない**（人が決めるまで） | あさくま（外食が本業で卸不明） |
| **未調査** | **AI実態調査がまだ**（行追加直後のプレースホルダ） | **しない** | 新規ヒットでサマリ行ができた直後 |

**入口推奨**（サマリの別列）は「Amazon で何語で探すか」のメモ。

| 実態 | 入口推奨 | 探し方 |
|------|----------|--------|
| 製造メーカー | メーカー | 「永谷園」「尾西食品」で検索 |
| 入口ブランド | ブランド | 「AGF」「S&B」など棚の名前で検索 |
| 非仕入先 |  non仕入先 | 探さない |
| 要確認 | 要確認 | 探さない（実態ck に Amazon 検索URL） |
| 未調査 | 未調査 | AI調査前。探さない |

**未調査の判定（コード）**: サマリ.`実態信頼度` が空 かつ（`実態=未調査` または レガシー `実態=要確認`）。AI調査後は `要確認`／`製造メーカー` 等へ。移行はメニュー **99→16. 実態ラベル移行**。

## 3. 「製造メーカー」と「入口ブランド」の見分け方（核心）

### 3.1 巨大かどうかは関係ない

- サントリー・アサヒ・森永も **製造メーカー**。
- 「ブランド」に入るのは **小さいから** ではない。

### 3.2 発売元が商社でも製造メーカーになりうる

永谷園の例（[会社概要](https://www.nagatanien.co.jp/company/profile.html)）:

- 事業内容: **お茶づけ・ふりかけ・即席みそ汁等の製造販売**
- 発売元に三菱商事とあるが、**製造は永谷園側**
- ホールディング: [永谷園HD](https://www.nagatanien-hd.co.jp/) がグループ

→ **仕分けは「製造メーカー」**（発売元表記だけでブランド扱いにしない）。

### 3.3 判断の中心質問（AI 用プロンプトの芯）

> **お客さんが Amazon で商品を探すとき、パッケージに載っている名前は「会社名そのもの」か、それとも「別の商品ブランド名」か？**

| パターン | 答え | 仕分け | 検索語 |
|--------|------|--------|--------|
| 永谷園のお茶づけ | パッケージも **永谷園** | 製造メーカー | 永谷園 |
| 味の素のコーヒー | パッケージは **AGF**（味の素ではない） | 入口ブランド（親=味の素） | AGF |
| ペヤング型 | 会社はまるか食品、棚は **ペヤング** | 入口ブランド | ペヤング |

**「世の中にその名前だけで認知されるか」**＝棚で単独のブランド名として通じるか、でよい。

### 3.4 味の素と AGF（入口ブランドの典型）

[味の素公式](https://www.ajinomoto.co.jp/) より:

- 親会社は味の素グループ
- 商品・ブランドサイトは **AGF・ほんだし・Cook Do・鍋キューブ・クノール** など多数
- Amazon で「味の素」と検索しても **コーヒーは AGF 名でヒット** しやすい

→ サマリの **メーカー列は「味の素」**（親名で1行）  
→ **実態=入口ブランド**、**入口推奨=ブランド**、**入口語候補=AGF**（マスタ）

### 3.5 永谷園は「製造メーカー」が正

[会社概要](https://www.nagatanien.co.jp/company/profile.html) では自社製造販売。サマリに古い `入口ブランド` が残っていても **ミラー high が無ければ AI が再調査** する（手修正・辞書不要）。

### 3.6 あさくま（要確認の典型）

[株式会社あさくま 会社情報](https://www.asakuma.co.jp/company.html)・有価証券報告書より:

- **本業**: ステーキレストラン（飲食・FC）
- ソース等の開発・「あさくまファーム」通販はあるが、**卸売り・製造販売が主事業かは HP 上一覧で断定しにくい**
- Amazon ヒットの「あさくま」がレストラン由来商品か別法人かも要確認

→ 機械では **要確認**（業種=外食・飲食、Amazonルート=食品・飲料・お酒、Browse棚=調味料・ソース 程度まで）  
→ 人が EDINET・商品ページ・卸有無を見て **製造メーカー** か **非仕入先** を確定  
→ 根拠URL例: `https://www.asakuma.co.jp/company.html`、EDINET

## 4. AI／Web 判定の手順（機械側）

辞書の代わりに、**1メーカー1回** 調べてマスタに保存。

```
1. サマリに「実態」が人入力済み → 触らない
2. マスタにキャッシュあり & 再採取しない → それを使う
3. 公式サイト（会社概要・IR）を優先
4. 足りなければ Gemini google_search 1回（会社名 + 事業内容 + 卸売）
5. 失敗時のみ OpenAI（任意）
6. 結果をマスタに書き、ミラーをサマリへ
7. 信頼度 high のみサマリ.実態を自動確定
```

### 4.1 AI に渡す入力

- メーカー名（Keepa の manufacturer / brand 由来）
- 当社スコープ: **食品・飲料の仕入れが主**。外食・小売・化粧品単体は原則対象外
- （あれば）そのメーカーを拾った **店の食品比率**
- （あれば）Amazon 上の表示ブランド名

### 4.2 AI に出させる出力（JSON）

```json
{
  "jitta_candidate": "製造メーカー",
  "entry_preferred": "メーカー",
  "entry_needle": "",
  "confidence": "high",
  "source": "official",
  "evidence_urls": ["https://www.nagatanien.co.jp/company/profile.html"],
  "gyoshu": "即席食品・中食（食品製造）",
  "gyoshu_source": "official",
  "amazon_root_categories": "食品・飲料・お酒",
  "amazon_browse_shelves": "お茶漬け・ふりかけ|即席みそ汁|惣菜・食材・調味料",
  "reason": "会社概要に製造販売と明記。棚名も永谷園。"
}
```

### 4.3 業種と Amazon カテゴリ（分ける）

**3列**。yes/no では表さない。

| 列 | 意味 | 永谷園 | 味の素 | FANCL（将来） |
|----|------|--------|--------|----------------|
| **業種** | 会社が何の業界か | 即席食品・中食（食品製造） | 調味料・加工食品 | 化粧品 |
| **Amazonルートカテゴリ** | Amazon の **大分類**（セラー台帳列名と同じ） | 食品・飲料・お酒 | 食品・飲料・お酒 | ビューティー \| ドラッグストア |
| **AmazonBrowse棚** | ルート内の **細かい棚** | お茶漬け・ふりかけ \| 即席みそ汁 等 | 調味料 \| コーヒー・紅茶 等 | スキンケア \| サプリメント 等 |

- **ルートは単独でも必須**（食品以外の仕入れ拡張に備える）。Browse 棚だけでは足りない。
- ルートの語彙は `schema.py` の `AMAZON_SELLER_CAT_COLS`（セラー台帳と揃える）。
- Browse 棚は Amazon の商品分類に合わせた自由記述（複数 `\|`）。

#### 4.3.1 業種が取れないとき

東証・日経・会社HPの事業内容が **無い／薄い** ときの順序:

| 順 | ソース | 業種列 | 信頼度 |
|----|--------|--------|--------|
| 1 | 東証・日経の業種区分 | そのまま記載 | high |
| 2 | 会社HP・IRの「事業内容」 | そのまま記載 | high |
| 3 | EDINET／有報 | そのまま記載 | high〜medium |
| 4 | Web検索（Gemini 等） | `○○（推定）` と付記 | medium |
| 5 | 当社の Amazon ヒット商品（Keepa categoryTree） | `○○（推定）` | medium〜low |
| 6 | すべて無し | **`不明`** | low。実態は **要確認** のまま |

- 業種が `不明` でも **実態の high 自動確定は別判定**（実態と業種は独立）。
- 人が後から業種を直せばミラーに反映。`実態再採取しない` で再調査を止められる。

#### 4.3.2 Amazon カテゴリが取れないとき

| 状況 | Amazonルート | AmazonBrowse棚 |
|------|--------------|----------------|
| 非仕入先（小売・出版） | 空でよい | 空 |
| 要確認・情報不足 | 空 or ヒット商品から推定 | 空 or 推定（信頼度 low） |
| 複数ルートにまたがる | `\|` で併記（例: 食品・飲料・お酒\|ドラッグストア） | ルートごとに棚を `\|` で列挙 |

C3 自動選定の「食品0%店のみ由来メーカー除外」と併用。ルートに `食品・飲料・お酒` が無くても、将来のドラッグストア仕入れ用に **ルート列は残す**。

## 6. 人の作業（変わらない）

- **要確認** だけ、サマリの `実態` を手で直す（`実態ck` の Amazon 検索も可）。
- 確定したら **実態再採取しない** を ON にできる。
- AI が high で確定した行も、間違いがあれば人が上書き（上書き優先）。
