## 0. 目的

- PC が壊れても、**スプシの断面**を Google 上から戻せる
- 人が毎日押さない（**完全自動**）
- プロジェクトを1本にまとめない
- **壊れた断面は控えにしない**（保存せず人間へ報告）

コード（GAS／docs）のウェブ控えは **GitHub**（本ジョブの外）。スプシ丸ごとを GitHub に載せない。

## 3. いつ・何をするか

| 項目 | 正 |
|------|-----|
| 時刻 | 毎朝 **8:00**（Asia/Tokyo） |
| 更新あり | **昨日 8:00 〜 今日 8:00** に最終更新があった（カレンダー日の 0:00〜8:00 だけではない） |
| 更新なし | コピーしない。**成功扱い** |
| 破損・消失疑い | **コピーしない**。人間へ報告（**ログ必須**＋ Property の宛先があればメール） |
| 成功時 | `99.バックアップ / （PJ名）/` へ `makeCopy`（名前に日付） |
| 掃除 | 残日数を超えた古いコピーをゴミ箱へ（**正本は消さない**） |
| 人手 | 毎日は押さない。初回 Property／フォルダ／トリガー確認と、報告を受けたあとの対応だけ |

### 3.1 破損・消失疑い（機械判定の目安）

次のいずれかならコピーせず報告する。

- 直前の良品コピーより **ファイルサイズが急縮小**（目安: 良品の 80% 未満。Property で調整可）
- 必須シートが無い／開けない
- （コード側・別経路）GAS ソースが欠落・途中切れなど、明らかに壊れている

疑わしいときは **残さない**（壊れた断面を「控え」にしない）。

## 4. 置き場と名前

```text
99.バックアップ/
  ├─ 出品/
  ├─ 仕入れ検討①/
  ├─ （次段）広告/
  ├─ （次段）在庫管理/
  └─ …
```

- 親フォルダ名は **`99.バックアップ`**（固定）
- 配下は **プロジェクト別フォルダ**
- コピー名の例: `出品_backup_YYYYMMDD`／`①調査_backup_YYYYMMDD`／`競合DB_backup_YYYYMMDD`
- 残日数: 既定 **14日**（Property で変更可）

---

## 5. 自動化

- 各プロジェクトの **既存 GAS** にバックアップ関数＋毎日 8:00 トリガー
- 出品で型を固めてから①へ載せる（共通化してよいが **clasp プロジェクトは混ぜない**）
- ログ: 取得／スキップ（更新なし）／スキップ（破損疑い）／失敗理由
- 切戻し: Script Property で OFF（関数先頭で return）

---

## 6. 人間が初回だけやること

1. Drive に `99.バックアップ` と PJ 別サブフォルダを用意（または既存を指定）
2. Script Properties（フォルダ ID・残日数・ON・急縮小閾値）
3. `clasp push` 後、8:00 トリガーを確認
4. 以降は触らない。報告が来たら中身を見て正本／GAS を直す

手順の正: [PROJECT_DAILY_BACKUP_HUMAN_RUN.md](PROJECT_DAILY_BACKUP_HUMAN_RUN.md)

## 7. 検収

| ID | 合格条件 |
|----|----------|
| T1 | 昨日8時〜今日8時に更新した対象が、8時後に `99.バックアップ/（PJ）/` に当日名で存在する |
| T2 | その窓に更新が無い日は、新規コピーが増えない |
| T3 | 残日数超の古いコピーが減る（正本は残る） |
| T4 | Property OFF でコピーが増えない |
| T5 | 急縮小／必須シート欠落の模擬で、**コピーされず報告が出る** |
| T6 | （①）競合DBコピー失敗時、理由がログに残り正本は消えない |

## 8. リスクと割り切り

| リスク | 第1版の扱い |
|--------|-------------|
| 競合DB（Keepaフル肥大）のコピーが重い | ①で実施。失敗はログ＋報告。分割コピーは第1版ではやらない |
| 8時にちょうど洗い中 | 原則8時のまま。連続失敗なら時刻ずらしを検討 |
| Drive 容量 | 残日数14で抑える |
| Git 未 push | **G1 で毎日 main へ自動 commit/push**（下記 §9）。失敗はログ必須 |

## 9. コード控え（GitHub G1 ＋ ローカル G3）

**確定方針（2026-11-15）**: **G1＋G3**。GitHub が正、ローカル snapshot が保険。

### 9.1 G1 — GitHub 毎日 `main` へ

- remote（GitHub）をコード・docs のウェブ控えの**正**とする
- **毎朝 8:05（Asia/Tokyo）** に Windows タスク等で自動: 変更があれば `git add`（`.gitignore` 遵守）→ `git commit`（定型メッセージ）→ `git push origin main`
- 秘密・巨大バイナリ・スプシ丸ごとは載せない（`.gitignore`）
- push／commit 失敗時はログ必須（任意でメール）。人が毎日押さない
- 作業の区切り・セッション終了時も、エージェント／人が push 済みかを確認してよい（自動の補完）

### 9.2 G3 — 全 clasp ルートのローカル snapshot

- 出品ルートの `tools/backup_gas_snapshot.ps1` ＋タスク `\gas-project-gas-snapshot`（毎朝8時前後）を**保険**とする
- **全 clasp ルート**（出品・①・広告・在庫・競合Jitta・税務）へ同型を広げる（壊れた断面は拒否・良品を残す）
- ローカルは必須の「正」ではないが、Git 障害時の復帰用
