## 1. ゴール一文

本線 **C**（`★画像AIマッチング(操作用)`＝**案α**）で、数量セット違いの **子SKUごとに Amazon MAIN（白抜き）を人間が紐付け**、実行により Drive `04\02` へ `{sellerSku}.MAIN.jpg` を**コピー出力**する。サブは楽天流用（REUSE）または単独（ONLY・sheet で PT 紐付け）。  
**永続の正はマスタ列**。マッチング sheet は作業面（再生成後はマスタから復元）。Drive `02` は **出口**。白抜き**候補**は楽天ソースと分けた **Amazon 用フォルダ**。  
楽天 R-Cabinet／Yahoo マッチング本体は壊さない。

## 3. 確定方針

| 項目 | 方針 |
|------|------|
| **MAIN 紐付け** | 人間がマッチング sheet の **子SKU行**で白抜きを当てる |
| **永続の正** | **マスタ列**（Amazon MAIN 参照等）。sheet は作業面 |
| **再生成** | `generateAiImageMatrix` の `clear()` 後、**マスタ→sheet へ復元** |
| **MAIN 出口** | Drive `02\{sellerSku}.MAIN.jpg`（**コピー**。必須） |
| **白抜き候補** | **Amazon 用ソースフォルダ**（楽天 `DRIVE_IMAGE_SOURCE_FOLDER_ID` と分離） |
| サブ `REUSE_RAKUTEN` | マスタ「楽天サブ画像1〜n」→ PT01…（中身再判定なし）。正本はマスタ列優先 |
| サブ `AMAZON_ONLY` | **マッチング sheet で PT 紐付け**が本線。`02` 手置きは例外・復旧のみ |
| フォールバック | REUSE だが楽天サブ0枚 → AMAZON_ONLY（ログ） |
| モード粒度 | **子SKU単位を優先可能**（親一括のみでは不足しうる） |
| ファイル名キー | **`sellerSku`**（通常＝子SKU。異なる場合は実装承認で1行固定） |
| `02` 配置 | 当面 **フラット優先**（既存 `getFilesByName` との整合）。サブフォルダ任意なら探索契約を実装時定義 |
| UI 本線 | **案α**。Amazon専用 sheet（β）は不採用 |
| SC | 当面手 ZIP。T3・εは別ゲート |
| 将来 | 同一白抜き→`楽天白背景画像`（別チケット。既存自動上書きと衝突しうるため注記） |

参照: POC §2.1（U2上書きあり）、D要件 §7。多数決＋社長回答 2026-07-25。

## 3.1 層の分離（重要）

```text
【候補】Amazon用ソースフォルダ（白抜き置き場・楽天と分離）
    ↓ マッチング sheet に候補表示
【作業】sheet・子SKU行で人間が MAIN（＋ONLY時は PT）を当てる
    ↓ マスタ列へ永続化
【永続】マスタ列＝正。再生成後はここから sheet 復元
    ↓ 「Drive 02 へ出力」（コピー・楽天アップと別ボタン）
【出口】Drive 02 / {sellerSku}.MAIN.jpg （＋ PT）
    → D×Amazon・手ZIP・将来T3
```

## 3.2 既存マトリクス制約（実装必須・三点採用）

現行 `コード.js` 前提（実装承認時に再確認）:

| 制約 | 要件上の扱い |
|------|----------------|
| アップロードが **3行目以降・おおむね1〜25列**のみ読む | Amazon MAIN／PT 枠は **その範囲外**に置き、楽天1〜25列読みを壊さない |
| 候補枠が広い列帯を使用 | Amazon 枠の物理列は候補帯と衝突しない位置（例: 候補の右）を実装承認で固定 |
| `generateAiImageMatrix` が sheet を `clear()` して再生成 | **マスタ永続＋再生成後復元**が必須（§3） |
| 楽天経路は実ファイル `setName`／archive | `02` 出力は **コピー**。同名時は上書きルールを実装承認で固定 |

## 4. 命名・配置（正・出口）

```text
Drive 02（Folder ID 既定: 1T6_E6T-qd9whSF8Re8lyRVB2n-P4BM84）
  {sellerSku}.MAIN.jpg   … 必須（当面フラット）
  {sellerSku}.PT01.jpg   … ONLY時など任意
```

- サブフォルダ `{subBatchId|親SKU}/` は任意。使うなら U2-2 で再帰／直下の探索を契約する  
- R2 オブジェクトキーはファイル名と同一（T2 既存）

## 5. C UI（案α）— 人間が触ること

| # | 項目 | メモ |
|---|------|------|
| 1 | 対象行 | 出品CK親＋子行（セット違い＝別行） |
| 2 | Amazon MAIN 枠 | 子SKU行ごと（楽天メイン枠と分離・§3.2の列制約遵守） |
| 3 | モード | 子SKU単位を優先可能。REUSE／ONLY |
| 4 | ONLY 時の PT 枠 | **sheet 本線** |
| 5 | 「Drive 02 へ出力」 | 楽天 R-Cabinet アップと **別ボタン**。コピー出力 |

**人間の手順（MAIN）**

1. 白抜きを **Amazon 用ソースフォルダ**へ置く  
2. マッチング sheet で子SKU行に MAIN を当てる（必要なら ONLY で PT）  
3. マスタへ永続化（または出力時に同時）  
4. `02` へコピー出力  
5. 誤りは sheet／マスタを直して再出力。再生成後はマスタから sheet 復元を確認  

**非目標（U2 本線）**: ε、マッチング精度全面刷新、Yahoo 専用廃止。
