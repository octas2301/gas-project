## 1. ゴール一文

本線 **C** で Amazon 向け画像を揃え、Drive `04\02` に `{SKU}.MAIN.jpg`（必須）と必要なら `{SKU}.PT0n.jpg` が載る状態にし、**D×Amazon の画像ゲート**が人間手置きだけに依存しにくくする。  
楽天 R-Cabinet／Yahoo 画像マッチング本体は壊さない（案α＝拡張）。

## 3. 確定方針（親文書から継承）

| 項目 | 方針 |
|------|------|
| MAIN | **常に** Amazon 白抜き → `04\02\{SKU}.MAIN.jpg` |
| サブ `REUSE_RAKUTEN` | 楽天／Yahoo 併売時。楽天サブ画像1〜n（または `03\02`）→ **PT01…へ番号マップ**（中身判定なし） |
| サブ `AMAZON_ONLY` | Amazon のみ。`04\02\{SKU}.PT0n.jpg` |
| フォールバック | REUSE だが楽天サブ0枚 → AMAZON_ONLY（ログ） |
| UI | **案α**: 既存「画像AIマッチング(操作用)」等を拡張 |
| 画像投入の正（SC） | 当面 **手 ZIP**（T3は別ゲート） |

参照: POC §2.1、D要件 §7。

## 4. 命名・配置（正）

```text
Drive 02（Folder ID 既定: 1T6_E6T-qd9whSF8Re8lyRVB2n-P4BM84）
  [{subBatchId|親SKU}/]   … 任意サブフォルダ
    {sellerSku}.MAIN.jpg   … 必須
    {sellerSku}.PT01.jpg   … 任意
    {sellerSku}.PT02.jpg   …
```

- `sellerSku` = マスタの出品用 SKU（親／子の運用は Lv4 に合わせる。詳細は実装承認時に列名固定）  
- R2 オブジェクトキーはファイル名と同一（T2 既存）

## 5. C UI（案α）— 人間が触る最小

| # | 項目 | メモ |
|---|------|------|
| 1 | 対象行（出品CK／承認① amazon 親など） | 既存 C の対象選定を流用できるなら流用 |
| 2 | モード: `REUSE_RAKUTEN` / `AMAZON_ONLY` | 親単位または SKU 単位。マスタ列 or 実行時指定 |
| 3 | MAIN ソース確認（白抜きが `02` にある／これから置く） | 自動生成は本 U2 では必須にしない |
| 4 | サブ一覧プレビュー（REUSE時は楽天サブ列） | 番号→PT0n の対応を表示 |
| 5 | 「Drive 02 へ配置／コピー」実行 | 実装時。楽天アップ本体とは別ボタン推奨 |

**非目標（U2）**: マッチング精度の全面刷新、Yahoo 専用マッチングの廃止。
