## 1. ゴール一文

本線 **C**（`★画像AIマッチング(操作用)`＝**案α**）で、数量セット違いの **子SKUごとに Amazon MAIN（白抜き）を人間が紐付け**、実行により Drive `04\02` へ `{子SKU}.MAIN.jpg` を出力する。サブは楽天流用（REUSE）または単独（ONLY）。  
Drive `02` は **紐付け結果の置き場**であり、フォルダ内でセット数を見て当てる作業面ではない。  
楽天 R-Cabinet／Yahoo マッチング本体は壊さない。

## 3. 確定方針

| 項目 | 方針 |
|------|------|
| **MAIN 紐付け（誰・どこ）** | **人間**が **`★画像AIマッチング(操作用)`（案α）** の **子SKU行**で、数量セットごとに白抜きを当てる（楽天メインと同型の作業感） |
| **MAIN 出口** | 実行後 → Drive `02\{子SKU}.MAIN.jpg`（必須）。`02` は出力先 |
| サブ `REUSE_RAKUTEN` | 併売時。マスタ「楽天サブ画像1〜n」→ PT01…（中身再判定なし） |
| サブ `AMAZON_ONLY` | 楽天サブ無し／Amazonのみ。マッチング sheet または `02` の PT（実装承認で固定） |
| フォールバック | REUSE だが楽天サブ0枚 → AMAZON_ONLY（ログ） |
| UI 本線 | **案α**（既存 sheet 拡張）。Amazon専用 sheet（β）は採用しない |
| 画像投入の正（SC） | 当面 **手 ZIP**（T3は別ゲート） |
| 将来（Amazon落ち着き後） | 同一白抜きをマスタ **`楽天白背景画像`** にも載せる（別チケット） |

参照: POC §2.1、D要件 §7。社長決定 2026-07-25: 本線α／εバックログ。

## 3.1 層の分離（重要）

```text
【紐付け作業】マッチング sheet（案α）・子SKU行
    人間が候補を見て MAIN（白抜き）をその行に入れる
        ↓ 実行（U2-1/U2-2）
【出口】Drive 02 / {子SKU}.MAIN.jpg
    D×Amazon・手ZIP・将来T3 が参照
```

「`02` に正しいファイル名がある」＝紐付け**結果**。  
セット数を見ながら当てる行為は **sheet 上**で行う（フォルダ内探索は本線にしない）。

## 4. 命名・配置（正・出口）

```text
Drive 02（Folder ID 既定: 1T6_E6T-qd9whSF8Re8lyRVB2n-P4BM84）
```

## 5. C UI（案α）— 人間が触ること

| # | 項目 | メモ |
|---|------|------|
| 1 | 対象行 | 既存どおり出品CK親＋子行（セット違い＝別行） |
| 2 | **Amazon MAIN 枠**（新規） | 子SKU行ごとに白抜きを紐付け（楽天メイン枠と分離） |
| 3 | モード REUSE / ONLY | 親単位または実行時。サブの出所 |
| 4 | サブ | REUSE＝楽天サブ→PT プレビュー。ONLY＝sheet または手置き（実装時） |
| 5 | 「Drive 02 へ出力」 | 楽天 R-Cabinet アップとは **別ボタン**推奨。MAIN→`{子SKU}.MAIN.jpg` |

**人間の手順（MAIN）**

1. マッチング sheet で子SKU（セット数違い）行を見る  
2. 各行に Amazon 用白抜き MAIN を当てる  
3. 02 出力を実行  
4. 誤りだけ sheet／再出力で直す  

**非目標（U2 本線）**: マッチング精度の全面刷新、Yahoo 専用マッチング廃止、εの自動当て。
