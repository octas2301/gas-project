### 0.1 画像作成前 — 文案構造の合格文（仮想テストの正）

**目的**: 画像生成に渡す前に、要素が役割ごとに分かれていること。仮想ゲートで欠陥を見分けたあと GAS に配線する（S1〜S9＝2026-10-10 配線済。要 clasp・検収）。

**課題の追加**: 検収で新しい課題が出たら、**この節の表に合格文を1行足す**（必要なら仮想fixtureも足す）。コード改修は、足した合格文の仮想テストが通ってから。沈黙は承認にしない。

| ID | 課題 | 合格文（すべて満たす） | 不合格の例 |
|----|------|------------------------|------------|
| S1 | ミックスなのに単構成指定 | ミックス（セット構成1が空でない）の各案で、キャッチ／短縮／セールス小が**一方の構成・区別語だけを主役**にしていない。材料にある構成の特徴を**両方**読める（交互・並記のいずれでも可。魚・チーズ・味など種別を問わない）。単品分岐ではこの行は適用しない | 検証例: 構成Aだけ書く／片袋だけが目立つ文言 |
| S2 | キャッチとセールスの役割 | **全案**に (a) キャッチ（大）と (b) セールス小が分かれて存在する。キャッチ＝手を止めクリックさせる短いフック。セールス小＝止まったあとに読む補足（だいたい全角6〜12字目安）。同じ文を両欄に複製しない。セールス小が空の案は出さない（門で落とすか再生成） | キャッチに説明が長い／セールス欄が無い・空／役割が入れ替わっている |
| S3 | ペルソナ詳細 | 各案に短文（personaShort）と詳細（personaDetail）がある。提案画面で短文から**詳細を開いて読める**（クリック等）。詳細は画像に焼かない | 短文だけ／詳細が無い／画像プロンプトにペルソナ全文が入る |
| S4 | 焼成文の日本語（旧・画像用短縮） | **catchBurn＝catch**（別短縮しない）。全角6〜12。12字を超えたら1回書き直し、まだ超えたら焼かない。語の途中切れなし。助詞や「・」で不自然に終わらない。人が読んで**一文として成立**する。不合格なら再生成または人が直すまで焼成に使わない | 検証例: 「【用事】…て」で終わる／「〜の」／意味不明な断片／別欄へ切った画像用 |
| S5 | ペルソナが整文に効かない | キャッチ／セールス小の生成（ルール梯子・Gemini整文）は**その案のペルソナ短文・詳細の用事に沿う**。プロンプトまたは生成条件にペルソナを載せる。旧文「材料に無い相手（ペルソナ属性）を作って用事にしない」は**使わない**（ペルソナ本線と矛盾） | ペルソナ表示だけ／整文プロンプトにペルソナ無し／旧禁止文のまま |
| S6 | レ点再作成が全件作り直し | 「レ点を外した案を再作成する」は**レ点なしの案だけ**を作り直す。**訴求軸（候補または自由入力）必須**→ペルソナ〜場面をセット再生成。レ点あり（残す案）は保持。**作り直し後は外していた案にレ点を自動で戻す** | ボタン名だけレ点、実体は親の全案を再生成／ペルソナ据え置きの polish のみ／作り直し後も外したまま |
| S7 | 場面が見えない | 各案に sceneHint（場面1〜3文）があり、確認画面で**表示し、人が直せる**。画像指示に載せる前に人が読める | データだけあって画面に無い／直せない |
| S8 | 字数切りだけで壊す | catch／salesTalk は**完結文**を保つ。単なる末尾切り・助詞切りだけを合格にしない。機械の字数スライスで中途半端なら不合格（S15） | 「出せる」を切って「出」／長い文の途中で切っただけ |
| S9 | 区別語1語残しがミックスを壊す | **ミックスでは**「区別語1語だけ残してよい」を適用しない（魚種に限らない）。単品のみ、区別語1語を許す。ミックスは S1（両方の特徴）を優先 | サニタイズがミックスでも構成の片方1語だけを残す |
| S10 | 同一用事が切れている | 1案でペルソナ用事・catch・salesTalk・sceneHint・catchBurnが**同じ用事**でつながる。不一致は出さない | ペルソナとキャッチの用事が違う／場面だけ別用件 |
| S11 | 用事が後・味が先 | **商品名明示案以外**で、【見出し】または文頭が味・食感・用事ラベルだけで、用事の結果が先に読めない | 「おいしい」だけ先頭／「お茶請けに」だけの見出し |
| S12 | 場面が売文・料理連打 | sceneHintは写真指示。売文ではない。食品の用事・成果案は描く料理が案ごとにばらける。根拠不足時は捏造しない | 同じ料理の連打／料理名だけの場面／ペルソナ属性を書く |
| S13 | 入口ゲートで案を落とす | テーマ入口ゲート（数字→T1／産地→T2）で候補を落とさない。事実の門（材料に無い賞・数字・産地の捏造禁止）は残す | 「産地文が無いからT2ラベル禁止」でペルソナ案を落とす |
| S14 | 画像の字が大だけ | 画像に載せる字は **大＝catch** と **小＝salesTalk**（同文を焼く）。文字20マスに両方含める | 小を無視／長い文を切り詰めて焼く |
| S15 | 文の途中切れ・別短縮 | catch／salesTalk は完結。**別欄への短縮変換をしない**。希望字数で不成文ならフォールバック上限まで可。**Gemini生が完結していれば採用を優先**（字数切りで壊さない）。スライス合格禁止 | 「かつおとぶ」／「そのまま出」（生は「出せる」）／長い提案を切った画像用 |

### 0.3 1枚目は訴求の入れ物（2026-10-14 まとめ）

料理と場面の正はここです。これより前の、棚に置く、新しい料理を1つ作る、手渡す手元、機械は勝ちを決めない、はここから使いません。戻しは Property `B5_CAUSE_FIX=false`。

目的は、その人の得たい結果が、商品と一緒に、何の場か分かる1枚です。

材料は全文を使います。商品名、特徴キーワード、検索キーワード、Yahooキャッチ、楽天キャッチ、商品説明、箇条書きです。先頭の数件だけ、途中で切った文、は使いません。料理の候補には、公式商品ページの食べ方も使います。

得たい結果は1つです。買う人、困り、得たい結果を先に書きます。買う人は、この商品をネットの店で注文する人です。食べているだけの人、届いた箱を受け取るだけの人、は書きません。困りと得たい結果は、その注文の理由です。玄関で渡す、インターホンを押す、箱を抱えて届ける、は書きません。案ごとに、材料にある売り方か使い道を1つ起点にします。誰・得たい結果・区分のどれかが欠けた案だけ、材料つきで1回やり直します。それでも誰か得たい結果が空なら、困り・得たい結果・理由をまとめて空にし、状況にも書き直しにも入れません。書き直しには、材料と誰と起点を渡します。揃わなければ3欄とも空にします。人は、材料に年齢が無くても、売り方から想像してよいです。状況はそのあと、別の段で書きます。同じ返答で人と状況を一緒に書きません。依頼の欄は、根拠の次に困り、得たい結果、訴求理由を続けます。三つは欄へ書く前に一つの流れで考え、その文は返しません。配列を閉じる前の書き直しはしません。揃いの検査は、受け取ったあとです。配列の終わりが無い空と、3欄が揃わない空は、ログで分けます。返答の分割は全部つなぎ、思考の分割は除きます。つないでも終わりの括弧が無ければ、閉じて完結している人だけ残し、途中の最後は捨てます。終わり方、分割の数、考える分、末尾はログに残します。ペルソナの依頼は、考える段階を最小にします。このモデルはゼロにはできません。ログの `think=minimal` と `thought=` で確認します。届いた困り・得たい結果・訴求理由は、一つの話でなくても消しません。得たい結果が空の案は、これまでどおり3欄を空にします。戻しは Property `B5_KEEP_STORY=false`。キャッチが全角6〜12なら、得たい結果を前に足しません。体の効能をうたう語は、得たい結果と見出しに書きません。健康、栄養、成長、糖質、ダイエット、血圧、免疫、罪悪感、高タンパク、ヘルシーは例で、同じ種類も書きません。1回書き直して残ったら、消さずにログだけ残します。戻しは Property `B5_FLOW_FIRST=false` と `B5_JOIN_PARTIAL=false` と `B5_THINK_OFF=false`。

状況の足場は、材料に書いてある使い方を1つです。選んだ語は、材料の文にそのままあるものだけです。ペルソナは、その中から自分の話に合うものを選びます。案ごとに別の足場にします。足場が無ければ状況は空で、場面は商品そのものです。

状況の文は、その足場を、ネットで注文するその人の場が見えるところまで延ばします。その場に普通にある物は、材料にその名詞が無くても状況に書いてよいです。書いてよい物は、選んだ使い方の場の物だけです。その人の生活の、別の場の物は書きません。体への効能は状況に書きません。

並びは、買う人、困り、状況、得たい結果、訴求理由、です。得たい結果とキャッチと場面は、この状況から書きます。得たい結果を書き直すときも、状況の欄は残します。

場面は1〜3文です。商品の見本を前に置き、包材は後ろです。袋を並べて主役にしません。組み合わせでも、個品は種類が分かればよいです。状況に書いた場と、その場の物を描きます。選んだ食べ方と別の食べ物は足しません。保管を棚の一種類にしません。買い置きという理由で棚に寄せません。顔と、手渡す手元は出しません。状況の欄は画面に出します。画像の文字には焼きません。キャッチとセールスに【】は付けません。キャッチは全角6〜12字の1本です。得たい結果の全文は前に足しません。12字を超えたら1回だけ短く書き直し、まだ超えたら画面に残して画像には載せません。

料理の名前は新しく作りません。4件に満たなくても、検索で名前を足しません。

- マスタか公式ページに、別の料理へ足す食べ方があるときは、その中から機械が状況に合うものを1つ選び、画面では選択済みにします。人は候補の中で直せます。同じ料理は1案だけです。残りが無ければ、その案の料理は空で、商品を写します。
- 食べ方が1件も無いときは、料理名は空です。商品そのものを、その状況の場に置きます。商品名では分けません。

贈り物は、得たい結果に届ける、渡す、贈る、手土産、差し入れ、贈り物、贈答があるときです。包んだ箱を商品の横に置きます。手渡す手元は使いません。

合格は、その画像を見て、誰のどの状況か分かることです。料理名の上手さでは見ません。足場が材料に無い、体への効能で場が無い、選んだ使い方と別の場の物がある、は不合格です。選んだ使い方の場に普通にある物は、材料に名詞が無くても不合格にしません。

#### 3.6.3 再生成前後の比較・採用（2026-08-30 ロック）

**目的**: レ点再生成したあと、**再生成前と後を並べて**見比べ、どちらが良いか（または**どちらも採用**）を選べる。いまの「比較ファイルを上書き」は廃止する。

##### ファイル

| 置き場 | ルール |
|--------|--------|
| `比較\` | 人が見る候補。**再生成で消さない・同名上書きしない** |
| 再生成前 | 同名のまま残すか、`比較\履歴\{YYYYMMDD_HHMMSS}_{元ファイル名}` へ退避（どちらでも可。実装は片方に固定） |
| 再生成後 | **新ファイル名**で追加（例: 元名＋`__r2`、または theme 内連番）。カードを増やして表示 |

##### 画面

- 同じ themeId の複数版を **横並び（または世代ラベル付きカード）** で出す（例: `T4 現行`／`T4 再生成`）

- 再生成直後は旧版と新版の両方が残る（旧を自動削除しない）  

##### 採用の選び方

| 人の選択 | 挙動 |
|----------|------|
| **片方だけ採用** | その版だけ `adopted` に入り 02 へ。他版は比較に残す（削除しない） |
| **どちらも採用** | **可**。同じ themeId でも版が違えば別キーにする（例: `T4` と `T4__r2`）。それぞれにレ点子SKUを割り振れる。02 は `{親SKU}_単体__{adoptKey}.png` |
| どちらも不採用 | 02 に書かない。比較・履歴には残してよい |

#### 3.6.2 既存画像の再利用（スキップしてレビューへ・2026-08-30 ロック／**Agent自動 2026-11-01**）

**目的**: 一度作った比較画像があるとき、B-④／レビュー再実行でも **全部作り直さず**、最終の修正・採用・レ点子割当画面へ進める。

**実現可否**: **可**。画像の実体はローカル `b5_main_base_compose\{省略名}_*\比較` に残る。`review_launch` は既存 dir を開ける。compose（OpenAI）だけ条件付きで飛ばせばよい。

##### 判定（親ごと）

1. `b5_main_base_compose` 配下で、当該親の **省略名（または JAN／親SKU）に一致する最新ラン**を探す（`比較\` に jpg/png があるもの）  
2. 今回チェックした各案の **catchBurn（なければ catch）** が、比較ファイル名に含まれるかで照合（themeId だけでは足りない）  
3. **Agent は三択をチャットで聞かない**（`python b5_reuse_decide.py --from-json _b5_checked_{JAN}.json`）。人が「全部作り直し」と書いたときだけ `--full`

| mode | 挙動 |
|------|------|
| **reuse（既存を使う）** | OpenAI compose を**しない**。その compose-dir を `--fresh` で review |
| **missing_only（足りない分だけ）** | キャッチが無い案だけ、**同じ compose-dir** へ足す → `--fresh` で review |
| **full（全部作り直し）** | 新規タイムスタンプでチェック分を compose → `--fresh` で review |

**自動で full にする条件（聞かない）**: 比較ラン無し／比較0枚／textColor が既存と違う／packageTruth が既存と違う／チェック案のキャッチがすべて未作成。  
**人が明示したときだけ full**: 指示・チャットに「全部作り直し」。

##### 既存を使うときの注意（門）

- **文字色** → 既存再利用時は前回 `b5_proposals.json` の textColor と今回が同じこと。違うときは自動 full（画像に焼いた色は部分更新できない）  
- **キャッチ文** → 焼き込み済みのため画像側が正（必要ならレビューで再生成）。案のキャッチが変わった分は missing_only  
- **比較が0枚／フォルダ無し** → 自動 full  
- 02 へのコピーはレビュー後。再利用は **比較フォルダの再利用**  
- review 起動は **必ず `--fresh`**（古い Listen 禁止）

##### GAS ①ボタン（コード済）

- 文言: **「過去の画像を使う（案・生成をスキップ）」**  
- 正本を選んだ親について Drive の最新比較を探し、**案出し・compose なし**で指示文へ（フォルダパス付き）  
- 人が指示をコピー → Cursor／Agent が `review_launch --compose-dir … --fresh` だけ実行

### 3.7 どのテーマを何件取るか

目標 **レ点子SKU数**（2未満なら4、上限12）。**採用画像は最大でレ点子SKU数**。次は **出さない**: 根拠が薄い効能売り／材料もAI補完も無いテーマで枚数だけ埋める案。

候補化（2026-10-10・入口ゲート廃止）:

1. 案は **ペルソナ＋材料**から出す。themeId はラベル（ファイル名・画文一致用）。  
2. **入口ゲートはしない**（「数字があるからT1」「産地文があるからT2」で落とさない）。  
3. **事実の門は残す**: 材料に無い賞・累計数字・産地・原料・効能は書かない／描かない。  
4. **商品名明示**は名前フル＋特徴。それ以外は用事が先（§0.2）。  
5. 食品で材料不足時の料理は AI 補完可（§0）。味だけの材料で成果案を無理に埋めない。  

候補が目標より多ければ **その商品の sellScore 順**。最低1（商品名明示のみでも可）。カテゴリ一括の順位表は使わない。
