## 0. 社長合意（2026-07-26）

1. SC送信テストは **未送信SKU**（または事前チェックのみ）。既存掲載への不完全UPは避ける。  
2. 必須列の正は **マスタ列名 → HPC列**。成功PACKAGEDで検証する。  
3. 次は本付け合わせ表 → 承認後に **C1-1b（必須列追加）** 実装。  

**拡張前提（合意補足）**: FOOD や他 Product Type でも必須項目の追加・紐付け直しが必要になる。  
本表は **PT別シート（またはPT別セクション）** で伸ばす。HPCは第1シート。列番号はテンプレ版でずれうるため、**見出し名を主キー**、列番号は「当該指紋時点の参考」とする。

## 1. 設計原則

| 原則 | 内容 |
|------|------|
| 正本 | **マスタの列項目名**（楽天／Yahooと同型の人間正本） |
| 中間 | GENERATED列（不足分は拡張 or C1がマスタCSVを併読） |
| 行き先 | HPC純正 xlsm の行4見出し（行5属性は書かない） |
| PT分離 | `HPC` / `FOOD` / … ごとにマップ表を持つ。共通列は「共通」節に抜き出し可 |
| 検証 | 成功PACKAGEDの非空列 ⊆ マップ実装。差分は DRY_RUN レポートに出す |
| 指紋 | 行3–5不一致時は本番停止（既存C1）。マップ更新時は指紋も取り直し |
| 固定値 | マスタに無いがSC必須のものは「固定／既定」列で持つ（PT別） |

## 6. 今回のSCエラーとの対応（スモーク）

スモークCSVはテスト文言・必須列未埋めのためエラー多数。対応関係の例:

| SCで赤かった系統 | マップ上の手当 |
|------------------|----------------|
| メーカー名 | §3 メーカー名 |
| 商品説明／仕様 | 箇条書き①〜⑤ |
| 輸入・限定・感熱 | 固定＋感熱マスタ |
| 原産国・危険物・液体 | マスタ／固定 |
| ユニット数・単位・状態 | マスタ／固定「新品」 |
| 商品タックスコード | **マスタ `商品タックスコード`（固定しない）** |

→ **送信せず破棄でよい**（ツール生成パイプライン自体の合格とは分離）。
