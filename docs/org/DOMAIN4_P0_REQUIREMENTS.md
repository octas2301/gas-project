## 1. スコープ

### 1.1 やること（P0）

1. inventory-app から実在庫を読む（シート再計算＝`InventoryLogic.gs` 同規則）  
2. 出品マスタから子SKU・セット数（数値）・紐付けキーを読む（親行除外）  
3. 単品シリーズのみ適正在庫を算出（親 §7.2）  
4. ローカル TSV に出力  
5. 月販はスタブ（`monthly_sales_source=stub` 必須）  
6. ミックスは計算せず `skip_reason`（P6）

### 1.2 やらないこと

- 楽天CSV／Amazon 出品 PUT／Yahoo 出品本線  
- inventory-app UI 改修  
- モール在庫更新・FBA更新  
- 発注メール・発注書（P4/P5）  
- マスタ「在庫数」更新・領域4専用スプシ書込（P0外）  
- ミックス分解計算（P6）

## 2. キー方針（社長ロック）

| 種別 | 倉庫との紐付け |
|------|----------------|
| 倉庫キー（B1） | inventory-app「単品JAN」欄＝本物JAN **または** 社内キー |
| 単品シリーズ | **代表JAN（＝その単品のキー）** で倉庫と結んでよい |
| ミックス | 代表JANは倉庫キーにしない。**構成比商品一覧の構成品JAN（または社内キー）** で部品紐付け（計算はP6） |
| 薄い台帳 | 巨大発注マスタは作らない。領域4専用の紐付け台帳で名簿をつなぐ（P0は設計のみ可） |
| 結べない行 | `skip_reason`。**在庫0扱いしない** |

### 2.1 マスタ読取ルール

- 子SKUが空の親行は対象外  
- セット数は **数値セル前提**（非数のみ skip: `set_count_invalid`）  
- キーは文字列正規化（空白除去・桁落ち防止）  
- 倉庫名簿にキーが無い → `stock_key_not_in_inventory`（0にしない）  
- ミックス → `mix_deferred_p6`（P0）

## 3. 入出力

### 3.1 入力

| 入力 | 正本 |
|------|------|
| 実在庫 | inventory-app（棚卸＋確定後修正＋翌日以降入荷−出荷。Asia/Tokyo） |
| 販売SKU | 出品マスタ `▼商品マスタ(人間作業用)` |
| 月販 | スタブ |

### 3.2 出力列（TSV）

`run_id`, `ran_at`, `child_sku`, `set_count`, `stock_key`, `stock_qty`, `monthly_sales`, `monthly_sales_source`, `safety_stock`, `available`, `proper_qty`, `skip_reason`, `note`  

パス: `tools/domain4_inventory/out/proper_stock_YYYYMMDD_HHMM.tsv`（stub であることがファイル名またはヘッダで分かるようにする）

---

## 4. 計算式（単品・P0）

```text
安全在庫 = monthly_sales × (7 / 30)
可用     = max(0, stock_qty − 安全在庫)
proper_qty = floor(可用 / N)   # N はセット数（数値）
```

中間値の端数は保持し、最後の `floor` のみ。実在庫が負でも出力し note に記録。

現在庫再計算の一致条件（必須）:

- 最終棚卸日（完了セッション優先、無ければスキャン日最大）  
- 棚卸当日数量は完了セッション・確定後修正除外  
- 確定後修正は最終棚卸日0時以降加算  
- 入荷・出荷は翌日0時より後  
- タイムゾーン Asia/Tokyo  

読取は読み取り専用。再計算 **かつ** C4 画面突合（±0）。
