## 1. 目的

人間の Drive **File 操作**を、Amazon新規の日常で次だけに落とす。

| 残す人手 | やめる人手（P1目標） |
|----------|----------------------|
| Drive **07** へ白抜きを置く | `02` への手コピー／手リネーム／手削除 |
| マッチング sheet で **MAINドラッグ**（ONLYなら PT） | 退避フォルダへの手移動 |
| SC **ZIP UP**（手ZIP＝当面の正。U5は別） | C-2／U4の前後で Drive を開いて File を直す運用 |

シート上のドラッグは **File ではない**（人間ゲートとして維持）。MAINドラッグ**自動化**は本包に含めない。

## 3. スコープ

### 3.1 含む（実装承認後）

| 項目 | 仕様 |
|------|------|
| ギャップ洗い出し | C-1→ドラッグ→C-2 の経路で、人間がまだ Drive File している箇所を列挙し潰す |
| `02` 出口契約の強化 | ④＝コピー出力・同名上書きルールを HUMAN_RUN／ログで明示。手置きを日常手順から削除 |
| 失敗時の案内 | `02` 不足・MAIN欠落時は **ログ＋ダイアログで原因と次アクション**（「Driveで直して」ではなく「C-1再実行／ドラッグ見直し／レ点不一致」等） |
| 退避 | `AMAZON_IMAGE_CANDIDATE_ARCHIVE_ENABLED` 既定ONを維持。失敗候補は手退避させない |
| Cコース整合 | 日常入口は C モーダルのまま。P1でメニューIAをやり直さない |
| Property | 新規トグルは最小。追加する場合は **既定安全側（OFFまたは現行互換）**＋LEDGER |
| docs | 本承認／P1 HUMAN_RUN／U2・C HUMAN_RUN の「02を手で触る」記述削除／PHASE／LEDGER |

### 3.2 含まない

- MAINドラッグ自動化・白抜き自動生成  
- U5（ZIP作成自動化）  
- P2／P3／Dc・P4b（カテゴリ本線書込）  
- 楽天画像マッチング本体・R-Cabinet 経路の改変  
- マスタ JAN／在庫数への書込  
- レ点規則の変更（子レ点／親のみ全子）  
- 07／02 フォルダID契約の破壊的変更（分離方針は維持）  
- ALLOW_PROD 等の出品トグル自動ON  

### 3.3 境界（混同防止）

| 本承認（P1） | 隣接 |
|--------------|------|
| 07以降の **Drive File 手数**を減らす | C-IA＝メニュー／クリック削減（済） |
| `02`／退避／U4前後の人手 File を無くす | U5＝ZIP自動（後） |
| sheet ドラッグは残す | MAINドラッグ自動化（後） |

## 4. 日常フロー（P1後の目標）

```text
（常設）AMAZON_IMAGE_CANDIDATE_FOLDER_ID = Drive07
 → C「Amazon新規：準備」
 →【人間・File】白抜きを 07 へ
 →【人間・sheet】MAINドラッグ（ONLYならPT）
 → C「Amazon新規：ドラッグ後」（③→④→U4・FileはGASのみ）
 → 以降 D（出品）。画像の SC 投入は【人間・ZIP】のみ
```

人間が日常で Drive を開くのは **07 への白抜き配置**と、必要なら **ZIP用素材の回収（04等・既存運用）**に限る。`02` は開かない。
