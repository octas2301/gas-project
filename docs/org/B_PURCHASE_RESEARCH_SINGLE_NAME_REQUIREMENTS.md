# 仕入れ検討① — 単品商品名・JAN 充填（見積前）

**日付**: 2026-08-24  
**状態**: **要件定義**（コードなし。実装は別承認）  
**親**: [B_PURCHASE_RESEARCH_FLOW.md](B_PURCHASE_RESEARCH_FLOW.md) D→E  
**列**: `単品商品名`・`JANコード`・`商品名`・`メーカー名`・`同商品のセット数量`・`販売形態`

---

## 1. 目的

問屋・メーカーへの見積には **単品の商品名**が必要。できれば **JAN**。

| 列 | 役割 |
|----|------|
| `商品名` | Amazon／Keepa の販売タイトル（セット表記込み）。見積文面の正にしない |
| `単品商品名` | **見積に出す名前の正**（1袋／1品） |
| `JANコード` | あれば強い。空・誤り・複数がありうる。**正本にしない** |

本スライス（**S**）で `単品商品名` を埋め、JAN の信頼を付ける。見積提案（E）の前に完了させる。

**対象行**: 品番リストで **見積候補**のものだけ。見送り行は触らない。人が直した `単品商品名` は機械が上書きしない。

---

## 2. 役割分担

| 層 | やること |
|----|----------|
| AI | タイトルから単品名案を切り出す。迷い時は候補選びの補助 |
| Amazon Catalog／Keepa 検索 | 「メーカー＋単品名案」で実ヒットを取る（**存在する**の証拠） |
| コードの照合 | ヒット件数・タイトルの近さ・JAN 件数でパターン判定 |
| 公式サイトの商品ページ突合 | **しない**（掲載なしが多く使えない） |

「世の中に存在する」をプロンプト文言だけで定義しない（根拠なしで通るため）。

### 2.1 「存在する」の定義

> メーカー名＋単品名案で Catalog（主）または Keepa を検索し、返ってきたタイトルが単品名案と十分近いものが **1件以上**ある。

| 結果 | 意味 |
|------|------|
| 存在OK | 近いヒットあり |
| 存在NG | 無い／遠すぎる |
| 存在不明 | API失敗など。落とさず保留 |

閾値は実装前の dry で決める。セット数量だけのヒットは「近い単品」とみなさない。

---

## 3. 処理順

```text
0. 前処理
   セット語を落とした候補文字列（ヒントのみ）
   販売形態が詰め合わせ系（③④）→ 自動確定しない

1. AI が単品名案を出す（まだ確定書きしない）
   入力: 商品名・メーカー・セット数量・販売形態

2. 存在確認（Catalog／Keepa）
   NG → ヒントで再検索 → AI 再抽出1回 → だめなら要確認

2b. 当行の Keepa 商品名との突き合わせ（§4.3）
   まとめ売りでズレるのは正常／単品なのにズレる・別ASINヒットは要確認

2c. メーカー内コーパス補助（§5・限定）
   AI迷い・存在NG・まとめ売りで迷うときだけ。単品名の自動確定には使わない

3. JAN 整理（§4.2）
   Keepa 転記 JAN と検索で出た JAN をパターン分け

4. 人確認が必要な行だけ残す
```

---

## 4. パターン

### 4.1 販売形態

| ID | 条件 | 動き |
|----|------|------|
| **P-MIX** | 詰め合わせ・異種セット（③④） | 単品名を自動確定しない。見積提案に載せない |
| **P-OK** | 単品売り／同商品まとめ（①②） | 以下へ |

### 4.2 存在 × JAN

| ID | 存在 | KeepaのJAN | 検索側のJAN | 動き |
|----|------|------------|-------------|------|
| **A1** | OK | 1 | 一致 | 単品名確定・JAN高信頼 |
| **A2** | OK | 1 | 不一致 | 単品名は残す・JAN低信頼（消さない） |
| **A3** | OK | 1 | 取れない | 単品名確定・JAN中信頼 |
| **B1** | OK | 空 | 一意 | 単品名確定・JAN候補1（人レ点推奨） |
| **B2** | OK | 空 | **複数** | 単品名可・JANは列挙のみ。**自動で1つ選ばない** |
| **B3** | OK | 空 | 無し | 単品名確定・JAN空のまま（見積は名前だけ可） |
| **C1** | OK | 複数 | 1つに収束 | 単品名確定・収束JANを候補 |
| **C2** | OK | 複数 | 収束しない | 単品名可・JAN列挙・人必須 |
| **D1** | NG | — | — | 再抽出1回→要確認 |
| **D2** | 不明 | — | — | 保留（次回再実行） |
| **E1** | OKだがAI自信低 | — | — | 要確認（コーパス補助§5の対象） |

**複数JAN**: 先頭を黙って採用しない。単品名が通れば見積材料には載せてよい（JANは後で人選択可）。

### 4.3 存在OKでも Keepa 商品名と不一致（F）

| ID | 条件 | 動き |
|----|------|------|
| **F1** | まとめ売り（②）・数量＞1で、タイトルと単品名案がズレる | **正常**。単品名は書いてよい（信頼 mid） |
| **F2** | 単品売り（①）なのにタイトルと大きくズレる | **要確認**（切り出しミス疑い） |
| **F3** | 存在ヒットの ASIN が当行と違う | **要確認**（別商品に当たった疑い） |

---

## 5. メーカー内コーパス補助（限定仕様）

同一メーカーの品番リスト／①候補に溜まった Keepa 由来タイトルをコーパスにする。

**目的**: 似た語の繰り返し・近いタイトルを、AI へのヒントや検証に使う。

**使ってよいときだけ**（いずれか）:

- AI の自信が低い（E1）
- 存在NGのあとの再抽出
- まとめ売りで単品名が定まりにくい（F1付近で迷う）
- 人が「コーパス補助あり」で再実行したとき

**やってはいけない**:

- 出現回数1位をそのまま `単品商品名` に確定する
- 全行に毎回フルコーパス解析を必須にする
- 公式サイト突合の代わりにする

**第1版のやり方（簡単側）**:

1. メーカーの既存タイトルを集める（追加 Keepa GET は原則しない）
2. セット数量語を落とした文字列で、当行に近いタイトルを最大3件選ぶ
3. 任意で「同じフレーズがコーパスに何件あるか」をスコア補助
4. その3件を AI に渡し、単品名案を出し直す／選ばせる
5. その後も **存在確認（§2.1）を必ず通す**

出現回数だけで単品名を決める本線ロジックは作らない。

---

## 6. 単品名の切り出し

- 落とす: 〇袋セット・まとめ・詰め合わせ・送料無料などの飾り  
- 残す: シリーズ・味・内容量・形態  
- メーカー名は列と重複なら単品名から省いてよい  
- 機械のセット語除去はヒントのみ（単独では確定しない）  
- 画像 Vision は第2段（自信低・存在NGのときだけ）

---

## 7. 列・見積への接続

| 列（既存／追加案） | 意味 |
|--------------------|------|
| `単品商品名` | 見積文面の正 |
| `JANコード` | 原則消さない |
| `単品名信頼`（案） | high／mid／low／要確認／保留 |
| `JAN信頼`（案） | high／mid／low／欠測／複数 |
| `JAN候補`（案） | 複数時の列挙 |
| `単品名パターン`（案） | A1／B2／F2 等 |

| 見積提案に載せる | 載せない |
|------------------|----------|
| 単品名あり・要確認以外・詰め合わせでない | 要確認・保留・詰め合わせ |
| JAN複数でも単品名OKなら可（JANは空でも可） | 単品名なし |

> 見積の品目名は `単品商品名`。JAN は高信頼または人選定済みのみ併記。
