## 0. 目的（1文）

**セラー台帳を枯渇させず**、**店は軽く・メーカーは1社完走ずつ**回し、人は **実態check と見積判断** だけに寄せる。

## 1. 背景・問題

| 問題 | 本要件での解 |
|------|----------------|
| 店1件通しが重い（query＋product＋門＋①候補） | **A-light** で店フェーズを分離 |
| 週1メーカー決定で待ちが発生 | **完走→即次1社**（⑧の「週待ち」運用は廃止） |
| 複数メーカー同時洗いは見積が散る | **常に1社完走**（既存ロックと一致） |
| セラーが尽きると店レーンが止まる | **レーン0 セラー貯め** をサイクルに明示 |
| 前回簡易版でセラー貯めが抜けていた | 本書で **3レーン** として固定 |

## 2. 3レーン（正）

```text
[0] セラー貯め … 競合DB「セラー」へ新規 sellerId（§5.4・C0 実装後）
[1] 店 A-light … レ点店を調査しメーカー名＋累計ヒットを更新
[2] メーカー B→D … 1社完走 → D1→D2 → 即次1社
```

### 2.1 レーン間の依存

| レーン | 入力 | 出力 | 止まる条件 |
|--------|------|------|------------|
| **0 セラー貯め** | 門通過 ASIN（Keepaフル BB ＋ SP-API 新品オファー） | `セラー` 新規行（調査CK **OFF**） | 門通過 ASIN なし |
| **1 A-light** | `セラー` の調査CK=TRUE | `抽出メーカー`・食品比率・サマリ追記・**セラーヒット再計算** | **未調査店（レ点可能）が無い** |
| **2 B→D** | メーカーサマリ（自動選定1社） | 洗い完走・①候補・品番リスト・見積候補 | 洗えるメーカー（実態OK・未調査）が無い |

**フィードバック**: レーン2 の門通過 → レーン0（C0 後）→ レーン1 の店プール補充。

**A 契約の変更**: 従来 A は query ASIN を倉庫・①候補へ渡す。**A-light では門・①候補・店ASIN倉庫を行わない**。①候補／D の材料は **レーン2（メーカー Catalog 完走）のみ**。

### 2.2 A-zero は不可

`/query` のみでは **メーカー名が取れない**。店レーンは **A-light** が下限。

## 4. レーン1 — 店 A-light（2026-08-30 改訂）

### 4.1 やる／やらない

| やる | やらない |
|------|----------|
| Keepa `GET /seller` storefront=0 | **門** |
| Keepa `GET /query`（調査カテゴリ・ページ送り） | **①候補** |
| Keepa `GET /product` **メーカー名のみ**（スライス） | **D1/D2** |
| `セラー` 更新・`抽出メーカー`・規模帯 | Keepaフル **upsert** |
| サマリ行追記（実態シード）・**セラーヒット再計算** | メーカー洗い |
| トークン不足時は **温和停止＋トリガー続き**（1店を完走） | storefront=1 全ダンプ |

### 4.1bis 調査カテゴリ・SKU見積・構成比の分担（2026-08-30 了承）

**調査カテゴリ（入力）**: 調査複製 **`①プロファイル`**。最左に **`調査カテゴリー`**（チェック）と **`AmazonルートID`**（数字）。`調査カテゴリー=TRUE` かつルートID非空の行だけが `/query` の対象。初期は **`食品・飲料・お酒` のみ ON**（AmazonルートID=`57239051`。競合DBルート列と同名。カテゴリ名を「食品」に短くしない）。`共通` 行・カテゴリが数字のみの行は対象外。レ点0行は `57239051` へフォールバック＋①ログ警告。門の閾値行選択（マッチ語）とは **別列**。飲料・お酒の除外はルート変更せず門・後工程。

**SKU見積（計測の正・店規模）**:

| 項目 | 正 |
|------|-----|
| **理想** | 在庫があるSKUのみ（在庫なしは調査不要） |
| **計測** | Keepa `/query` の **`totalResults`** ＝ **調査対象カテゴリ・現在出品中SKU見積**（近似） |
| **やらない** | `/product offers=20` 等による在庫の事前サンプリング（トークン過多・中止） |
| **やらない** | `カテゴリ構成`／`食品比率`／`ストアASIN数` から規模帯を計算すること |

**カテゴリごとの測り方**:

| 項目 | 正 |
|------|-----|
| 規模測定 | レ点カテゴリ **1行につき query page0 を1回**（`rootCategory`＝その行のIDのみ）→ カテゴリ別 `totalResults` |
| A-light の ASIN 取得 | レ点カテゴリを **OR 1本の query** でページ送り（測ると歩くは分ける。union） |
| トークン（測定） | 約11 × レ点カテゴリ数（店1件・page0） |

**セラー列（出力・競合DB `セラー`）**:

| 列 | 役割 |
|----|------|
| **`在庫SKU見積`** | 店の代表件数（下記ルール） |
| **`規模帯`** | 店の代表帯（小／中／大／特大） |
| **`SKU見積内訳`** | レ点 **2カテゴリ以上**のとき必須。例: `食品:480\|おかし:40`。1カテゴリのみなら省略可 |
| **`規模帯内訳`** | 同上。例: `食品:大\|おかし:小` |
| **`asinList件数`** | 互換。A-light 完了時に代表件数と同値を書いてよい |
| **`カテゴリ構成`／`食品比率`／`ストアASIN数`** | **店の性格・優先・食品0%除外**用。規模帯の入力に **使わない** |

**代表値・501 hold**:

| 判定 | ルール |
|------|--------|
| 各カテゴリの帯 | そのカテゴリの SKU見積だけで §4.2 の閾値 |
| 店の **`規模帯`** | レ点カテゴリ帯の **最大**（大と小 → **大**） |
| **501 hold** | **いずれか1カテゴリ**の見積 ≥501 → 特大・フルしない（カテゴリ合算で501をまたがない） |
| 合算件数 | 帯判定に使わない。必要ならログ／任意列で可见化可（実装時） |

**見る場所**: レ点＝調査複製 `①プロファイル`。結果＝競合DB `セラー` の上記列。メーカーサマリの `規模帯`（Catalog）と混同しない。

### 4.2 セラー規模帯（メーカー帯と同型・閾値）

| 帯 | SKU見積（カテゴリ単位） | 店フル調査 |
|----|-------------------------|------------|
| **小** | ≤100 | **する**（1店ずつ・続きあり） |
| **中** | 101–300 | **する** |
| **大** | 301–500 | **する**（小中を先に。日常は控えめ） |
| **特大** | ≥501 | **フルしない**（浅い抽出のみ／hold。旧1000超holdを501に前倒し） |

閾値は当面変更なし。レ点を食品以外へ広げる直前に、代表店の内訳を見て必要なら再確認。

### 4.3 1店フル・バッチ

| 項目 | 正 |
|------|-----|
| 同時 | **1店ずつ**完走してから次へ |
| スライス | 1実行あたり product は従来どおり数十件単位（トークン・25分）。店全体はトリガーで続ける |
| 特大 | page0＋少数のみ → 調査CK OFF・帯=特大。全日次フル対象にしない |
| Keepaフル | **書かない**（社長決定維持） |
| 429／25分 | FULL と同形の温和停止＋続き |

### 4.4 日次・追加ラウンド（小中メーカーが空のときの店レーン）

| 項目 | 既定 | Property |
|------|------|----------|
| 自動レ点（調査CK ON） | **8店／日** | `PR_CYCLE_AUTO_CK_DAILY_CAP` |
| 店フル完走の目標 | **5店／日** | `PR_ALIGHT_DAILY_TARGET`（未設定=5） |
| 店フルの上限 | **10店／日** | `PR_ALIGHT_DAILY_MAX`（未設定=10） |
| 「新メーカー0なら追加」 | 同日最大 **10ラウンド** | `PR_ALIGHT_NO_MAKER_ROUNDS_MAX`（未設定=10） |

**用語**

| 語 | 意味 |
|----|------|
| 洗える小中 | 規模帯=小または中で、洗い選定適格（実態・除外・90日・保留等を満たす） |
| 店ラウンド | 自動レ点（残枠）→ 1店 A-light フル（または次レ点店）→ サマリ新規メーカー確認 |
| 新メーカー | 当該ラウンドでサマリに **新規 insert** された洗えるメーカー行 |

**ラウンド（正・2026-08-30 明確化）**:

```text
洗える小中 = 0
  → 店ラウンドを最大 10 回:
       a. 未レ点があれば日次cap内で自動レ点
       b. 未調査（レ点済・未フル）店があれば 1店 A-light
       c. サマリに新メーカーが増えたか見る
       d. 増えた → 直後の心拍から小／中メーカー洗いへ戻る（大に進まない）
       e. 増えず、かつ店フル日次上限・レ点枠・材料が残る → 次ラウンド
       f. 未調査店も未レ点候補も無いときだけ C0（未タグ門通過→セラー追加）→ また a へ
  → 10ラウンド尽きた／日次店上限／材料切れで小中がなお 0
  → 初めて 大（週間枠空き時）→ 大が 0 なら特大
```

**禁止（小中=0 かつ店ラウンド未尽）**

- 大・特大の **新規洗い選定**
- 大・特大の **キュー続き／Keepa中続き** を開始すること（進捗 `left=` は残してよいが、次スライスは店ラウンド優先）
- 小中=0 直後に **C0 だけして大へ進む**こと

**検収ログ**: 店ラウンド中は `shop_before_large`＋ラウンド番号。大を `target` にしない。大開始時は `shop_rounds_exhausted` または `shop_material_empty`。

### 4.5 サマリ insert

- 同名行は増やさない
- **実態**はシード＋AIリゾルバ。未解決は要確認（レーン2対象外）
- **未調査（AI前）**: A-light で行が増えた直後のプレースホルダ。洗い・Catalog選定の対象外

### 4.5bis 実態AIと店の分離（2026-09-04）

店調査の尻に実態AIを詰め込まない（時間切れで未調査が残るのを防ぐ）。**新トリガーは作らない**（心拍の次アクション1本）。

| 項目 | 正 | Property |
|------|-----|----------|
| 心拍アクション | `jitta_resolve`（①ログ `heartbeat jitta`） | — |
| 優先 | **洗える小中より後**／**小中=0の店ラウンドより先**（未調査を仕分けて洗えるメーカーを補充） | — |
| 1回件数 | **8**（最大20） | `PR_JITTA_HB_CAP` |
| A-light 末尾AI | **しない**（レーンON時。ログに `jitta_deferred_to_hb`） | `PR_JITTA_AFTER_ALIGHT`（明示時のみ） |
| 自動レ点抑制 | 未調査 ≥ **30** なら新規レ点しない（山を増やさない） | `PR_JITTA_BACKLOG_GATE` |
| 切戻し | 心拍レーンOFF → 旧: A-light 末尾でAI | `PR_JITTA_HB_LANE_ENABLED=false` |

### 4.6 店選定（レ点）

- 完成形: 日次cap内で調査CK自動 ON（案B）
- 優先: holdでない → **食品0%除外（構成比）** → **小規模出現**多い店 → Amazon／**特大帯（§4.1bis）**はフル対象外
- 食品0%・優先は **構成比**。フル対象外の特大は **SKU見積（query）**。混ぜない
- 試験中の手動レ点は残してよい
- **§4.5bis**: 未調査がゲート以上のとき自動レ点は選定しない（既存レ点店の A-light は可）

### 6.3 自動選定（人は選ばない）— 2026-08-25 改訂

**旧社長決定（2026-08-22）「≤500 → セラーヒット降順・変更しない」は本改訂で置き換え**（人間了承 2026-08-25）。

**規模帯（Catalog 列挙ユニーク件数。501 で打ち切り）**:

| 帯 | 件数 | 日常 |
|----|------|------|
| **小** | ≤100 | すぐ Keepa→門→D |
| **中** | 101–300 | 小の次 |
| **大** | 301–500 | 小・中=0 かつ **週間枠空き**のときだけ |
| **特大** | ≥501（打ち切り） | 大の次。**週間 N=2**。洗いは [FULL 分割B](B_MAKER_WASH_FULL_REQUIREMENTS.md) |
| **不明** | 未列挙／ページ未了 | **洗い選定しない**。心拍で列挙〜501して帯を書く |

**列挙＝規模確定**（選定専用の「数えて捨てる」探針はしない）。サマリに残す: `Catalog見積` / `規模帯` / `見積日時` / `見積根拠`（`enum_cut501` / `enum_done` / `queue`）。

**列挙は1実行でまとめる**（2026-09-08・`PR_CYCLE_ENUM_BATCH_N` 既定8）: 列挙そのものは実測16〜48秒だが、心拍1回=1社だと 洗い→店→心拍 の受け渡しを毎回やり直すため **1社あたり実測7分**（選定1.6分＋`hb_yield_deferred` 2分＋`shop_busy_wait` 2分＋発火往復1分）。未判定が実測244社あり、1社7分では消化に約28時間で、その間 Keepa は材料切れで空く（2026-09-08 夜間: 10.3時間の61%が Keepa作業ゼロ・空振り選定24回）。**打ち切りは3つ**:

| 打ち切り | 理由 | ①ログ |
|----------|------|--------|
| **小・中が1社出た** | 洗いを待たせない（小中優先を崩さない） | `stop=sm_found=（社名）` |
| 実行予算の残りが5分未満 | 予約とログのぶんを残す。列挙は1社ずつ確定書き込みなので途中中断でも成果は残る | `stop=budget` |
| 対象切れ／cap 到達 | — | `stop=list_end` |

1社の例外は**飛ばして次へ**（タイトル含有0は保留処理だけして継続。`skip=` に計上）。優先順は従来どおり **規模不明が先、次に「帯あり見積なし」**。`PR_CYCLE_ENUM_BATCH_N=1` で心拍1回=1社の旧動作に戻る。

**洗い選定の優先順**（§6.3bis と併用）:

1. **洗い途中**があれば **続きのみ**（ただし `empty_research`／`done_no_candidates`／**`洗い状態=保留`** は対象外）
2. **Catalog見積セル未了**の洗えるメーカー → **列挙のみ**（Keepa 新規より先。心拍 `catalog_first`）
3. **実態** = 製造メーカー or 入口ブランド
4. **除外**: 非仕入先・要確認・調査CK=TRUE・90日以内完走済み・食品0%店のみ由来・**保留全般**（`empty_research`／title0 等）
5. **小 → 中**（同帯内: セラーヒット **≥2 を先**、0〜1は後回し。同グループ内はヒット降順 → 最終調査日空 → 古い順）
6. 洗える小・中が **0** → **§4.4 店ラウンド**（最大10。尽くしてなお小中0のときだけ次へ）
7. 店ラウンド尽きた／材料なし かつ **週次大・特大枠に空き** → **大**（§6.3bis）
8. 大も **0** かつ枠に空き → **特大**（分割B）

**K=3**: 洗える小∪中が **3 未満**のとき店レーンへ（補助）。**主の店挟みは §6.3bis の完走1社ごと**。

**人**: `実態=要確認` のみ（その社はスキップし心拍は次へ。全体停止しない）。

### 6.3bis レーン配分（2026-08-29 了承）

**目的**: 中小の Keepa⇄セラーを主戦場にし、大・特大の占有を防ぐ。

| 段階 | 内容 |
|------|------|
| **列挙** | Catalog で規模帯付け。**洗えるメーカーの Catalog見積を先に広く埋める**。Keepa 新規は見積完了後のみ（途中の Keepa中続きは可） |
| **Keepa〜リスト** | キュー→門→①候補→D（主戦場は **小・中**） |
| **セラー** | A-light（または未レ点なら **C0→自動レ点→A-light**）。新メーカー名をサマリへ insert（同名は増やさない） |

|--------|----------------|

**小中=0 と大**: §4.4。店ラウンドを尽くすまで **大・特大を選定・続き開始しない**（一度 pick してから defer する実装は不合格）。
