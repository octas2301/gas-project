## 1. 目的

Da（人手の SC UP／結果待ち／記録）を、公式経路に寄せて減らす。本包は **Dc ①②③の可否と最短PoC設計**まで。④⑤・ループは P3／後回し。

| Dc | 意味 | いま（過渡） | P2でやること |
|----|------|--------------|--------------|
| **①** | バルクを SC（または公式経路）へ UP | 人間が SC に xlsm／ZIP UP | **可否調査**→可能なら読取／サンドボックス相当の PoC設計 |
| **②** | 処理結果を時間トリガーで取得 | 人間がサマリを監視フォルダへ置く | **取得経路の調査**（Reports／DL API／不可なら人手継続の結論） |
| **③** | 結果の自動取込（状態・エラー要約） | 21-⑮系：**ファイル名のみ**→`UPLOADED_OK`／`FAILED` | **強化方針**（中身パース／エラー要約の要否と安全弁） |

成功定義（調査完了）:

1. ①②③それぞれ **できる／できない／条件付き** が文書化されている  
2. 推奨アーキテクチャ（SP-API／SC人手残／ハイブリッド）が1案に絞れている  
3. 次の **PoC実装承認**に渡せる変更ファイル見積り・リスクがある  
4. 過渡の21-⑮が **いつまで残すか** が決まっている

## 7. 調査結論（2026-08-01）

### 7.1 可否表

| Dc | 結論 | 根拠 |
|----|------|------|
| **①** 現行 Da（**PACKAGED .xlsm** を SC「アップロードで商品を追加」） | **公式 API では不可**（人手継続） | SP-API の出品自動化正は **Listings Items API／`JSON_LISTINGS_FEED`**。flat／XML Listings Feeds は **2025-07-31 廃止**。SCへの **手動 xlsm UPは公式に継続可**だが API から同じ xlsm を投げる経路は無い。※「新規だけ不可」ではない。**xlsm×SC自動UPが不可**。既存ASINへの PUT（レーンA）は別経路で可 |
| **①'** 別経路（JSON Listings／既存 GAS PUT） | **条件付き可**（本P2の①置換ではない） | 相乗り等は既に PUT 実機あり＝**レーンA**。カタログ**新規**の xlsm 本線を JSON に置き換えるのは **レーンC・C1規模の別承認** |
| **②** SC の `*-processing-summary.xlsm` を時間トリガー取得 | **公式 API では不可**（人手で 08 へ置く継続） | 当該サマリは SC バルクUPのUI成果物。完了時刻不定はポーリング動機になるが、**xlsm経路では取るAPIが無い**。トリガーは現状どおり③（08配置後の取込）に使う |
| **②'** JSON_LISTINGS_FEED 利用時 | **可**（レーンCまたはAのFeeds化とセット） | `getFeed` → `resultFeedDocumentId` |
| **③** 取込 | **過渡（ファイル名）は本番温存**＋**強化は任意・低優先** | 21-⑮温存 |

### 7.2 当面アーキテクチャ

```text
① 人手: SC へ PACKAGED xlsm／画像ZIP UP（レーンB）
② 人手: processing-summary を Drive 08 へ
③ GAS: 21-⑮（ファイル名）※中身パースは任意低優先
【並行・本開発】レーンA: 既存カタログは SP-API PUT を主に伸ばす
```

### 7.3 21-⑮

**削除しない。**

### 7.4 方針ロック（2026-08-01 社長「その方針で進めましょう」）

**最適解＝三レーン。今の本開発はA。Cはゲート後。**

| レーン | 対象 | 手段 | 今 |
|--------|------|------|-----|
| **A** | 既存カタログ（ASINあり・相乗り／更新） | SP-API Listings PUT 等 | **本開発の主戦場**（実機あり→安定・範囲拡大） |
| **B** | 新規カタログ（C1 PACKAGED型） | 純正 xlsm＋SC人手UP＋21-⑮ | **本番の正**。多ブラウズ（食品・ドラスト・おもちゃ等）もこちら。エラー／成功を台帳化 |
| **C** | 新規の JSON／Listings 化（最終形） | Definitions＋JSON_LISTINGS_FEED／Items | **今は本実装しない** |

**レーンCに入るゲート（すべて満たすまで禁止）**

1. 同一 PT で xlsm 成功が複数回ある  
2. 同じ欠落エラーが台帳で繰り返している  
3. その **1PTだけ** Definitions＋dry_run が xlsm 成功と同等になる PoC  
4. 優先 PT は最大 1〜2（全ブラウズ同時は禁止）  

**明示しないこと**

- 「JSONの機械エラーが強いから今すぐ新規もJSON」→ **不採用**（多ノード探索では純正xlsmの方が安い）  
- ②ポーリング単独着手 → **不採用**（①'／レーンC前提）  
- P2-③を本開発最優先にする → **しない**（任意低優先）
