## 処理（v1.10）

### A. KW区切り（必須）

- キーワード系セルの **トークン区切りは半角スペースのみ**。
- **`,`（半角カンマ）・`、`（読点）での区切りは禁止**。
- 検出時: カンマ／読点を半角スペースへ正規化して書き戻し、`要確認`（区切り違反）を立てる。
- トークン分割・横断dedupe・最終名trimは **半角／全角スペースのみ**で行う（カンマでは割らない＝正規化必須）。

### B. メインキーワード（1つ）

- 列: `メインキーワード（一つ）[商品を示すkw]`（論理名 `メインKW(3つ)`）。
- **候補から1つだけ選択**する。セル内に複数トークン（スペース区切り）がある場合は **先頭1語だけ残し**、残りを除去して要確認。
- **役割**: 商品名ベースだけでは大カテゴリ／大規模検索からこぼれることがあるため、**大〜中カテゴリ／中規模検索ワード**でSEOを底上げする。
- 細かい語・横展開は特徴／用途／各モール検索KWへ（半角スペース区切り）。

### B2. 共有4列の役割分離と類似横断dedupe（v1.10）

処理順（左優先）: **メインKW → CTRコピー → 特徴キーワード → 用途キーワード**

| 列 | 役割（方向性） |
|----|----------------|
| メインKW | 大〜中カテゴリ／検索語 |
| CTRコピー | 信頼・共感・クリック誘引 |
| 特徴 | 商品属性・差別化 |
| 用途 | 誰が／いつ／どこで使うか |

- **禁止**: ほぼ同じ言い回しを複数列に置くこと（文字数の無駄）。例: `大学共同開発品` と `大学共同開発`。
- **判定**: 完全一致に加え、空白除去＋末尾「品」「用」除去後の一致、または短い方≥5文字で他方に包含される場合は類似とみなす。
- 後列は先行列の seen と類似する語を除去。特徴／用途は候補選定時にも類似を不適とし、適当な候補がなければ空可。
- 空欄採用時は候補を先頭から見て、類似しない案を選ぶ。

### C. 最終商品名の文字数（厳格）

上限（半角0.5・全角1換算）:

| モール | 上限 |
|--------|------|
| Amazon | 75 |
| 楽天 | 120 |
| Yahoo! | 75 |

- 最終名はモールごとの式列順（例 Amazon: `FQ→J→FS→FR→FJ→FK→FT→FW`）で連結。
- **上限超過時**: 式の **後ろの列**から、その列内の **後ろのワード**を1語ずつ削る。
- 弱語／強語の優先はしない（厳格・列順のみ）。超過解消を優先。
- これ以上削れず上限超過のままなら `要確認_最終名{mall}`。
