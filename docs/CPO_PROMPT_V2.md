# CPO値決めプロンプト V2（Gemini用）— Amazon

GAS では `getCPOPromptTemplateV2()` に同一内容を埋め込み、`{{ }}` をマスタで置換する。

## 方針

- **送料・利益の最低ラインはここでは決めない**（②.5 と ③ の役割）。
- **競合価格とセット数**に基づき、**税込・整数の売価案**を JSON で返す。
- **単価グラデーション**（まとめ買いほど1個あたり安い）を **必ず意識**する。システム側でも単調補正するが、**JSON から大きく外れないこと**。

## 入力テーブル

- **②.5 前（既定）**  
  `セット数` / `セット卸値(税込)` / `競合価格(Amazon)`  
  ※送料は **含めない**（未確定のため）。

- **送料参照モード（任意・②.5 後など）**  
  上記に加え `確定送料(参考)` を付ける。**参考情報**であり、送料を決めるのはシステムの②.5 である。

## 競合とグラデーション（指示の要点）

1. **競合があるセット**は、売価の目安として **「競合価格 − 1円」** を最優先する。
2. **同一JAN内で競合が入っている行が2行以上ある**ときは、それらの **1個あたり単価** の関係を踏まえ、**その間のセット**は **単価が滑らかに下がる**ように提案する（競合同士の単価がほぼ同じなら **約1%** ずつの下がりを想定してよい）。
3. **競合が1行以下**のときは、セットが増えるに従い **おおむね 1%** ずつ **1個あたり単価が下がる** イメージで埋める。
4. **心理価格**（980、1980 など）は可能な範囲でよい。

## 出力（厳守）

**必ず最初に** `## 5. 【JSONデータ】` に続く **1つの** ` ```json ` ブロックを出力する。**

```json
{"amazon":[{"setCount":1,"price":749},{"setCount":2,"price":1498}]}
```

その後に説明文（戦略）を書いてよい。システムは **JSON をパースして子行の販売価格amazon に反映**し、**JSON 以外の本文**は **親行の amazon価格戦略** に書く。

## 禁止

- 送料・手数料を使った **厳密な利益額の約束**（③で行う）。
- **単価の逆転**（セット数が増えるほど1個あたりが高くなる）を JSON で提案すること。
