## 5. 実装メモ（実施済）

- **④** … 「リサーチ一括」から「選択行に価格・セット数提案を反映」の呼び出しを外し、モール横断→抜け挿入→反映の3ステップに変更済み（`menuResearchBatchCrossMallAndPropose`）。
- **⑤** … メニュー「⑤ 楽天Yahoo!販売価格を提案（CPO）」で、レ点（出品CK）が付いた行を JAN 単位で Gemini により楽天・Yahoo! の価格を提案。親行に楽天価格戦略・Yahoo!価格戦略、子行に楽天価格設定・Yahoo!価格設定を書き込む。行選択は不要。
- **①** … Keepa取得実行時にシートが無ければ自動作成してから取得処理へ続行（`runKeepaFetchAsinPasteSheetImpl`）。準備の単体メニューは⑨に配置。
- **⑨** … サブメニュー「⑨その他個別メニュー」の下に Amazon／楽天／Yahoo!／共通 を配置済み（`onOpen`）。

## 6. 出品までの流れの整理（マニュアル元データ）

後のマニュアル作成時の元データとする。起点から構成決定までを文章でまとめる。

### 6.1 起点（人間の入力）

**人間が「AI情報取得data」シートに入力する列**

- メーカー名、仕入判断、JANコード、商品名、卸値(税抜)、卸値(税込)、JANコードorオリジナルカタログ商品名、ASINコード、参考情報(画像URL)

※「2. 全データ一括生成」は AI情報取得data の AI 比較用データ（Gemini/OpenAI の結果列）を作るだけで、▼商品マスタ(人間作業用) には書き込まない。そのため、構成案（マスタの親行・子行）を作るには、このあとの Keepa 取得とセット構成提案が先に必要になる。

### 6.2 Keepa 調査

**その次**

- 人間が **ASIN貼り付け（Keepa用）** シートに ASIN を貼り付ける。
- **① Keepa取得（20件／50件／全件）** を実行する。

### 6.3 セット構成を決める（マスタに親・子を作る）

**その次**

- **② amazonセット構成提案** を実行する。
- AI情報取得data と ASIN貼り付け（Keepa用）のブロック（競合セット数・穴のセット数など）を元に、**▼商品マスタ(人間作業用)** の末尾に **親行 1 行と、セット数ごとの子行** を追記する。ここで「構成」が決まる。

**構成案を作るメニュー**

- **マスタに親行・子行をゼロから新規で作る**のは **② amazonセット構成提案** のみ。
- **④ 楽天Yahoo!リサーチ一括** は、**既にマスタに行がある前提**で、足りないセット数の子行を挿入して構成を揃える処理。親行の新規作成はしない。
- ⑨ その他個別の「モール横断 セット数統合判定」「抜けセット数行の挿入」「モール横断結果を楽天・Yahoo! マスタに反映」は、④ の各ステップを単体で回すだけであり、構成案を新規に作る別メニューではない。

### 6.4 この先の流れ（参照）

- 構成・価格の確認・送料設定のあと、③／⑤ で価格提案 → 商品名・商品情報の整備（マスタへ同期・商品名案生成など）→ 画像準備 → 楽天CSV出力・Yahoo!出品・一括出品 → ⑥ 出品CKをクリア。詳細は §3・§4 を参照。

## 7. メニュー名の付け方（メニュー変更時方針）

メニュー変更時に次の方針で命名する。

## 8. 出品フロー メニュー統合 要件定義（案・荒いメモ）

※まず荒く追記し、後にまとめ上げる。

### 8.1 目的

- **一括実行**: 構成決定〜価格提案〜出品情報（一括生成・同期・プルダウン）までを、**一連の流れとして一気に実行**し、最後に人間が構成・競合・価格・出品情報をまとめて確認する運用を、**1つの統合メニュー**で実行できるようにする。実行順は「②→④→③→⑤→一括生成→同期→プルダウン」とする。
- **個別実行**: 従来どおり、各手順を後から切り分けて実行できるよう、**既存の個別メニューも残す**。
- **連番**: メニュー表示の番号（③④⑤⑥など）を **手順の順（実行順）** に合わせて変更する。

### 8.2 前提（人間が理解しておくこと）

- **構成が決まるのは ② だけ**: マスタに親行・子行を新規で作るのは「② amazonセット構成提案」のみ。④は「既にある行のセット数抜けを子行で補う」処理。
- **レ点（出品CK）**: ②で追記した行にはレ点が自動で付く。④・③・⑤はすべて「レ点が付いた行」だけを対象にする。
- **推奨実行順**: ④→③→⑤（④で楽天・Yahoo!の競合・セット数を揃えてから、③Amazon・⑤楽天Yahoo!の価格提案）。

### 8.3 統合メニュー（新規）

- **メニュー名・配置**: 「手順2 構成〜出品情報まで一括（②→④→③→⑤→一括生成→同期→プルダウン）」など、手順番号＋「構成〜出品情報まで一括」と分かる名前にする。② 出品用サブメニュー内で、② amazonセット構成提案の直後など、構成の次に実行するメニューとして分かりやすい位置に置く。
- **実行内容（順序固定）**:  
  1. ② amazonセット構成提案  
  2. ④ 楽天Yahoo!リサーチ一括  
  3. ③ amazon販売価格を提案（CPO）  
  4. ⑤ 楽天Yahoo!販売価格を提案（CPO）  
  5. 2. 全データ一括生成（AI情報取得data の比較用データを生成）  
  6. 3. マスタへ同期（AI情報取得data → マスタの▼マスタ列・作業エリアへ反映）  
  7. 商品名案を生成＆プルダウン再設定（レ点・親SKU行）
- **実行前の前提**: 人間が AI情報取得data に入力済み、ASIN貼り付けにASINを貼って ① Keepa取得 を実行済みであること。この統合メニュー1回で「構成〜価格提案〜出品情報（一括生成・同期・プルダウン）」までが完了し、**構成・競合・価格のチェック・修正は後回し**とし、その後で人間がまとめて確認する。
- **実行後の案内**: トースト等で「構成〜出品情報まで完了しました。マスタの構成・競合・価格・商品名案を確認し、必要なら修正してから出品作業へ進んでください。」と伝える。

#### 8.3.1 時間制限・続きから再開（実装方針）

- **背景**: GAS の実行時間制限（例: 30分プランでも確実に30分動くとは限らず、途中で終了することがある）に対応するため、統合実行は「メニュー（ステップ）ごとに区切り」「1回の実行で複数ステップを回し、時間が来たら続きをトリガーで再開」する形で実装する。
- **チャンク単位**: 統合前の Z. の各メニュー（1. セット構成 ～ 7. 商品名案・プルダウン）を**1チャンク**とする。実行順は ②→④→③→⑤→一括生成→同期→プルダウン（Z.1 → Z.2 → Z.4 → Z.3 → Z.5 → Z.6 → Z.7）。
- **状態保存**: 各ステップ完了ごとに「次に実行するステップ番号」とスプレッドシートIDを Script Property（`B_INTEGRATED_RUN_STATE`）に保存する。全7ステップ完了時に削除する。
- **時間チェック**: 各ステップ実行前に `ScriptApp.getScriptRunTime()` で経過時間を確認し、**25分を超えたら**そのステップには入らず、状態を保存して**約1分後に続きから実行する時間トリガー**を1本だけ設定し、いったん終了する。
- **続きから再開**  
  - **メニューから実行した場合**: 前回の状態が残っていれば「続きから再開しますか？」と確認。Yes で次ステップから、No で最初から、キャンセルで状態を消して終了。  
  - **トリガーから実行した場合**: 保存された「次ステップ」からそのまま実行。コンテナバインドのスクリプトでは `getActiveSpreadsheet()` で同じスプレッドシートが取得できる前提。  
- **急に終了した場合**: プロセスが強制終了しても、**最後に完了したステップの直後に状態が保存されている**ため、次回メニューまたはトリガーで「続きから」再開できる。途中のステップでエラーが出た場合も、そのステップ番号を保存してトリガー（または手動再実行）で同じステップからやり直す。
- **トリガー**: 続き用の時間トリガーは `runBIntegratedFromTrigger` を1本だけ登録。次回実行時に既存の続き用トリガーは削除してから実行する。

### 8.4 個別メニュー（既存を残す・連番を手順順に変更）

- ②・④・③・⑤・⑥ などは、従来どおり個別メニューから実行できるように残す。
- 連番は「手順の順」に合わせて変更する。実行順が ②→④→③→⑤→(確認)→⑥ なので、メニュー表示も ②→④→③→⑤→⑥ の順で並べ、必要に応じて「手順3」「手順4」のようにする。上から順に実行すると推奨手順になり、あとから④だけ・③だけをやり直すときは該当メニューを選べばよい。

### 8.5 人間の作業フロー（理解用）

※ステップ3と4のあいだは後に変わる可能性あり（出品情報の収集と修正確定の詳細が入る想定）。まずは荒く記載し、後でまとめ上げる。

| ステップ | 誰が何をするか | メニュー |
|----------|----------------|----------|
| 1 | 人間が AI情報取得data に入力し、ASIN貼り付けにASINを貼って ① Keepa取得 を実行する | ① Keepa取得（20/50/全件） |

### 8.6 まとめ（要件の要約）

- 統合メニューを1つ追加し、実行内容は「②→④→③→⑤→一括生成→同期→プルダウン」の順で固定。構成・価格のチェックは後回しとし、出品情報まで一気に実行したあと、最後に人間が構成・競合・価格・出品情報をまとめて確認する運用を実現する。
- 既存の個別メニューは残し、後から④だけ・③だけ・一括生成・同期・プルダウンなど切り分けて実行できるようにする。
- メニュー並び・表示番号を実行順に合わせ、作業者が手順を追いやすくする。
- 統合メニュー実行後は「構成・競合・価格・商品名案を確認し、必要なら修正してから出品作業へ進んでください」と分かる文言で案内する。

### 8.7 出品完了後の出品CK一括クリア自動化（実装要件）

一括出品（楽天CSV出力 → Yahoo!出品）の完了後に、**出品CK（レ点）をまとめてクリアする**処理まで自動化する。

**要件**

1. **新規関数の追加**
   - マスタの「レ点（出品CK）が付いた行」を対象に、それらの行の出品CK列を一括で FALSE に更新する関数を追加する。
   - 選択行は使わず、**レ点が付いている全行**を対象とする（`menuClearShippingCheckForSelection` は選択行前提のため、別関数とする）。
   - 関数名・配置は実装時に決定（例: `clearShippingCheckForCheckedRows` など、トリガーや一括出品から呼び出しやすい名前にする）。

2. **一括出品フローへの組み込み**
   - 「一括出品実行」のフルコース（楽天CSV出力 → Yahoo!出品）が**正常に完了したとき**に限り、上記関数を呼び出す。
   - 楽天またはYahoo!のいずれかでエラーになった場合は、出品CKクリアは実行しない（ユーザーが結果を確認してから手動で ⑥ 出品CKをクリア する想定）。
   - トリガー実行時（`runBatchExportFromTrigger`）でも、成功時は同様に出品CK一括クリアを実行する。スプレッドシートは `ssOverride`（openById で開いたオブジェクト）を渡してマスタを更新する。

3. **既存メニューとの関係**
   - 既存の「⑥ 出品CKをクリア（選択行）」は残す。選択した行だけクリアしたい場合に利用する。
   - 新規の一括クリアは「一括出品の成功時のみ自動で呼ぶ」形とし、単体メニューとして追加するかは任意（追加する場合は「出品CKを一括クリア（レ点行）」などとし、実行前に確認ダイアログを出す）。

4. **確認・安全**
   - 一括クリア実行前に、対象行数が一定数（例: 50行）を超える場合は確認メッセージを出すか、ログに件数を残すなど、誤操作時の追いやすさを考慮する。実装方針は実装時に決定する。

### 8.8 B. 統合実行のダイアログ廃止・B-② メニュー（実装済み）

**目的**: B. をメニューまたはトリガーで実行したときに、確認ダイアログで処理が止まらないようにする。あわせて送料・競合価格修正後に価格だけ再提案するメニューを追加する。

**メニュー名・配置**

- **B-①** … 「amazon競合価格のみKeepa修正を反映」。ASIN貼り付け（Keepa用）で直した競合価格・ASIN・URLをマスタに反映するのみ。価格の再提案は行わない。
- **B-②** … 「送料・競合価格修正後、価格を再設定（全モール）」。④楽天Yahoo!販売価格をAI提案 → ③Amazon販売価格をAI提案 の順で実行。入荷後や競合価格修正後に価格だけ再提案したいときに使用。配置は B. の直後、B-① の直後（B. → B-① → B-② → C. → D. → Z.）。

**B. 統合実行でダイアログに止まらないようにする**

1. **ステップ2（楽天Yahoo!リサーチ一括）**: 「続行しますか？」の確認ダイアログを廃止し、確認なしで実行する。実装済み。
2. **ステップ4（Amazon販売価格をAI提案）**: 「送料の確認」ダイアログ（サイズ＆自己発/FBA・梱包箱指定が未入力のときの確認）を廃止する。実装済み。想定物流費AI試算（ステップ2.5）実装後はサイズ・梱包は自動入力される想定。

これにより、B. 実行中にユーザー操作を待って進まなくなる事態を防ぐ。「続きから再開しますか？」はメニューから実行したときのみ表示し、Yes/No/Cancel のいずれかを選べば次に進む。
