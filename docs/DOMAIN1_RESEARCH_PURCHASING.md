## 3.5 対話でロックした判定（2026-08-14）

一気に全要件は書かない。確認が取れたものだけここへ積む。

**①の正（Q1-a）**: マニュアルの「仕入れ検討商品の市場調査」（最低条件 → 特定 → 深掘り → 粗利）。問屋開拓・Shopee／セラー発掘は対象外。**見積依頼は後続**（C／M3-2）。

**最低販売価格（Q2-a）**: 門は **税込2000円以上**（検索バーの1800〜2000は便宜）。食品は **1500円以上も多い** → いったん2000。必要なら1500へ下げることを検討（カテゴリ閾値と一緒に設計）。

**ランキング（Q3-a）**: 対象は **売れ筋順位の数字が 150000 以下（以内）**。**セットの中身単品だけ** 15万より悪くても深掘り可。  
食品は賞味期限の都合で **6万位以内、可能なら3万位以内** が実務上きつい。**カテゴリーごとに閾値を選べる**設計にする（食品／おかし／その他でプロファイル）。

旧 docs の「仕入れ検討は2500円」（RESEARCH_AND_ESTIMATE D3）は、領域1①については **2000円に上書き**（食品1500は未採用・検討メモ）。

**Amazon 本体（Q4-a）**: 基本は本体なし。**いま橙でも、直近6ヶ月ほぼ不在（または一瞬だけ橙）なら「いない」として通過**。自動化も同じ。

**出品可否・出品画面エラー（Q5-a）**: **第1版の門には入れない**。出品可否は後段で注記（Q9-a）。  
理由: マニュアルの「出品画面で5886等なら調査中止」は **新規カタログを作らない前提**。いまは新規カタログを量産できるため、その中止ルールを門にしない。

**カテゴリ閾値の器（Q6-a）**: **プロファイル表**（カテゴリごとに価格下限・順位の段階1・段階2）。未設定カテゴリは共通（2000円・15万）。食品の例: 段階1=6万、段階2=3万（賞味期限）。価格1500は検討枠のみ。

**冷凍・生・大型（Q7-b）**: 第1版の門で落とすのは **明らかに冷凍・生だけ**。大型は第1版では人または後段（「クイックショップ大」の数値化は後）。

**出品者1人／おまけ（Q8-c）**: 第1版は **落とさずフラグだけ**（1人／おまけ疑い）。理由: **新規カタログ出品で対応できる**ため、マニュアルの「調査除外」は門にしない。

**出品可否の後段（Q9-a）**: 調査は止めない。後段で「新規カタログが必要／既存に相乗り可／出品制限あり」を **注記するだけ**。見積候補からの除外もしない（第1版）。

**調査経路（Q10-a）**: 第1版で **3経路すべて**（リストKeepa → メーカーKeepa → Amazon検索の救い）。Amazon検索は **機械化できる範囲から**。

**入力（Q11-b）**: **卸リストが無くてもメーカー名だけで経路2＋3を回す**。リストがあるときは経路1も使う。特定問屋リストは必須ではない。

**粗利（Q12 修正）**: 第1版の **門では粗利を使わない**。粗利は **見積が取れたあと機械で見る。最終判断は人**。掛率推定だけで自動打ち切りはしない。

**成果物（Q13-b）**: **仕入検討品番リスト相当（1行1ASIN）** に加え、**メーカー単位サマリ**（通過SKU数、有名／マイナー目安）。見積依頼は含めない。

**経路3（Q14-a）**: Keepa メーカー検索に載らなかった ASIN を、**Amazon 検索API／スクレイプで足す**（一覧で価格・順位・本体が取れる範囲）。

**1行の単位（Q15-a＋補足）**: 第1版は **1 ASIN＝1行**。セットを中身JANに分解する開発は **難易度が高いため基本不要（メモのみ）**。門の「セット内訳は順位例外」は、分解できるときだけ。  
主対象は **同じ商品の複数セット数量で利益を確保する**リサーチ。異種組み合わせセットは **見積取得後の副産物**でよい。

**同じ商品の束ね（Q16-a）**: 第1版は **束ねない**（ASIN行の羅列＋メーカーサマリのみ）。紐付けは人または後段。安定したら束ねを検討する。

**書き先（Q17-b）**: **出品マスタとは別の専用シート**（調査スプシの複製または新規）。出品マスタへは書かない。

**メーカーサマリ（Q18-b）**: 第1版は **通過SKU数と本体在席率の数値のみ**。有名／マイナーラベルは初期不要。スクレイピングで確認できるようになったら検討する。

**専用シート（Q19-a）**: **調査スプシを複製**して自動化用にする（タブ構成踏襲。外注原本は触らない）。複製後の **調査データはテストに必要な最小だけ残し、あとは削除して軽くする**。

**重複（Q20-a）**: **ASIN で1行に潰す**。経路1／2／3で見つかった印を列に残す。

**候補行の必須項目（Q21-b）**: Q21案（メーカー、ASIN、JANあれば、商品名、税込価格、順位、本体いま／6ヶ月、冷凍生、出品者数、おまけ疑い、経路、取得日時、門の結果）に加え **画像URLは第1版から必須**。開発が重すぎる場合は後続。Keepa経由なら重くない想定。

**複製のタブ（Q22-a）**: 自動化用は **候補リスト＋メーカーサマリ＋カテゴリプロファイル＋実行ログ** を残す／新設。ガイド・報酬・問屋開拓・見積PV・過去の大量データは複製時に削る。

**門落ち行（Q23-a）**: **落ちた ASIN も残す**（門の結果＝落ち＋理由）。通過はフィルタで見る。

**Keepa 基盤（Q24-a 確定）**: **既存 GAS の Keepa 取得だけ流用**し、②のシート書き込みは触らない。書き先は①専用スプシ。経路3の Amazon 検索が GAS で厳しいと分かった時点で、**その部分だけ Python** に出す。

**実行単位（Q25-a）**: **メーカー名 1件**（経路2＋3。そのメーカーのリストJANがあれば経路1も）。

**Keepa と再開（Q26 訂正）**: **件数キャップは置かない**（1回の消費トークン未計測）。プランの **回復上限は 300 トークン**。残トークンを見て足りなければ待ちトリガーで再実行を繰り返してメーカー1件を終える。出品用②の 1ASIN=2トークン換算は経路2に流用しない。サブスク外課金はしない。

**起動（Q27-a）**: **専用スプシのメニューから人が押す**。出品の B統合には入れない。

**再実行（Q28-b）**: **追記**。ASIN 重複は1行に潰すので実質更新。データが増え過ぎたら、新しい行を残し重複を消す等で対策する。

**冷凍・生（Q29-a）**: Keepa／タイトルに冷凍・冷蔵・生鮮などが **明示されていれば落とす**。曖昧は落とさず **要確認**。

**おかしプロファイル仮置き（Q30-b）**: 価格下限 **1000円**、順位 **6万位**（食品に近い段階の仮。段階2は未設定）。食品は 2000円・15万／6万／3万。

**複製の作成（Q31-a）**: **人が原本を複製してデータを削ったあと**、スクリプト紐づけとスプシ ID を教える。GAS は空ファイルを勝手に作らない。

## 3.6 方針更新（2026-08-14・Keepa API合格後）

§3.5 の Q10 / Q14 / Q11 / Q25 を次で上書きする。門の閾値の**初期値**（Q2–Q8, Q29–Q30）は維持。ただし **プロファイル表で人が調整できる**（コード定数だけに固定しない）。

**最終形**: セラーリスト化 → … → メーカー洗い。

**データ置き場（2026-08-15 再ロック）**: Amazon リサーチの Keepa は競合情報と同じ。正は競合DB `Keepaフル`（90日。出品・貼付が再利用）。調査複製 `①候補` は門の作業面（転記・仕入検討品番リスト相当）。Catalog 生は `モールヒット` に入れない。メーカー第2語は `メーカーマスタ`。

**進め方**: 門の作業面（C1–C8）は済。**次は倉庫 W1–W3**（Keepaフルへ①書き）。セラー①–⑧は後。

**メーカー洗い**: 発見＝SP-API Catalog キーワード＋**タイトルにメーカー名を含む**（brandNames 単独は正にしない）。属性＝Keepa product API → **Keepaフル**。巨大メーカーはキーワードにカテゴリ／アイテムを足してよい。石原完走。五木は1語で試す（済）。

**第1版に載せない**: ペヤング型、公式サイト照合。発見の Keepa 切替は運用で精度問題が出てから。

**検収（門）**: 石原＋五木1語が①候補に残る。**済。** 倉庫（Keepaフル）は別検収（W1）。
