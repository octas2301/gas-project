# Gemini と OpenAI（ChatGPT）の役割分担（商品情報まわり）

**目的**: 「基本 Gemini・失敗時 ChatGPT」という運用イメージと**実装の正**を揃え、次 Agent・運用の判断を誤らないこと。

**正の実装**: `コード.js`（本ドキュメントは仕様レベルの要約。関数名は検索用に最小限のみ記載）。

---

## 1. 方針との対応（重要）

| 運用イメージ | 実装の正 |
|--------------|----------|
| 商品名・キーワードは Gemini 主 | **本線は OpenAI のみ**。Gemini 版の商品名案生成は**未配線**（関数は存在） |
| バリエーション単位は Gemini→補完 | **Gemini → OpenAI → 内容量フォールバック**（◎ASIN 経路も同様） |
| 内容量パース | **Gemini（商品名分解）中心**。ChatGPT への自動フォールバックは**ない** |

---

## 1.1 ASIN貼り付け（Keepa用）の ◎ と 1セットあたり内容量（同一 JAN ブロックのみ）

- **対象**は **その JAN に対応する 1 ブロック**内の **◎ 行の商品名**だけ（他 JAN の ◎ は見ない）。
- **複数 ◎ がある場合**は **すべての行を材料に総合判断**する（`pickPerSetContentFromCircleTitles_`）。  
  - 各行を `parseProductNameByGemini` で分解し、**同一行では g/kg/ml 等の質量・容量を袋数（〇包）より優先**して候補化。  
  - **ブロック全体**では **質量・容量候補 → その他 → 〇包**の順で最初の採用値を使う（先頭の ◎ だけで打ち切らない）。  
  - いずれも空のときは **◎ 商品名を結合した文字列**で従来どおり `getContentPerItemFromProductName` を 1 回。
- **旧挙動**（先にパース成功した 1 本だけで確定）に戻す: Script Property **`CIRCLE_COMBINED_PER_SET_CONTENT`** = `false`（未設定時は **`true`**＝総合判断）。
- ログ: `[◎ASINバリエーション][総合判断]`

## 2. OpenAI を使う処理（商品情報の本線）

- **キーワード案**（特徴・用途・楽天/Yahoo 補足KW）
- **商品名案**（Amazon / 楽天 / Yahoo、各モール別呼び出し）
- **バリエーション単位**の**補完**（Gemini で単位が取れないとき）

---

## 3. Gemini を使う処理（代表）

- **商品名の分解**・**1セットあたり内容量**の抽出（商品名文字列から）
- **バリエーション単位**の**第1候補**（◎商品名テキストにも適用）
- **CPO 価格提案**（プロンプトを Gemini に送信）
- **楽天セット別・モール横断セット数**など、セット数・画像・カテゴリ推測の各所（詳細はコード検索）
- **AI情報取得データ生成**（リスト）: 調査・Vision JSON 等。OpenAI Vision と**併用・マージ**する箇所あり

## 4. Z「11-③」と B 統合 Step7 の差（検証・障害切り分け）

| 項目 | 11-③（商品名案のみ・テスト用） | B 統合 Step7 |
|------|----------------------------------|--------------|
| 入口 | 一括関数でレ点親行を処理 | 状態保持・フェーズ分割・時間分割 |
| 商品名案（OpenAI）が全失敗の行 | **`runProductNameProposalsForRows`**: マスタに**商品名があれば**バリエーション書込まで**進む**（既定）。旧挙動に戻す場合は Script Property `PRODUCT_NAME_PROPOSALS_CONTINUE_VARIATION_ON_OPENAI_FAIL=false` | **バリエーションのみ実行され得る** |
| プルダウン再設定 | **しない**（仕様） | 完了時に**する** |

**ログの目安**: ◎・バリエーション経路は `[◎ASINバリエーション]`、`[バリエーション書込]`、`[Step7][variation]` 等で確認。OpenAI 失敗後にバリエーションだけ動いた場合は `[バリエーション書込] ... OpenAI商品名案失敗後のバリエーション継続 run` と `[商品名案] ... 完了（商品名案なし・バリエーションのみ）`。

## 5. OpenAI 429（`insufficient_quota` 等）時の影響

- **キーワード案・商品名案**は OpenAI 本線のため、429 では**書き込めない**ことがある。
- **`runProductNameProposalsForRows`（11-③・商品名案一括生成など）**: 既定では **429 でもマスタ商品名があればバリエーション（Gemini 中心・単位補完に OpenAI）を実行**する。キーワード案は失敗時スキップ。
- **B Step7** では **variation フェーズまで到達する**場合があり、**単位・内容量だけ更新**されることがある（商品名列が空でも）。

**切り分け**: OpenAI ダッシュボード・キーのアカウント・上限を確認したうえで、上表の「経路の差」を踏まえてログを読む。
