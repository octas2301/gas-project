# 商品名・説明・AI提案 要件定義書

商品名・説明・キャッチおよびAIおすすめ商品名の列方針・スコープ・開発残をまとめた要件定義。  
前提は [FLOW_AND_PRIORITY.md](FLOW_AND_PRIORITY.md) §4「既存マスタ連携による最小必須項目の対応」および本会話での合意事項。

---

## 1. 目的・スコープ

### 1.1 進め方

- **採用方針**: ③ベース＋④段階的（[FLOW_AND_PRIORITY.md](FLOW_AND_PRIORITY.md) および本会話で合意）。
- **Phase 1（今回スコープ）**
  - 商品名は**現行のまま**（共通1本）。説明・スペック・キャッチでAI・モール要素を補完する。
  - 既存の syncAiDataToMaster・COMPARE_ITEMS（コード.js）の流れを拡張する。既存列で賄える範囲で実施する。
- **Phase 2（必要に応じて）**
  - 検索KW収集・上位分析・モール別商品名を一部のみ導入する場合は、本ドキュメントの「開発残」を参照して検討する。

### 1.2 対象

- **モール**: Amazon・楽天・Yahoo! の3モール。
- **データの中心**: ▼商品マスタ(人間作業用)。出品時はマスタの確定列を参照する。
- **本要件の対象範囲**: **モールに登録する商品名・商品説明・キャッチなど**に限定する。**セット構成・価格決めの工程は対象外**（既に組み上がっているため）。評価・競合セット数・穴のセット数提案など、リサーチ・価格提案用の列は本要件の必須列に含めない。

## 2. タイトル構成要素とマスタ列の対応

「必要な項目のみ列として取り込む」方針に基づく対応。今回スコープで新規に列を追加する必要があるものはない（既存列で賄う）。

| 構成要素 | マスタでの対応 | 備考 |
|----------|----------------|------|
| ブランド | メーカー名（既存列）で対応 | 新規列不要 |
| 商品名 | 既存の「商品名」列 | 確定用。出品時参照 |
| 型番 | 既存の型番列 | 新規列不要 |
| カテゴリ | 既存の ★推奨楽天ジャンルID・★推奨YahooカテゴリID 等で対応 | 共通用カテゴリ列は任意（今回必須ではない） |
| サイズ | 商品名に含める運用。必要時は「商品本体サイズ」等の既存スペック列で補完 | 新規列は不要 |
| 特徴 | 現状なし | 必要に応じて「特徴キーワード」等を追加可能（今回必須ではない） |
| 用途 | 現状なし | 必要に応じて「用途キーワード」等を追加可能（今回必須ではない） |
| CTRコピー | 既存の COMPARE_ITEMS「CTRコピー」・▼マスタ(CTRコピー) | 新規列不要 |

- 特徴・用途は「必要なら後から追加」とする。今回必須ではない。

## 3. AIおすすめ商品名（参考用）

**マスタ列の追加方針**: マスタシートには既存データがあるため、**コードで列の自動作成・挿入は行わない**。**列の追加と項目名（ヘッダー）の設定は人間が行う**。コードは既存の列名を参照し、列が存在する場合のみ読み書きする（上書き・データ消失を防ぐため）。

### 3.1 仕様

- AIがモールごとに**おすすめ商品名を3案**生成し、**参考用**の列に格納する。
- 人間の工数は現行のまま。**確定は既存の「商品名」列**で行う。

### 3.2 列案

実装時にシート・列名を調整可能。マスタ専用の参考用列とする。

| 列名（案） | 内容 |
|------------|------|
| 商品名案(Amazon) | 3案を改行または区切りで格納 |
| 商品名案(楽天) | 同様 |
| 商品名案(Yahoo!) | 同様 |

### 3.3 入力

- 既存の商品名・型番・メーカー名・カテゴリ・スペックなど、マスタ既存項目のみをAIへの入力とする。
- モール別の文字数・ルールに合わせて生成する。

### 3.4 参照上の注意

- 既存の コード.js の **COMPARE_ITEMS には含めない**。COMPARE_ITEMS は AI情報取得data との比較・同期用のため。商品名案はマスタ専用の「参考用」列として扱う。
- **出品時の商品名参照**（本フェーズで実装済み）: マスタに「商品名amazon」「商品名楽天」「商品名Yahoo!」を追加済みとする。楽天CSV出力は「商品名楽天」（空欄時は「商品名amazon」）、Yahoo出品は「商品名Yahoo!」（空欄時は「商品名amazon」）、Amazon出品は「商品名amazon」を参照する。詳細は [TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md](TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md) を参照。

### 3.5 人間が追加する列の一覧（本要件の対象範囲）

本要件の対象範囲（商品名・説明など）で**人間が追加する列**は以下のとおり。コードは列を自動作成しない。

| 区分 | 列名（スプシヘッダー） | 内容 |
|------|------------------------|------|
| **追加済み（本フェーズ）** | 商品名amazon | 出品時参照。Amazon用・フォールバック元。 |
| **追加済み（本フェーズ）** | 商品名楽天 | 楽天CSV用。空欄時は商品名amazonを参照。 |
| **追加済み（本フェーズ）** | 商品名Yahoo! | Yahoo出品用。空欄時は商品名amazonを参照。 |
| **追加済み（本フェーズ）** | 商品名検索キーワードamazon | モール別検索KW。プルダウン対象。 |
| **追加済み（本フェーズ）** | 商品名検索キーワード楽天 | 同上。 |
| **追加済み（本フェーズ）** | 商品名検索キーワードYahoo! | 同上。 |
| **追加する** | 商品名案(Amazon) | AIおすすめ商品名 3案（参考用） |
| **追加する** | 商品名案(楽天) | 同上 |
| **追加する** | 商品名案(Yahoo!) | 同上 |
| 任意 | 特徴キーワード | 商品の特徴。AI生成・検索KWの入力に使う場合に追加 |
| 任意 | 用途キーワード | 想定用途。同上 |
| 任意 | 楽天 補足KW | 楽天向け補足キーワード。運用で必要になった場合に追加 |
| 任意 | Yahoo! 補足KW | Yahoo!向け補足キーワード。同上 |
| 任意 | 商品名案の理由 | 商品名案3案の戦略・ロジック説明を全モール分まとめて記載。列が存在する場合のみ書き込む。 |

### 3.6 モールごとの商品名戦略（実装方針）

商品名案生成時、AIには以下のモール別戦略をプロンプトで指定する。コードはこれに従いモールごとに3案を生成する。

#### 共通タイトル設計ルール

- **優先順位**: 1.ブランド 2.商品名 3.型番 4.カテゴリ 5.スペック(サイズ/容量) 6.機能・特徴 7.用途 8.購買KW(人気・おすすめ等)。重要情報は前半に配置。
- **ルール**: ①検索キーワードを優先 ②タイトル前半に重要情報 ③スペックを必ず含める ④同一ワードの過剰重複を避ける ⑤自然な日本語を維持。

#### Amazon

- **アルゴリズム特性**: 商品一致・検索一致・CTR/CVR重視。タイトル前半が特に重要。
- **購買コピー**: 入れないか最後に配置。
- **3案の役割**: 案1＝検索SEO最適型（ブランド+商品名+型番+カテゴリ+サイズ+機能）、案2＝機能強調型、案3＝用途強調型。

#### 楽天市場

- **アルゴリズム特性**: 検索キーワード一致・商品名内KW・CTR重視。**検索ワードをブランドより前に**配置する。
- **購買KW**: 人気・おすすめ・ランキング・送料無料等がCTR向上に有効。
- **3案の役割**: 案1＝検索KW最大型、案2＝機能訴求型、案3＝購買誘導型（人気・おすすめ等を含む）。

#### Yahoo!ショッピング

- **アルゴリズム特性**: 情報量・キーワード一致・属性重視。スペックの明確さが重要。購買コピーは楽天ほど不要。
- **3案の役割**: 案1＝スペック重視型、案2＝検索KW重視型、案3＝情報量最大型。

### 3.7 キーワード案（特徴・用途・補足KW）の5案生成

- 商品名の構造に入れる**特徴キーワード・用途キーワード・楽天 補足KW・Yahoo! 補足KW**について、AIがそれぞれ**5案**を改行区切りで提案し、該当列に書き込む（列が存在する場合のみ）。実行順は「キーワード案の書き込み → 商品名案の生成」とし、キーワード案を商品名案の入力に含める。

## 4. 楽天・Yahoo! 独自の必要ワード

### 4.1 今回の扱い

- 既存の列で対応する。新規に「楽天独自必須KW」「Yahoo!独自必須KW」のような列は**今回スコープでは追加しない**。

### 4.2 既存での対応

| モール | 既存列（COMPARE_ITEMS に含まれる） |
|--------|-----------------------------------|
| 楽天 | 楽天Slug(30字)、楽天キャッチ(60-80字) |
| Yahoo! | Yahooキャッチ(20-30字) |

### 4.3 将来

- 運用で必要になった場合、「楽天 補足KW」「Yahoo! 補足KW」等の列を必要に応じて追加可能とする。

## 5. 開発残（検索順位・上位分析）

以下は今回スコープ外とし、要件定義上は**開発残**として記載する。別途検討する。

### 5.1 検索順位の取得

- キーワード検索順位の取得（Google Custom Search API / 各モール商品検索APIの返却順 / SERPs API 等）は**今回スコープ外**とする。
- 実装する場合は、効果・工数を踏まえて優先度を判断する。

### 5.2 上位商品分析

- 各モールの検索上位10〜20件のタイトルから**共通語・差別化語・ノイズ**を抽出する処理は**開発残**とする。
- その結果をマスタに残す方針（パターンB）も**開発残**とする。将来実装する場合は、列として「上位分析:共通語／差別化語／ノイズ」をモール別に持つ、または「上位分析メモ」1列で対応する。
- 優先度は今後の効果・工数を踏まえて判断する。

## 6. 商品名作業エリア・プルダウン・モール別商品名（本フェーズ実装済み）

以下は [TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md](TITLE_WORKAREA_DROPDOWN_AND_MALL_NAMES_REQUIREMENTS.md) にまとめた仮要件定義に基づき実装済み。

- **プルダウン**: マスタの対象列（メインKW(3つ)、商品名検索キーワードamazon/楽天/Yahoo!、CTRコピー、特徴キーワード、用途キーワード、楽天 補足KW、Yahoo! 補足KW）のセル値を改行で分割し、GASでデータ入力規則を設定。**親SKU行**のセルに適用。CTRコピーは `[char_8]` 等のプレフィックスを除去し、文字数順に並べる。リスト外入力は許可し警告のみ。メニュー「キーワードプルダウンを再設定（選択行の親行）」で再設定可能。
- **モール別商品名**: 楽天CSVは「商品名楽天」（空欄時は「商品名amazon」）、Yahoo出品は「商品名Yahoo!」（空欄時は「商品名amazon」）を参照。Amazon出品は「商品名amazon」を参照。
