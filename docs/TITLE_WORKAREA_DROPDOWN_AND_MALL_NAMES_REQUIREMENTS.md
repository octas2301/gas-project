# 商品名作業エリア・プルダウン・モール別商品名 要件定義（本フェーズ・仮）

本フェーズで実装する内容をまとめた仮の要件定義。実装完了後に問題なければ、既存の要件定義書（AI_LISTING_AND_TITLE_REQUIREMENTS.md 等）へ反映する。

## 修正内容のまとめ（実装反映済み）

- **プルダウン対象行**: レ点をしている行の**親SKU行**のセルにプルダウンを設定する。子SKU行の同じ行ではなく、親行のセルで選択し、子行は親の値を継承する。
- **CTRコピー（[CTR,CVRを上げるコピー]）**: 選択肢の値から `[char_8]` / `[char_10]` 等のプレフィックスを**除く**。候補は**プレフィックス除去後の文字数順**に並べる（8→10→15→20文字の順）。
- **商品名**: 既存の「商品名」列は廃止済み。空欄時のフォールバックは**商品名amazon**のみ。楽天CSVは商品名楽天（空欄時は商品名amazon）、Yahooは商品名Yahoo!（空欄時は商品名amazon）を参照。
- **マスタ列と作業エリア列の紐付け**: プルダウンの**候補**は▼マスタ(〇〇)（AIが持ってきた複数案）、**設定先**は作業エリア列（人間が選んだ1つを入れるセル）。`TITLE_DROPDOWN_PAIRS` で論理項目ごとに候補元・設定先を定義。下流（商品名案生成など）では「選んだ値」を使うため**作業エリア列を優先**して参照する。
- **Yahoo!出品の親行（同一親SKUが複数ブロックあるとき）**: 本線の下に下書き用の親行だけを置くと、旧実装は**走査で最後に通った親行**を `_createSingleProduct` のマージ元にしていた。2026-05 より **出品CKが付いた親行のうちシート上で最下段に近い行**を優先し、**レ点付き親が1行もないときだけ**従来どおり「最後に見た親行」へフォールバックする（`Yahoo.js` `YahooDataBuilder._groupMasterData`）。子行の出品対象は従来どおり**子の出品CKのみ**。詳細は §「Yahoo!出品: 親行データの選定（2026-05）」。
- **Yahoo! `path`（API送信時）**: マスタの **`(Yahooカテゴリ名)`** はプルダウンで「**＞**」区切りの可読表記のまま運用し、**マッピングの `path` が当該列を参照している場合**、editItem 送信直前に **全角＞・半角`>` を半角`:` に置換**し、**コロン前後の空白を除去**する（`normalizeYahooItemPathForApi_`）。初めから `食品:あられ、ひなあられ` のように **`:` 区切りで手入力したセル**も同じ処理で正規化される。**スプレッドシート上のセル値は書き換えない**。詳細は §「Yahoo! editItem path の正規化（2026-05）」。

### 実行するメニューと手順（AI情報取得〜プルダウン）

1. **AI情報取得data シート**で「**2. 全データ一括生成**」（`generateListingDataComparison`）を実行し、各行の [Gemini]・[GPT]・[正解] を生成する。
2. **「3. マスタへ同期**」（`syncAiDataToMaster`）を実行する。  
   - ▼マスタ(〇〇) に Gemini と GPT の案を改行でマージして書き、**作業エリア列には Gemini 案**を書き込む（初期表示をGeminiに統一）。  
   - **商品説明**はプルダウンにせず「商品説明文AIから取得」へ**値コピーのみ**（Gemini案）行う。
3. **▼商品マスタ(人間作業用)** で、プルダウンを付けたい**親行を含む行範囲**を選択し、**「キーワードプルダウンを再設定（選択行の親行）」**（`menuSetTitleDropdownForParentRows`）を実行する。

   - 箇条書き1～5 も同様に **Gemini 案を表示**で統一し、一通り Gemini 案で確認できる。

## AI→マスタ同期（`syncAiDataToMaster`）の突合に「商品名ベース」を追加した件（2026-05）

### 経緯

- **商品名列廃止**に合わせ、同期時にマスタ側で参照する名前列は **`商品名` が無いとき `商品名amazon`** とした（上表「商品名列廃止に伴うフォールバック」）。
- 一方、運用・シート構成によっては、親行で **JAN・ASIN が未入力**のまま、人間が一覧で追いやすい表示名を **`商品名ベース`** に載せているブックがある。
- **Z→1（B Step1）** 等で、AI情報取得data の **商品名（例: D列）** をマスタの作業用列へコピーするフローでは、AI側の比較・同期のキーは従来どおり **AI情報取得data の「商品名」** で `aiMapByName` を構築している。このときマスタ側で **`商品名`／`商品名amazon` が空**で、**`商品名ベース` にのみ** Z→1 で揃えた名前がある行では、従来の同期は **ASIN・JAN・（商品名 or 商品名amazon）のいずれでもヒットせず**、▼マスタ(〇〇) 列・作業エリア列への反映がスキップされていた。

### 判断

1. **突合キーを追加する**: マスタに **`商品名ベース`** 列が存在する場合、**ASIN → JAN →（商品名 or 商品名amazon）に続けて `商品名ベース`** でも AI 行を解決する。名前系のうち後ろ2段は、いずれも **`aiMapByName`（AI情報取得data の「商品名」列を正規化したキー）** と同じマップで照合する。これにより、「マスタの表示名＝ベース、AIのキー＝商品名」が同一文字列で揃っている限り、JAN/ASIN が空でも同期できる。
2. **後方互換**: **`商品名ベース` 列が無い**ブックでは、従来どおり **ASIN / JAN /（商品名 or 商品名amazon）** のみで突合する（`masterNameBaseIdx` が未定義のためフォールバック行に入らない）。
3. **子SKU行**: 従来どおり **同期対象外**（`子SKU` が非空の行はスキップ）。
4. **リスク**: 別SKUで **`商品名ベース` の文字列が偶然一致**すると、意図しない行に AI 結果が流れる可能性がある。運用上は **JAN/ASIN を埋める**、またはベース名の **ユニーク性**を意識することが望ましい。重複が疑われる場合はログやスプシ上で突合結果を確認する。

## 1. 目的・スコープ

1. **キーワード等のプルダウン化**  
   商品名作業エリアで、マスタの「改行区切り複数案」を**セル内改行で分割し、GASでデータ入力規則を設定する方式**でプルダウンにする。新規列・新規行・プルダウン用データ範囲は増やさない。
2. **モール別商品名・商品名検索キーワード列の参照**  
   マスタに「商品名amazon」「商品名楽天」「商品名Yahoo!」および「商品名検索キーワードamazon」「商品名検索キーワード楽天」「商品名検索キーワードYahoo!」を追加済みとする。楽天CSV出力・Yahoo出品で対応するモール列を参照する。**空欄時は「商品名amazon」をフォールバック**とする（「商品名」列は廃止済みとする）。

## 2. プルダウン仕様（GASでセル内改行→リスト）

### 2.1 対象項目

次のマスタ列について、**該当セル**に「改行区切りで複数案」が入っている場合、**その行の同じセル**にプルダウンを設定する（リスト元＝そのセルの値の改行分割。設定先＝同じセル）。

| 対象（マスタ列名） | 備考 |
|--------------------|------|
| メインKW(3つ) | 複数案を改行区切りで格納。 |
| 商品名検索キーワードamazon | モール別。 |
| 商品名検索キーワード楽天 | 同上。 |
| 商品名検索キーワードYahoo! | 同上。 |
| CTRコピー（[CTR,CVRを上げるコピー]） | マスタのセルが `[char_8] 〇〇` 等形式の場合、プルダウン候補は**プレフィックス（[char_8] 等）を除いた文言のみ**とする。候補は**プレフィックス除去後の文字数順**に並べる（8→10→15→20文字の順）。 |
| 特徴キーワード | 5案を改行区切りで格納。 |
| 用途キーワード | 同上。 |
| 楽天 補足KW | 同上。 |
| Yahoo! 補足KW | 同上。 |

### 2.2 実装方式

- **リスト元**: 新規列・新規行は作らない。対象セルの `getDisplayValue()` を改行で分割した配列を候補とする。
- **設定先**: 同じセルにデータ入力規則を設定する。
- **リスト外入力**: `setAllowInvalid(true)` でリスト外も許可し、警告表示のみ（入力を拒否しない）。
- **CTRコピー**: 各行から先頭の `[char_N]` パターンを除去した文字列を候補とし、除去後の文字数でソート（8→10→15→20の順）してから `requireValueInList` に渡す。

### 2.3 適用対象行・トリガー

- **対象**: **親SKU行**のセルにプルダウンを設定する。レ点を付けた子SKU行がある場合、その**親SKU行**を対象とする。子SKU行の同じ行ではなく、親行のセルで選択し、子行は親の値を継承する想定。
- **更新タイミング**: メニュー「キーワードプルダウンを再設定（選択行の親行）」で、選択範囲に含まれる親行について、上記対象列のセルにデータ入力規則を再設定する。

## 4. 受け入れ条件

1. **プルダウン**: 指定マスタ列について、選択した親行の該当セルに、セル内改行を分割したプルダウンが設定されている。CTRコピーは [char_N] 除去・文字数順。リスト外入力は許可し警告のみ。
2. **モール別商品名**: 楽天CSVは商品名楽天（空欄時は商品名amazon）、Yahooは商品名Yahoo!（空欄時は商品名amazon）を参照している。
3. 既存の「商品名」列は参照しない（廃止済み）。フォールバックは商品名amazon のみ。

## 5. Yahoo!出品: 親行データの選定（2026-05）

### 経緯

- 同一「親SKU」で、上段に**出品CK付きの本線親行**・下段に**レ点なしの下書き親行**（旧データや控え）を置いていたケースがあった。
- 旧ロジック（`YahooDataBuilder._groupMasterData`）は、同一 `親SKU` の親行が現れるたびに `groups[pSku].parent` を**常に上書き**していた。そのため **下書き親行が後から走査されると、子の出品CKに関係なく**キャッチ・YahooカテゴリID・パス・ブランド等の親由来フィールドが下書き側のセル値（例: `1.14755` 形式、複数行キャッチ）でマージされ、Yahoo! API のバリデーションエラー（400）や意図しない出品内容になることがあった。
- ユーザー想定は「レ点で対象を制御している」ことに沿い、**親マージ元も出品CK付き親行に紐づける**のが妥当と判断した。

### 仕様（実装済み）

| 項目 | 内容 |
|------|------|
| 子行の出品対象 | **変更なし**。`出品CK` が真の子行のみ `children` / `siblings` に含め、API送信対象とする。 |
| 親行のマージ元（`group.parent`） | 同一 `親SKU` について、親行（子SKU空欄）が複数あるとき、**出品CKが真の親行のうちシート上で最後に現れた行**を `parent` とする（＝一般的に本線に近い「下のほうのレ点付き親」が採用される配置を想定）。 |
| フォールバック | **出品CKが真の親行が1行もない**場合のみ、従来どおり **走査で最後に見た親行**（レ点不問）を `parent` にする。親にレ点を付けず子だけレ点、という運用を壊さないため。 |
| チェック判定 | `yahooMasterCheckboxIsTrue_` で、楽天 `generateRakutenCSV` と同様 **`true` および文字列 `'TRUE'`** を真とする（子・親とも）。 |

### 影響範囲

- 変更は **Yahoo.js のみ**（`runYahooExport` および同じ `buildProductData()` を呼ぶデバッグ関数は同一ルール）。
- 楽天CSV・一括出品オーケストレーション・R-Cabinet・`コード.js` のグルーピングとは**独立**。

### 運用上の注意

- 同一 `親SKU` で**複数の出品CK付き親行**を意図的に並べると、**最後のレ点付き親**がマージ元になる。
- 画像ゲート（`validateCheckedRowsHaveRakutenMainImage1_`）は親メイン画像のフォールバックに**別ルール**（親行走査）があるため、本変更だけでは「下書き親の画像」問題は解消しない場合がある。

## 6. Yahoo! editItem `path` の正規化（2026-05）

### 経緯

- Yahoo!ストアのサイト内パス（editItem の **`path`**）は、API 上**半角コロン `:` 区切り**の階層文字列として渡す必要がある一方、マスタの **`(Yahooカテゴリ名)`** ではプルダウン候補が **可読性のため「＞」区切り**（例: `ソフトドリンク、嗜好飲料 ＞ コーヒー ＞ デカフェ、カフェインレス`）になりやすい。
- そのまま送信すると形式不整合やバリデーションエリスの原因になるため、**完全なカテゴリ自動化は見送り**、**人間がプルダウンで選択した値を送信直前にだけ API 向けに正規化**する方針とした。

### 仕様（実装済み）

| 項目 | 内容 |
|------|------|
| 対象 | マッピングシートで **`path`** に紐づくマスタ列から解決される文字列（運用では **`(Yahooカテゴリ名)`** を参照）。 |
| 変換 | **全角 `＞`** および **半角 `>`** を **半角 `:`** に置換。続けて **`\s*:\s*`** を **`:`** に置き換え、**コロン前後の余分な空白を除去**する。 |
| 既存の `:` 表記 | 例: `食品:あられ、ひなあられ` のように**最初から `:` 区切り**の手入力・選択値も同処理で整形され、空白のみ除去される。 |
| マスタ | **セルの表示値は書き換えない**（可読な `＞` 表記を維持可能）。 |

### 判断

- `product_category`（数値ID）とは独立。**path の区切り文字整合**に限定した変更小さで運用負荷を下げる。
- API の**階層ごとの文字数上限**（例: `it-01002`）は、正規化だけでは解消しないため、必要に応じて人手での文言短縮は従来どおり。

### 関連コード

- `Yahoo.js`: `normalizeYahooItemPathForApi_`、`YahooApiClient._getValue`（`path` のみ正規化）、`_getMappingValueRaw`
